## 三个「差点误判」的教训

1. **BSD grep 的 `\|` 又踩一次**（这是第六、七次了）。
   我用 `grep -n "清掉最后一项\|老报表无 params\|先 grep 源码" MEMORY.md` 复核，
   **返回空** → 我据此判断「改动已生效」。其实 BSD grep 在 BRE 下把 `\|` 当字面量，
   三个词一个都没匹配。**判据：grep 说「没有」时先怀疑 grep。** 代码/文本搜索一律用
   Grep 工具或 `grep -E`。
2. **Edit 报成功 ≠ 文件真的改了**。同一批里有两个 Edit 返回 success，
   但事后逐字节核对发现**旧串还在文件里**（`清掉最后一项…`、`老报表无 params…`）。
   教训叠加了上面那条，导致连续两次误判。
   → **改完一批 Edit 要用「应有 / 应删」子串断言复核最终内容**，别信 success 消息。
   最后 `MEMORY.md` 改成**整文件 Write**，再用脚本逐条断言（应有 5 条 / 应删 4 条）
   并核对字节数（12199 < 12288）。
3. **⚠️ 把「沙箱 broker 拒绝」误判成「这个测试套件就是很慢」**。
   全量 vitest 跑了 **38 分钟无输出**，我先归因成「约 1900 用例 + happy-dom 慢」，
   还写进了日志。换成引擎配置又跑了 **30 分钟**，结束时是
   **64 个文件全部 `CODEBUDDY_BROKER_DENY` / `Sensitive content approval timed out`**
   —— 每个文件在等 broker 审批超时，**根本没跑测试**。
   挂上 `NODE_OPTIONS="--require scripts/vite-safe-delete-bypass.cjs --require
   scripts/broker-mkdir-throttle.cjs"` 之后：引擎 **4.15 秒 / 779 用例**，
   全量 **13.8 秒 / 1068 用例**。
   **判据：vite 工具链（vite / vitest / vue-tsc / tsc -p）在沙箱里一律要挂 preload；
   几分钟没输出先怀疑 preload，别怀疑套件慢。** 这条 `sandbox-broker-workarounds`
   里本来就有（trigger 就写着 `CODEBUDDY_BROKER_DENY`），**该先读技能再动手**。
   顺带：`vitest run <路径过滤>` 带位置参数也会被拒，要收窄范围用 `-c 配置文件`。

# 2026-09-22（下午）· 补设计器面板：条码 + 图表

上一段收口了 B2 的**引擎**能力，但设计器里**只有「图片」段** —— 条码和图表都只能手改 JSON，
等于「能力做出来了、UI 上摸不到」。本轮把这两段面板补上（用户选定）。

## 做了什么

### 1. 引擎层的设计期判据（`openprint/src/report/grid-report.ts`）

加了一批**纯函数**，只吃声明不吃数据，供面板在**发出请求之前**就提示：

- `BARCODE_SYMBOLOGIES` / `BARCODE_MAX_BYTES`（`{qr:213, code128:48}`）/ `normaliseSymbology`
  / `isGs1Relevant` / `utf8ByteLength` / `isValueBarcode` / `barcodeProblem`
- `CHART_KINDS` / `chartProblem`

三条刻意的设计：
- **`barcodeProblem` 不收 `payload` 参数**：内容就是声明里的 `value`，让调用方另传一份迟早会传岔。
- **`from: 'value'` 直接返回 `null`**：内容运行期才从数据里来，设计期无从判断，硬报就是假红。
- **只提示不拦**：服务端失败粒度是**一格**（`[条码: 原因]` + 告警），设计器拦成「整表不让存」
  比服务端更严 = 擅自加规则。
- `utf8ByteLength` 要**认代理对**：`'𝒜'.length === 2` 但 UTF-8 是 4 字节，直接 `s.length` 会算少。

### 2. `GridReportModal.tsx` 的 `CellModelEditor` 加两段

照「图片」段的写法。另有**优先级提示**（同时设了 ≥2 种图形时说明只有第一个会出）。
`gs1` 只对 Code128 显示，且切回二维码时**把已有 `gs1` 摘掉**（否则静默留在模板里，设了没反应）。

### 3. 用例 35 条 + 反证 10 条

- `grid-report-cell-barcode.spec.tsx`（18）/ `grid-report-cell-chart.spec.tsx`（17）。
  断言一律看 `onChange` 收到的 **model**，不断言「没报错」。
- `scripts/fault-inject-ui-panel.py`：**10 条注入全部让用例变红**，还原后复验全绿。

## 本轮两个新教训

1. **⚠️ 同一个文件的两个 `Edit` 放在同一条消息里会互相覆盖（静默）。**
   我给 `GridReportModal.tsx` 并行发了两个 Edit，两个都回 success，
   但事后核对发现**第一个没落地**（`const ch = m?.chart` 那行还是原样）。
   两个 Edit 各自「读文件 → 改 → 写回」，并发时后写的把先写的覆盖掉。
   → **同一文件一次只发一个 Edit，改完立刻 Read 复核**。
   （这是本项目第二次栽在「Edit 报成功 ≠ 文件真改了」，上一次是 `MEMORY.md`。）

2. **`ts-check.sh` 过了 ≠ 类型没问题 —— 它是 `--noResolve`，看不见跨文件类型错。**
   本次 `ts-check.sh` 报「无类型错误」，而 `tsc -p designer-react/tsconfig.json` 在
   **同一个 spec 文件**里抓出 **2 处真错**：
   - `symbology: 'code39'` 不满足 `BarcodeSymbology`（故意塞契约外的值，要显式 cast）；
   - `{ from: 'value', symbology: 'code128' }` 缺必填 `value`（`value: string` 是必填，
     `from: 'value'` 时它被忽略，所以填 `''`）。
   → **两个门禁都要跑**：`ts-check.sh`（快、带 `--noUnusedLocals` 抓没用的 import）
   + `tsc -p`（真解析、抓跨文件）。只跑前者就宣称「类型干净」是过度自信。
   顺带：`ts-check.sh` **真的会抓没用的 import** —— 本次它先报出
   `CHART_KINDS` / `CellChart` 两个 import 没用（因为我把下拉项硬编码了，
   没用 `CHART_KINDS.map`），改成从常量生成后才消掉。修法是**用上它**（单一事实源），
   不是把 import 删掉。
