## `=` 方言：真实存盘报表逐格往返（67f0a8d）

之前所有方言用例都是合成的（`{value:null, model:{ds,field}}` 这种），
盖不住真实模板的形状。所以直接读
`print-server/reports/sales-by-region.json`，`templateToGrid` 后逐格
`formatCellText` → `parseCellText` 往回认，断言：

- 绑定格必须以 `=` 开头、不含 `{{`
- 解析回来的 `ds/field/agg/value_expr` 与原 model 一致
- 真实模板里特有的「带 model 但没 field 也没 value_expr」的纯占位格
  （如「城市小计」）要走字面量分支

末尾 `expect(bound).toBeGreaterThan(3)` 是**防空转**：样本里必须真有绑定格，
否则整段循环一次都不进、测试照样绿。

探针：把 `formatCellText` 的 value_expr 分支改回 `{{...}}`，这个用例立刻红。
103 通过（原 102 + 这一条）。

## 语言包：一个「界面好好的、一改格子就静默失败」的真 bug（fccf009）

切到 formula-free Univer 时把 `LocaleType` / `mergeLocales` /
`UniverPresetSheetsCoreZhCN` 一起删了 —— 当时界面照画、控制台没红字，
以为那是 preset 才需要的死代码。

不是。用 `window.__univer` 调 `setValue` 才发现：

```
Error: [LocaleService]: Locale not initialized
    at SheetPermissionCheckController._getPermissionCheck
    at CommandService.syncExecuteCommand
    at FRange.setValue
```

权限检查挂在**每一条**命令上，所以任何改格子的操作都会炸。
按插件逐个带 zh-CN（design/ui/docs-ui/sheets/sheets-ui）+ `mergeLocales` 修掉。

**教训：删 import 时别以「界面没变化」为准。** 死代码和「只在某条路径上才
需要」的代码长得一模一样，必须找到那条路径实际跑一遍。

## 画布键入那条路这次真验到了

之前 CDP 多字符文本输入的 harness 坏了，只能验右侧面板。这次加了 dev-only
的 `window.__univer` 钩子，直接喂 sheets-ui 编辑器会产出的那个形状：

```js
sheet.getRange(0,0,1,1).setValue({ f: '=ds1.city', v: null })
```

→ `getCellData()` = `{ t: 4, v: '=ds1.city' }`，`getValue()` = `=ds1.city`

mutation 拦截器把 `{f, v:null}` 就地改成 `{v, f:null, t:4}`，`=` 原文保住了。
再点回该格，右栏：格内容 `=ds1.city`、数据集 `ds1` ——
`SheetValueChanged → setGrid → parseCellText` 整条也通了。0 报错。

**`window.__univer` 是 dev-only 的调试钩子**，HMR 不会让 effect 重跑，
改完必须整页 reload 才生效。

## 前端定义→保存→重开→执行：闭环验完

用真实 `demo.db / orders` 在设计器自由模板里定义了一张两列表（A1 = `=ds1.order_no` 纵向扩展 / B1 = `=ds1.amount` 不扩展），存为 `print-server/reports/orders-free-e2e.json`，刷新页面，从「打开已保存的报表」里重开，再点执行 —— 三行真实数据渲染到预览 Univer：

```
SO20260910001 | 1250.50
SO20260910002 | 88
SO20260910003 | 640.25
```

逐段验证：
* **定义**：A1/B1 的 Univer `cellData` 在右侧面板填完值后是
  `{ t: 4, v: '=ds1.order_no', s: 'tpl-r-field' }` / `{ t: 4, v: '=ds1.amount', s: 'tpl-n-field' }`。
  `s` 是语义样式（r = 纵向扩展、n = 不扩展），来自 `formatCellText` → 模板格→Univer 双向桥。
* **保存**：文件里 `template.sheets[0].rows[0].cells[0].model = { ds:'ds1', field:'order_no', expand_type:'r' }`，
  序列化用的是 `=` 方言（不是 `{{}}`）—— 和之前那批单测里的「真实存盘报表往返」对得上。
* **重开**：dropdown 列出「订单明细（1 个数据源）」，选中后 A1/B1 的 `cellData` 与保存前**逐字节一致**。
* **执行**：`POST /api/reports/orders-free-e2e/run` → 3 行，`dump` 显示
  `B1 <- A1:0,B1:0` / `A1:1,B1:0` / `A1:2,B1:0`，行父链自动推断正确（B1 没显式设 row_parent）。
  `runReport` 的实现是先 `GET /api/reports/:id` 再 `POST /run`，**从磁盘读** —— 不是用内存里的 def，
  所以「重开后执行」和「直接 curl 执行」拿到的是同一条数据，证明存盘是真的源。

截图：`.workbuddy-ai/screenshots/orders-free-e2e.png`。

### 设计器里几件不该再踩的事

* **画布键入 vs 面板键入**：CDP 多字符文本输入 harness 是坏的（之前已记），所以「在 A1 里手输
  `=ds1.order_no`」这条路验不到。改走右侧面板 `data-testid="free-cell-text"` + `fill` 是稳的：
  React 受控输入，`fill` 改 value → 触发 onChange → `setGridCell` → `applyGrid`。
* **`applyGrid` 是把整张 Univer 拆了重建**（`canvasKey++` 触发 effect dispose + 重 init）。
  所以面板写入后**立刻读** `getRawValue()` 会拿到旧实例的 null —— 要等重建完。
  重建也会把选区重置回 A1，所以「先 activate B1 再填」这种序列里面板填完后选区可能跑回 A1。
  改用 `free-sel-row` / `free-sel-col` 两个 InputNumber 选格子更可靠（测试态友好）。
* **antd 6 Select** 的 `option` 元素不在原 DOM 里（rendered to portal）；要看选项得
  `click [data-testid=...]` 开下拉，再用 `document.querySelectorAll('.ant-select-item-option')`。
* **`fill` 设 input value 之后必须等 React render 完**再读，否则读到的还是上一次的；
  `applyGrid` 也是异步（要等 `useEffect`），所以填完 → 立刻读 model 会误判为「没写进去」。
