## 「Excel 作设计器」换成 Univer：三层拆解（设计讨论结论）

用户问 NopReport 那套「Excel 当设计器」的思路能不能换成 Univer。结论：**行，我们已经换了**，
但要拆成三层看，不是一回事：

| 层 | NopReport / Excel | 我们 / Univer | 状态 |
| -- | ----------------- | ------------- | ---- |
| 1 表达式载体 | Excel 格内文本 | Univer 格内文本 `=ds1.city` | ✅ 照搬 |
| 2 扩展元数据 | Excel 批注（hover 才见） | 右栏属性面板（React state） | ⚠️ 换载体 |
| 3 持久化形态 | **.xlsx 文件即 DSL** | ReportDef JSON | ❌ 断 |

第 3 层才是「Excel 作设计器」的真正含义，也是唯一换不掉的地方。
`designer-react` 装的是 Univer 0.25.1，**没有 `sheets-io`**（xlsx 导入导出包），
所以前端 .xlsx 进不来也出不去；出 xlsx 是 Rust 侧 `report/xlsx.rs` 另写的。
`sheets-note` / `sheets-note-ui` / `preset-sheets-note` 在 node_modules 里（批注等价物），但没启用。

**文章自己承认这是复用决策，不是优越性**：「因为 Nop 平台本身就要解析和生成 Excel
用于模型驱动的代码生成，所以只要增加少量扩展注解，就可以把 Excel 变成报表设计器。」
我们没有现成的 Excel 解析/生成，照抄第 3 层反而是负担。

### 一个更干净的做法（待定，没动手）

NopReport 自己也嫌批注看不见，才加了 `*=^` / `*=>` 前缀把扩展方向**塞进格文本**。
我们的 `=` 方言现在只表达「绑什么」（`=ds1.city` / `=D3[B3:+0].sum()`），
方向还在 `model.expand_type` 里，跟格文本分离。
如果把方向也塞进文本（`=^ds1.city` 纵向 / `=>ds1.city` 横向），格文本就**自描述**了 ——
那样即使没有批注、没有 xlsx 导入，格文本本身就是完整定义，
「元数据跟着文件走」的问题顺带解决。改动只在 `BIND_RE` / `parseCellText` / `formatCellText`。

代价：失去「拿客户现成 Excel 模板直接导入」的能力。值不值取决于用户手上有没有存量 Excel 模板。

## 查「真差距能不能实现」→ 挖出一个更严重的静默丢数据 bug（已修）

本来是去评估那两个真差距，结果在验「嵌套数组能不能展开」时撞见一个**更要命**的问题。

### 引擎其实只支持「一个 sheet 一个数据集」

`engine.rs` 里**从不读 `model.ds`**——全文件搜不到 `.ds` / `datasets`。
数据集由 `mod.rs:227 pick_dataset()` 挑：扫全 sheet，取**第一个**遇到 `m.ds` 的数据集，
整个 sheet 共用它。所以「多源」目前是假的：

实测 A1 绑 `ds1.city`、B1 绑 `ds2.name`（两个字段都合法）→ B1 出**空**，且**无告警**。
这正是引擎 warnings 机制专门要抓的「静默产出错误数据」，但它没抓到。

### 顺手挖出的 bug：堆叠主从把父格那一行吃掉了

`engine.rs:1181 place()` 原来把子格从**父格自己那一行**开始排：

```rust
let used = self.layout_group(&children, offset).max(1);  // 子格起点 = 父格起点
self.insts[idx].row_span = used;                          // 父格自己那行没算进去
```

父格锚在「第一组子格」那一行上是**有意为之**（`华东 | 37,900` 不同模板行也同行，
见 `default_row_parent_follows_neighbour`）。但当第一组子格里有**跟父格同列**的，
同格落位就把父格盖掉了 —— 上下堆叠主从（A1=地区 / A2=城市，都在 A 列）正是这个形状。

实测（修复前）：
```
A1=region(展开)  →  输出只有 ['上海'] ['杭州'] ['广州']
A2=city(展开,行父A1)   华东 / 华南 整个消失，无告警
```

**修法**（engine.rs `place`）：算出第一组子格里有没有跟父格同列的，有就让整组下移一行。
`row_span` 只用于输出 rowspan（`engine.rs:806`），不参与布局推进，所以让行时
`row_span = 1`（否则子格会被盖进父格的合并区）。

探针：`let own = if collides {1} else {0}` → `let own = 0` → 新用例立刻红，其余 128 条照绿。
修复后：V7 堆叠主从 5 行（华东/上海/杭州/华南/广州）✅，V4 同行主从 3 行不变 ✅。

**第一次修错了**：我先按「子格模板行 > 父格模板行就多给一行」来改，结果
`default_row_parent_follows_neighbour` 从 3 行变 6 行 —— 那个用例里父格和子格
不同模板行但仍要同行。**判据是「同列」不是「下一行」。**

新用例 `stacked_parent_keeps_its_own_row`（mod.rs）。
Rust 128 → **129 通过**。

## 嵌套数组展开落地：UNNEST 预处理（真差距 ① 闭合）

**结论：数据侧不用改引擎。** 在 `render()` 里加一道预处理，把嵌套数组摊平成扁平行，
后面的展开 / 层次坐标 / 行父链全走既有逻辑，不给引擎加「实例 ↔ 嵌套路径」这一层。

### 声明方式：`数组名.字段名`

`field: 'educations.school'` —— 只是个字符串，**不用给 CellModel 加字段**，
契约不用动（mirror-check 照过），模板里也自解释。摊平后前缀会被自动去掉，
因为元素字段此时已和父行字段在同一层。

### 实现（mod.rs）

* `unnest(ds, field)`：每行按数组摊成多行，父行字段 + 元素字段合并。
  元素是对象 → 字段并入；元素是标量 → 挂到数组名上；**空数组保留父行**
  （否则该实体整行消失，明细出空但父行还在）。
* `prepare_dataset(datasets, sheet)`：**先挑数据集，再按需摊平**，替代原来的 `pick_dataset`
  调用点。一个 sheet 只允许一个嵌套数组——多个并进一张扁表会变笛卡尔积，
  所以检测到 2 个以上就**明确告警**（并给出「拆到多个 sheet」的出路），不静默产垃圾。
* 数组名在数据里不是数组 → 也告警（"按普通字段处理"），不闷声。

### 端到端实测

```
张三 / 清华 2,000 / 北大 2,004 / 李四 / 浙大 2,010     ← 多实体 + 嵌套，无告警
张三 | 清华、(空) | 北大、李四 | 浙大                    ← 同行主从，无回归
两个嵌套集合（educations + works）→ 告警并说明拆 sheet
```

### 三条用例 + 双向探针

`nested_array_is_unnested_before_expand` / `two_nested_arrays_warn_instead_of_cartesian` /
`empty_nested_array_keeps_parent_row`。

* 让 `prepare_dataset` 提前 return（不摊平）→ 前两条立刻红
* 让 `unnest` 丢掉空数组的父行 → 第三条立刻红

## 前端补上 `^` / `>` 方向标记 + 抽 applyCellText

导入 xlsx 做完后的**遗留不对称**：方向标记只有 Rust 侧认。前端
`parseCellText('=^ds1.city')` 因为 `FIELD_RE` 不接受前导 `^`，会降级成
`{kind:'expr', expr:'^ds1.city'}` —— 从 Excel 粘一格进来，字段绑定和
展开方向**一起丢**。

* `parseCellText` 认 `^`/`>`，方向带在 `CellText.expand` 上
* `=^`（只有标记没内容）当字面量；层次坐标剥掉标记，expr 里不留 `^`
* `formatCellText` **不写**标记 —— 跟「只写 `=` 不写 `{{}}`」同理，
  方向在 `model.expand_type` 上，不挤进文本
* 方向是**显式覆盖**：写了标记才改，没写保留原有的
  （在已设成纵向展开的格子里改字段名，方向不能跟着丢）

## 一个 sheet 多个数据集（用户纠正了我的错误结论）

我原本把「跨数据集」判成 ❌ 架构上做不到，建议 SQL 侧 JOIN。
用户一句 **「跨数据集 可以是多个, SQL 也是多条的」** 把它推翻了 —— 判错了。

**实测证明判错**：两个 source（ds1=orders、ds2=customers）**两条 SQL 都取到了数**。
卡住的从来不是取数，是引擎里「一个 sheet 只认一份 DataSet」这个假设：
`pick_dataset` 只挑第一个扫到的，其余格子字段取不到 → **静默出空**。
→ 教训：**告警文案说「做不到」，要先分清是「取不到」还是「拿到后不用」**。

### 实现（Rust 侧）

* `Engine.datasets: BTreeMap<String, DataSet>` + `Engine.primary`；
  `CellInst` 记住自己属于哪个 `ds`（`CellInst::new` 多收一个 `ds` 参数）
* `pick_datasets` 引用几个就给几个，**不再告警**；只在「名字不存在」时告警
* `CellModel.join_on`：父子格跨数据集的关联键，取「子数据集里与父行同值」的行
* **绝不按行号硬凑**：没写 join_on / 键取不到值 → 告警 + 出空，不退回全量
* UNNEST 从「一个 sheet 摊平一个数组」放宽成「**一个数据集**摊平一个数组」
* `loop_groups` 多数据集版：主数据集分组，其它数据集**按同名同值跟着筛**；
  某数据集没这个字段就整份透传 + 告警

测试 150 → **154**；五向探针全红（退回单数据集 / join_on 不过滤 /
没写 join_on 硬凑 / 键取不到退回全量 / 循环不筛其它数据集）。

### E2E 的坑（值得记住，浪费了 3 次跑）

1. **端口被旧进程占着** → 新进程绑定失败直接退出，但「/api/config 通了」的
   探活照样成功，于是**测的是上一次会话留下的旧二进制**，结论是假的
   （第一次跑就看到了旧告警文案才发觉）。现在脚本会比对 lsof 里的 PID，对不上就拒绝跑。
2. 改了脚本里的 PORT 却**没把 `--port` 传给二进制** → 白等 16 秒。
→ E2E 固化在 `print-server/scripts/multi-ds-e2e.py`（自带这两道校验）。

## 自定义函数 assign（轻量版，用户选的方向）

原文是【展开前】脚本里写 JS 函数再 `assign("myFunc", myFunc)` 注册 ——
同款要内嵌 JS 引擎（重依赖 + 模板可执任意代码）。用户选了**轻量版**：
`assign("name", 值)` 绑命名变量，表达式里用裸名字引用。不引新依赖。

**唯一的语义难点**：裸标识符怎么分「格子」还是「变量」。
判据 `expr::is_cell_name`：字母+数字（A1/B3/AA10）= 格子，其余 = 变量
（`total`/`rate`/`rate_pct`）。代价：变量不能叫 `x1`。
改完 154 条老测试全过 —— 说明没有模板依赖「裸标识符一律当格子」的旧行为。

* 引用没赋过值的变量 → **告警点名**（静默当 0 用是本项目一直在抓的失败）
* 求值是 `&self`（`eval_call` 也是），所以变量表用 `RefCell` —— 跟已有缓存同款
* 导出 Excel 公式时变量没有对应物 → 该格退化成写值

**探针的意外收获（值得记住）**：六向探针里有**一条没变红** ——
故意不清变量表，跨 sheet 用例照样通过。查下来真实保证是
「render 每张 sheet 新建一个 Engine」，那两行 clear 只是防御性的。
→ **探针没红不等于探针写错，也可能是被测的那行根本不是保证来源**；
  查清楚后把注释改成不抢功的版本，别让注释替代码吹牛。
