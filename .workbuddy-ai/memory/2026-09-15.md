## 前端定义→保存→重开→执行：闭环验完

用真实 `demo.db / orders` 在设计器自由模板里定义了一张两列表（A1 = `=ds1.order_no` 纵向扩展 / B1 = `=ds1.amount` 不扩展），存为 `print-server/reports/orders-free-e2e.json`，刷新页面，从「打开已保存的报表」里重开，再点执行 —— 三行真实数据渲染到预览 Univer：

```
SO20260910001 | 1250.50
SO20260910002 | 88
SO20260910003 | 640.25
```

逐段验证：
* **定义**：A1/B1 的 Univer `cellData` 在右侧面板填完值后是
  `{ t: 4, v: '=ds1.order_no', s: 'tpl-r-field' }` / `{ t: 4, v: '=ds1.amount', s: 'tpl-n-field' }`。
  `s` 是语义样式（r = 纵向扩展、n = 不扩展），来自 `formatCellText` → 模板格→Univer 双向桥。
* **保存**：文件里 `template.sheets[0].rows[0].cells[0].model = { ds:'ds1', field:'order_no', expand_type:'r' }`，
  序列化用的是 `=` 方言（不是 `{{}}`）—— 和之前那批单测里的「真实存盘报表往返」对得上。
* **重开**：dropdown 列出「订单明细（1 个数据源）」，选中后 A1/B1 的 `cellData` 与保存前**逐字节一致**。
* **执行**：`POST /api/reports/orders-free-e2e/run` → 3 行，`dump` 显示
  `B1 <- A1:0,B1:0` / `A1:1,B1:0` / `A1:2,B1:0`，行父链自动推断正确（B1 没显式设 row_parent）。
  `runReport` 的实现是先 `GET /api/reports/:id` 再 `POST /run`，**从磁盘读** —— 不是用内存里的 def，
  所以「重开后执行」和「直接 curl 执行」拿到的是同一条数据，证明存盘是真的源。

### 设计器里几件不该再踩的事

* **画布键入 vs 面板键入**：CDP 多字符文本输入 harness 是坏的（之前已记），所以「在 A1 里手输
  `=ds1.order_no`」这条路验不到。改走右侧面板 `data-testid="free-cell-text"` + `fill` 是稳的：
  React 受控输入，`fill` 改 value → 触发 onChange → `setGridCell` → `applyGrid`。
* **`applyGrid` 是把整张 Univer 拆了重建**（`canvasKey++` 触发 effect dispose + 重 init）。
  所以面板写入后**立刻读** `getRawValue()` 会拿到旧实例的 null —— 要等重建完。
  重建也会把选区重置回 A1，所以「先 activate B1 再填」这种序列里面板填完后选区可能跑回 A1。
  改用 `free-sel-row` / `free-sel-col` 两个 InputNumber 选格子更可靠（测试态友好）。
* **antd 6 Select** 的 `option` 元素不在原 DOM 里（rendered to portal）；要看选项得
  `click [data-testid=...]` 开下拉，再用 `document.querySelectorAll('.ant-select-item-option')`。
* **`fill` 设 input value 之后必须等 React render 完**再读，否则读到的还是上一次的；
  `applyGrid` 也是异步（要等 `useEffect`），所以填完 → 立刻读 model 会误判为「没写进去」。

### 两个真差距（都是实测出来的，不是猜的）

1. **嵌套数组不能展开**。喂 `ds1 = [{name:'张三', educations:[{school:'清华'},{school:'北大'}]}]`，

   输出**一行**，文本是整个 JSON 数组 ` [{"school":"清华",...}] `，子格空。
   原因：`group_by_field` 按「字段值」分组，一个数组值只算一个组。

## 「Excel 作设计器」换成 Univer：三层拆解（设计讨论结论）

用户问 NopReport 那套「Excel 当设计器」的思路能不能换成 Univer。结论：**行，我们已经换了**，
但要拆成三层看，不是一回事：

| 层 | NopReport / Excel | 我们 / Univer | 状态 |
| -- | ----------------- | ------------- | ---- |
| 1 表达式载体 | Excel 格内文本 | Univer 格内文本 `=ds1.city` | ✅ 照搬 |
| 2 扩展元数据 | Excel 批注（hover 才见） | 右栏属性面板（React state） | ⚠️ 换载体 |
| 3 持久化形态 | **.xlsx 文件即 DSL** | ReportDef JSON | ❌ 断 |

第 3 层才是「Excel 作设计器」的真正含义，也是唯一换不掉的地方。
`designer-react` 装的是 Univer 0.25.1，**没有 `sheets-io`**（xlsx 导入导出包），
所以前端 .xlsx 进不来也出不去；出 xlsx 是 Rust 侧 `report/xlsx.rs` 另写的。
`sheets-note` / `sheets-note-ui` / `preset-sheets-note` 在 node_modules 里（批注等价物），但没启用。

**文章自己承认这是复用决策，不是优越性**：「因为 Nop 平台本身就要解析和生成 Excel
用于模型驱动的代码生成，所以只要增加少量扩展注解，就可以把 Excel 变成报表设计器。」
我们没有现成的 Excel 解析/生成，照抄第 3 层反而是负担。

### 一个更干净的做法（待定，没动手）

NopReport 自己也嫌批注看不见，才加了 `*=^` / `*=>` 前缀把扩展方向**塞进格文本**。
我们的 `=` 方言现在只表达「绑什么」（`=ds1.city` / `=D3[B3:+0].sum()`），
方向还在 `model.expand_type` 里，跟格文本分离。
如果把方向也塞进文本（`=^ds1.city` 纵向 / `=>ds1.city` 横向），格文本就**自描述**了 ——
那样即使没有批注、没有 xlsx 导入，格文本本身就是完整定义，
「元数据跟着文件走」的问题顺带解决。改动只在 `BIND_RE` / `parseCellText` / `formatCellText`。

代价：失去「拿客户现成 Excel 模板直接导入」的能力。值不值取决于用户手上有没有存量 Excel 模板。

## 查「真差距能不能实现」→ 挖出一个更严重的静默丢数据 bug（已修）

本来是去评估那两个真差距，结果在验「嵌套数组能不能展开」时撞见一个**更要命**的问题。

### 引擎其实只支持「一个 sheet 一个数据集」

`engine.rs` 里**从不读 `model.ds`**——全文件搜不到 `.ds` / `datasets`。
数据集由 `mod.rs:227 pick_dataset()` 挑：扫全 sheet，取**第一个**遇到 `m.ds` 的数据集，
整个 sheet 共用它。所以「多源」目前是假的：

实测 A1 绑 `ds1.city`、B1 绑 `ds2.name`（两个字段都合法）→ B1 出**空**，且**无告警**。
这正是引擎 warnings 机制专门要抓的「静默产出错误数据」，但它没抓到。

### 顺手挖出的 bug：堆叠主从把父格那一行吃掉了

`engine.rs:1181 place()` 原来把子格从**父格自己那一行**开始排：

```rust
let used = self.layout_group(&children, offset).max(1);  // 子格起点 = 父格起点
self.insts[idx].row_span = used;                          // 父格自己那行没算进去
```

父格锚在「第一组子格」那一行上是**有意为之**（`华东 | 37,900` 不同模板行也同行，
见 `default_row_parent_follows_neighbour`）。但当第一组子格里有**跟父格同列**的，
同格落位就把父格盖掉了 —— 上下堆叠主从（A1=地区 / A2=城市，都在 A 列）正是这个形状。

实测（修复前）：
```
A1=region(展开)  →  输出只有 ['上海'] ['杭州'] ['广州']
A2=city(展开,行父A1)   华东 / 华南 整个消失，无告警
```

**修法**（engine.rs `place`）：算出第一组子格里有没有跟父格同列的，有就让整组下移一行。
`row_span` 只用于输出 rowspan（`engine.rs:806`），不参与布局推进，所以让行时
`row_span = 1`（否则子格会被盖进父格的合并区）。

探针：`let own = if collides {1} else {0}` → `let own = 0` → 新用例立刻红，其余 128 条照绿。
修复后：V7 堆叠主从 5 行（华东/上海/杭州/华南/广州）✅，V4 同行主从 3 行不变 ✅。

**第一次修错了**：我先按「子格模板行 > 父格模板行就多给一行」来改，结果
`default_row_parent_follows_neighbour` 从 3 行变 6 行 —— 那个用例里父格和子格
不同模板行但仍要同行。**判据是「同列」不是「下一行」。**

新用例 `stacked_parent_keeps_its_own_row`（mod.rs）。
Rust 128 → **129 通过**。

## 多数据集静默出空 → 改成显式告警（已做）

承接上一条的发现（引擎一个 sheet 只支持一个数据集）。`pick_dataset` 现在返回
`(DataSet, Vec<String>)`，把两类静默问题报出来：

1. **引用了多个真实存在的数据集** —— 只有一个生效，其余格子取不到字段会出空：
   `[双源] 本 sheet 引用了多个数据集（ds1、ds2），但一个 sheet 只能用一个，
   实际用的是 ds1；绑到其余数据集的格子取不到字段，会出空
   （要跨数据集请先在 SQL 侧 JOIN 成一张表）`
2. **引用了不存在的数据集名** —— `单元格引用了数据集 ds3，但提交的数据集里没有它（有：ds1、ds2）`

端到端实测：之前 A1=ds1.city / B1=ds2.name 出空且 `warnings: null`，
现在 `warnings` 带上上面第 1 条；单源的 `orders-free-e2e` 照旧 `warnings: None`（无误报）。

### 三条新用例 + 双向探针

* `multi_dataset_reference_warns` —— 要求告警出现
* `single_dataset_reference_does_not_warn` —— 要求**不**告警（防噪声淹正常报表）
* `unknown_dataset_name_warns` —— 要求点名不存在的数据集

探针（两个方向都试了，证明不是空转）：
