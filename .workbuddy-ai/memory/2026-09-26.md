### 1. 新增 `scripts/check-all.sh`

把 6 道已有闸串起来，**便宜优先**排序（出错时几十秒内看到）：
mirror-check(1s) → ts-check(2s) → ts-test(5s) → project-check designer-react(18s)

**对初版方案最重要的修正：三种结果，不是两种。**

```
0 通过 · 1 失败 · 2 没跑成（环境缺东西，**根本没检查**）
```

- 「没跑成」算成**通过** = 假绿（最坏）
- 「没跑成」算成**失败** = 假红（本项目在 `node-bin.sh` 里专门为这个写过注释）

实测三态：
- 正常 → 退出码 0，`通过 6 · 失败 0 · 没跑成 0`

另有 `--fast`（3.5s，只跑前两道）与 `--list`。
**没有 `--fast` 的话 36 秒的脚本会没人跑 → 又回到「有闸没跑器」。**

### 4. 顺手修：3 个闸脚本自己的输出被**静默吃字节**

跑 check-all 时日志里有非法 UTF-8 字节。追下去是**本机 bash 3.2.57** 的坑：

```bash
V=abc; echo "测试 $V）"      # → 「测试 」+乱码；abc 与 ） 的头一字节都没了
V=abc; echo "测试 ${V}）"    # → 正确
```

**`$VAR` 紧跟非 ASCII 字符 → 静默吃掉变量的值 + 多字节字第一个字节。**
退出码正常、脚本照跑，只是**打印的数字凭空消失**：
`检查 31 个文件（源码 13 / 测试 18）` 印成 `测试 ）`。

受影响 4 处：`ts-check.sh:69`、`ts-project-check.sh:69`、`ts-project-check.sh:76`（2 处）、
以及我新写的 `check-all.sh:66`。全部改 `${VAR}` 并就地写明原因。

**对照实测**（哪些写法安全）：`${V}）` ✓ · `$V""）` ✓ · `$V ）` ✓ · `printf` ✓ ·
**`$(...)` 不受影响** · `（$V`（变量在多字节字之后）✓ · **`$V）` ✗**。
`zsh` 实测**同样中招**，所以不是 bash 专属。
排查手法：搜 `\$[A-Za-z_]\w*(?=[\x80-\xff])`（`\$` 转义的不算）。

**为什么值得单独记**：它出在**闸脚本自己的状态行**上 —— 也就是「本该说真话的那一行」。

### 报告里几条**以前没在记忆里写过**的算法事实

- **`span_of` 是自底向上算展开范围**（`engine.rs:257`），叶子 `(0, 自身跨度)`，
  非叶子取自身与所有子格 `(子格号+子 offset, +子 span)` 的并集。`collect_spans`
  必须覆盖**全部**格子（含无子格的叶子），否则顶层展开格查不到范围。
- **`default_row_parent` 第 ② 步读的是「解析后」的父格**（含推断出来的）→
  这就是 `resolve_parents` 必须**按行优先序一次性预扫**的原因。
- **`place` 的「同格冲突让一行」**（`engine.rs:1846-1849`）：第一组子格里有跟父格同列的
  → 整组下移一行，否则上下堆叠的主从（A1 地区 / A2 城市）会把地区名**静默盖掉**。
- **`layout_group` 的 `share_row` 判据**（`engine.rs:1894-1895`）：
  `group.len() > 1 && (col_expand || col_parent.is_some())` —— 列展开的兄弟格共享一行。
- **`compute_display` 只覆盖文本、不动 `value`**（`engine.rs:2080-2082`）：
  字典把 1 显示成「是」时，Excel 里那格还是数字 1。这是刻意的（导出后仍可透视）。
- **`merge_down` 不参与布局推进**（`engine.rs:1824-1826`），
  否则多级表头会**凭空多出一行**。
- **`coord_prefix_cache` 第一版是错的**（`engine.rs:824-827`）：把逐行的维度塞进缓存键
  → 键逐行不同 → **永不命中** → 8000 行 149 ms 曲线照旧平方。
  正确做法是「把逐行的维度变成**下标**」。
- **`agg_of_numbers` 是六个聚合函数的唯一口径**（`engine.rs:591`），
  但 `"counta"` **刻意不走它**（要的是 `non_null` 不是 `count`）。
- **PNG 是 1 位灰度 + 全 stored 块的非压缩 DEFLATE**，zlib 头 `0x78 0x01`（`png.rs:91`）。
- **xlsx 图表数据写表格下方隐藏列**（`xlsx.rs:375`、`xlsx.rs:430`）：
  模板坐标展开后可能不连续（0/3/6 行），而 Excel 一条序列只能引用**一个连续区域**。
- **`row_pixels(pts) = round(pts × 4/3)`**（`xlsx.rs:108-109`）—— 行高是另一套换算。

### ② 非收敛：值必须与**最终**可见集合对齐

- 老行为：`evaluate_to_fixpoint` 到 `MAX_ROUNDS` 强行 `break` 时**不重置 `evaluated`** →
  最后一轮的 `value` 用的是**上一轮**的 hidden，而 `hidden` 已是最后一轮的 → 两者不同步。
  实测：最终 3 行可见，`C1` 显示 **0**。
- 修法：未收敛时「清轮缓存 → 重置 `evaluated` → 按**已冻结**的最终 hidden 重算全部值」。
  抽了两个 helper：`clear_round_caches()` / `reset_evaluated()`。
  **`cycle_warned` 刻意不重置** —— 它是「同一个环只报一次」的闸，重置会让环告警刷屏。
- 附带：老告警文案「已按最后一轮结果出表」**与事实相反**（数值恰恰不是最后一轮的），
  换成「…该条件在最终数据上仍不成立 —— 这张表的结果**不稳定**，不要当作可发布的结果」。
- 测试：`nonconvergence_tests::forced_exit_recomputes_values_against_final_visibility`
  （3 条断言：值 == 最终可见数、不稳定告警恰好 1 条且老文案消失、`grid.len() == 3`）。

### ① 落位冲突：检测 + 上报，**不**去「修好布局」

- 老行为：`grid[r][c] = Some(..)` **没有占用检查** → 后写静默覆盖前写。
  同一模板行两个列展开格 → 6 实例只落 4 位，出表 `1月 Q1 Q2 Q3`，**零告警**。
- 修法：写入点加占用检查 —— 冲突时**保留先创建者**（序号小 = 模板位置靠前，结果稳定可预测），
  后到者标 `dropped`（与「没被 place 过」同义 → 图表解析等后续环节自动跳过），
  冲突**逐条告警**（坐标 + 两个 pos + 可执行建议），**上限 20 条**，超出只报总数。
- **刻意不修布局**：两个**独立的**列展开本来就没有合法二维布局，硬排只会得到
  **看起来像正常交叉表**的 `1月 Q1 Q2 Q3`（每列都有值，完全不像出错），比报错更危险。
  现在的结果 `1月 2月 3月 Q3` **一眼能看出是坏的**。

## 第三步：分级诊断通道（`Issue`）—— 落地

用户说「下一步」。我把 `warnings: Vec<String>` 换成了**分级 + 带 code** 的通道。

### 形态

`print-server/src/report/issue.rs`（新文件）：

```rust
enum IssueLevel { Info, Warning, Error }   // Ord 是有意的：level >= Warning 就进 warnings
struct Issue { level, code: String, sheet: Option<String>, pos: Option<String>, message }
struct IssueSink<'a>(&'a mut Vec<Issue>);  // 见下面「借用陷阱」
```

- `Engine` 私有字段 `warnings: Vec<String>` → `issues: Vec<Issue>`；
  `warnings()` 变成**派生视图**（`level >= Warning` 的 message），新增 `issues()`。
- `RenderResponse` 增量加 `issues`，`warnings` **保留** → 前端零改动。
- TS 镜像：`grid-report.ts` 加 `RenderIssue` / `IssueLevel` / `IssueCode` +
  `RenderResponse.issues`（`mirror-check.py` 盯着 `RenderResponse`，不加就红 —— 这条闸有用）。

### 一个**关键的**结构决定：`warnings` 是派生的，不是并列的

原来 `[sheet] ` 前缀是**拼进消息字符串**里的（`format!("[{}] {}", sheet, w)`）。
如果 `issues` 另存一份消息，就变成「同一份事实声明两遍」→ 必然漂移。

所以改成：**消息不带前缀，归属放 `sheet` 字段**，末尾统一派生 `warnings`。
于是「某条告警只进了 `warnings`、没进 `issues`」在结构上不可能发生。

顺带把 `loop_groups` / `check_paper_consistency` 的签名从 `&mut Vec<String>`
改成 `&mut Vec<Issue>` —— 否则那几条（数据集/循环变量/纸张一致性）会**只进 warnings**，
又是一个静默缺口。

### 借用陷阱：`Engine::warn(&mut self)` 在循环里编不过

`expand_sheet` 里有 `for (i, inst) in self.insts.iter().enumerate()`，
循环体里要记诊断。`self.warnings.push(..)` 只借**一个字段**所以一直合法；
换成 `self.warn(..)`（借整个 `*self`）后 **6 处 E0502**。

解法：`IssueSink(&mut self.issues)` 字段级包装，在循环里用**临时值**形式
（`IssueSink(&mut self.issues).warn(..)`）—— 借用只活在那一条语句里。
`Engine` 上那四个 helper 只是转发。**这个包装的存在理由是借用粒度，不是抽象。**

## 第四步：③④ —— 跨数据集关联的两处静默错数（已完成）

用户顺序 `② → ① → 结构化错误 → ③④` 的**最后一项**。两个缺陷同族（评审 §三.4）。

### ③ 跨数据集列主格按裸行号求交

`col_parent_index` 把列主格的 `rows` 当**裸行号**与当前格的 `base` 求交。
列主格的 `rows` 是**它自己那份数据集**的行号 → 跨数据集时两套行号没有共同含义。
实测 ds1 两行 / ds2 三行 → ds2 第三行（333）**静默消失、零告警**。

**修法：拒绝 + `Error`**（`cross_ds_col_parent`，本格一格都不建）。
判据 `insts[cp].ds != cell_ds_name`；**过滤必须在建 `row_to_cp` 之前**
（那个索引直接拿列主格 rows 建，混进跨数据集实例 = 两套行号混进一张表）。

### ⚠️ 本次最重要的发现：**① 修好后，③ 的复现形状变了**

③ 的原探针里数值格与列头在**同一模板行** → **① 的落位冲突检测先把它拦下了**。
一度真的怀疑「③ 是不是 ① 的重复」。

**分离办法**：把数值格移到列头的**下一行**（交叉表的正常形状）→ 不撞列、① 完全不响，
而裸行号求交**照样静默对齐**。两份数据集**等长**时输出

```
行0: "1月" | "2月" | "3月"
行1: "111" | "222" | "333"          ← 零诊断，看着完全正确
```

**纯属行数巧合**，这才是最危险的形态。回归测试里把子表顺序倒过来（333/222/111），
并**显式断言该形状里没有 `layout_collision`** —— 那一句就是「③ 独立于 ①」的判据。

**一般化教训**：一个缺陷的「复现形状」可能被**另一个修复**吃掉。
修完 A 之后要重跑 B 的探针 —— 若 B 的探针不再红，先别宣布 B 已修，
要问「是 B 修好了，还是 A 把 B 的症状盖住了」。**症状消失 ≠ 根因消失。**

### ④ `join_view` 用父实例首行代表整组

原注释「取第一行（**分组格下它们同键**）」—— 括号里那个前提**没有任何校验**。
分组字段 ≠ 关联字段时组内各行键不同 → 少取数。实测华东组内 cust=1/2（100/200）
只拿到 100，200 静默丢失。

**修法：取组内全部键值求并集**（组关联语义）。

- **同键**（绝大多数模板）→ 并集退化成单值 → 走**原来那条直接比较**分支，
  O(|子表|)、无额外分配、**逐字节一致**；
- **多键** → `HashSet` 求并集（线性 `contains` 会退化成 O(|子表| × 组内键数)）；
- 多键是**语义变化**（作者会看到不同的数）→ 报 `Warning`（`join_key_not_grouped`）。
  **不报就是新的静默行为变化。**

**已知行为差异（已披露）**：旧代码取 `rows.first()`，若首行恰好没有关联字段而后行有，
旧行为是「告警 + 空」，新行为取到后行的值。同质数据集不会出现，但确实是差异。
