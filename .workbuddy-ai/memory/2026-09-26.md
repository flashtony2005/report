## 按「架构体检」第 1 档动手：加跑器 + 补表钉子

用户选了第 1 档（`check-all.sh` + `PAPERS/KINDS/SYMBOLOGIES` 数量钉子）。
**做的时候发现三件事与体检报告的初版结论不符**，都已更正 —— 见下。

### 1. 新增 `scripts/check-all.sh`

把 6 道已有闸串起来，**便宜优先**排序（出错时几十秒内看到）：
mirror-check(1s) → ts-check(2s) → ts-test(5s) → project-check designer-react(18s)
→ project-check openprint(6s) → cargo test(4s 暖 / 1m33s 冷)。**热跑全量约 36 秒**。

**对初版方案最重要的修正：三种结果，不是两种。**

```
0 通过 · 1 失败 · 2 没跑成（环境缺东西，**根本没检查**）
```

- 「没跑成」算成**通过** = 假绿（最坏）
- 「没跑成」算成**失败** = 假红（本项目在 `node-bin.sh` 里专门为这个写过注释）

实测三态：
- 正常 → 退出码 0，`通过 6 · 失败 0 · 没跑成 0`
- 把 rustup 从 PATH 摘掉 → 退出码 **2**，`⚠ 没跑成：找不到 cargo`，末行 `有闸没跑器成 —— 不等于通过`

另有 `--fast`（3.5s，只跑前两道）与 `--list`。
**没有 `--fast` 的话 36 秒的脚本会没人跑 → 又回到「有闸没跑器」。**

### 2. 补表钉子 —— 但改了形式：**钉内容，不钉数量**

- `KINDS`（`chart.rs`）与 `SYMBOLOGIES`（`barcode.rs`）各加一条内容钉子
  `assert_eq!(X.to_vec(), vec![...], "…要同步 TS 的 …")`。
- **理由**：`assert_eq!(X.len(), 3)` 对**改名**（`pie`→`donut`，数量不变）毫无反应。
- 新增 `scripts/fault-inject-table-pins.py`：**5 条注入 5/5 抓到**，含**两条「改名」**
  （专门证明内容钉子 > 数量钉子），文件逐字节还原（sha256 比对）。

脚本里防了一个坑：**`cargo test <过滤名>` 匹配不到用例时仍返回 0** → 打错用例名会伪装成「通过」。
现在会数真的跑了几条 `... ok` / `... FAILED`，匹配不到就报「**没验过**」。

### 3. 🔴 更正：`PAPERS` **本来就有**钉子 —— 我体检报告里那句是错的

体检报告 §2.2 我写「纸张/图表/码制三张表都没有钉子」，判据是
`grep -rnE 'assert_eq!\((PAPERS|KINDS|SYMBOLOGIES)\.len\(\)'` → 无匹配。

**纸张那句错了。** `model.rs:1517 paper_table_is_pinned` 用的是
`assert_eq!(PAPERS.to_vec(), expect, "…")` —— **是内容钉子，比数量钉子更强**。
我的 grep **只匹配 `.len()` 形式**，于是静默漏掉它，然后据此下了个错结论。

**`KINDS` / `SYMBOLOGIES` 那两句是对的**（它们确实一个钉子都没有）。

**教训（跟 BSD grep 的 `\|` 是同一族）**：
判「有没有闸」**不能只搜一种写法** —— 要搜**符号名本身**（`PAPERS`），再逐个看它的用法。
`grep` 说「没有」时先怀疑 grep。
已在报告 §2.2 加了更正框、§7.4 复述、并把 §4 第 2 档那条「给 PAPERS 补钉子」改成「PAPERS 不用补」。

### 4. 顺手修：3 个闸脚本自己的输出被**静默吃字节**

跑 check-all 时日志里有非法 UTF-8 字节。追下去是**本机 bash 3.2.57** 的坑：

```bash
V=abc; echo "测试 $V）"      # → 「测试 」+乱码；abc 与 ） 的头一字节都没了
V=abc; echo "测试 ${V}）"    # → 正确
```

**`$VAR` 紧跟非 ASCII 字符 → 静默吃掉变量的值 + 多字节字第一个字节。**
退出码正常、脚本照跑，只是**打印的数字凭空消失**：
`检查 31 个文件（源码 13 / 测试 18）` 印成 `测试 ）`。

受影响 4 处：`ts-check.sh:69`、`ts-project-check.sh:69`、`ts-project-check.sh:76`（2 处）、
以及我新写的 `check-all.sh:66`。全部改 `${VAR}` 并就地写明原因。

**对照实测**（哪些写法安全）：`${V}）` ✓ · `$V""）` ✓ · `$V ）` ✓ · `printf` ✓ ·
**`$(...)` 不受影响** · `（$V`（变量在多字节字之后）✓ · **`$V）` ✗**。
`zsh` 实测**同样中招**，所以不是 bash 专属。
排查手法：搜 `\$[A-Za-z_]\w*(?=[\x80-\xff])`（`\$` 转义的不算）。

**为什么值得单独记**：它出在**闸脚本自己的状态行**上 —— 也就是「本该说真话的那一行」。
