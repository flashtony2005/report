### 一个先决约束（先查清楚才动手）

`print_job.rs:261-266` 走的是 Chrome/Edge `--headless=new --print-to-pdf`，
**这个 CLI 吐不出页眉页脚页码**（只有 CDP 的 `Page.printToPDF` 能），
而 Chrome 根本不支持 CSS `@page` 的 margin box。
→ 页码只能是**服务端烤进 HTML 的内容**，且只在服务端真知道页数时才有意义。
这条决定了整个设计，动手前先确认了它。

### 三个「静默失败」是我自己发现并修掉的（不是测试报的）

1. **Excel 页脚 255 字符上限**：`rust_xlsxwriter` 的 `set_footer` 超过 255 字符
   会 `eprintln!` 然后 `return self` —— **静默丢弃**，导出成功但页脚不见。
   按**字符**数（不是字节）算，且要算上 `&C` 两个控制字符。已在上游拦成 400。
2. **`apply_options` / `withPage` 的替换-而非-合并**：结构体字面量只写分页三项
   会把作者存的页面设置**静默抹掉**（存盘文件里有、跑出来没有）。
   服务端用 `PageConfig::with_pagination_of`（`..self.clone()`），TS 侧 `withPage` 用 `...page`。
3. **`page` 变成 `Some` 的原因不止分页** → `xlsx_handler` 里的
   `repeat_header_rows.max(1)` 会把「预览 2 行表头」静默变成「导出 1 行」
   —— 正是那段代码当初要修的 bug。抽成 `xlsx_header_rows()` 加 `.filter(|p| p.rows_per_page > 0)`。

### 一条**自己的测试抓到真 bug** 的（别删这条用例）

### B5 的口径（别再当 typo 改回去）

`PAPERS` 里 **B5 = 182×257（JIS）**，不是 ISO 的 176×250。
理由：Excel 纸张码 13（界面写「B5」）就是 JIS 那个；按 ISO 配码 34 会出现
「HTML 按 176×250 排版、Excel 按 182×257 出纸」。ISO B5 本项目**不支持**。
`paper_table_is_pinned` 的失败文案里写明了这是**口径变更**而不是笔误。

### 预检误报（跨端契约，本轮修掉）

TS 的 `pageSetupProblem` 注释原本写着「子集只会漏报、不会误报」，
但纸张名比对是**大小写敏感**的，而服务端 `paper_mm` 用 `eq_ignore_ascii_case`
→ `"a4"` 会被设计器拦下、服务端照样编得出来 = **误报**，正是这套预检唯一不该犯的错。

两边必须保持这个**不对称**，别「顺手」放宽。

### 2. xlsx 数据文件：`raw: false` 对报表是**静默错**（实测 SheetJS 0.18.5）

| 单元格 | `raw: false` | `raw: true` + `cellDates` |
| --- | --- | --- |
| 套了货币格式 `"¥"#,##0.00` 的 1234.5 | `"¥1,234.50"` **字符串** | `1234.5` 数字 |
| 日期格 2024-01-02 | `"1/2/24"`（随 locale 变） | `Date` → `2024-01-02` |
| 文本格 `007` | `"007"` | `"007"` |

- 第一行**比普通字符串数字更重**：`"100"` 至少 `as_num()` 的 `parse::<f64>()` 能成功
  （合计对、只有导出错）；`"¥1,234.50"` 连 parse 都失败 → **合计也错**。
  套了货币 / 千分位格式的金额列是最常见的触发方式，**预览完全看不出来**。
- `@/design/utils/data-import` 的 `parseDataFile` 用的就是 `raw: false`
  （它的另一个消费者「画布数据表」要的就是字符串）。**刻意不改它** ——
  改共享行为是拿别人的功能冒险。两处口径不同是**有意的**。
- 所以新加 `parseWorkbookFile()`：`raw: true` + `cellDates: true`，
  且用 **`header: 1` 要矩阵**（不是对象）→ `rowsFromMatrix` 的全套校验全部复用，
  不必为 xlsx 再写一遍。
- 日期转字符串的判据：**UTC 零点才截成 `YYYY-MM-DD`**，真带时间的输出完整 ISO。
  `JSON.stringify(Date)` 给 `2024-01-02T00:00:00.000Z`，一列日期全是这种串没法看，

### 4. 测试抓出来的一个真 bug：`fileNameFromUrl` 把**主机名**当文件名

手写 `split('/')` 取最后一段 → `http://a/` 得到 `a`（主机名！）、
`http://api.example.com` 得到 `api.example.com` —— 而主机名里有点，
于是 `com` 这种「看着像后缀、其实不是」的东西会被当后缀用。
**必须用 `new URL(url).pathname`**（不是完整 URL 时 `new URL` 会抛，退回按路径处理）。

同理 `fileExtension` 也要**先取 basename 再找点**，否则 `/api/v1.0/data` 得出 `0/data`。

### 5. #87 设计器 UI：数据来源二选一（数据库 / 文件·接口）

- `Segmented` 切换 `dataSourceKind`；文件侧隐藏 `<input type=file>` + 按钮，
  接口侧 `Input` + 「取数」按钮。
- **接口取数刻意走前端 `fetch`，不做后端代取** —— 后端代取 = 任意 URL 请求原语（SSRF），
  与本项目「图片只收 data URI、不收文件路径」的既有取舍一致。
  代价（CORS 被挡只有 `Failed to fetch`）**写进错误文案**并提示改用文件导入。
- **失败一律报错，绝不退化成空表**：空表和「接口真的返回 0 行」长得一模一样。
  注意预览的自动刷新是 `doRender(true)`（**silent**，错误被跳过），
  所以数据来源的错误**只能靠界面自己那个 Alert** 显示出来。
- **打开报表时要把来源重置回 `db` 并清掉内联数据**：不清的话，之前选的文件行会
  继续生效（`datasets` 同名时盖过 `sources`）→ 新打开的报表渲染的是**上一个文件的数据**，
  表头是报表的、数字是别人的，屏幕上完全看不出异常。
- **存盘要提示「内联数据不会被保存」**：报表文件存的是**数据源声明**而不是数据快照，
  而文件 / 接口这条**没有可存下来的声明** → 存出来的报表「无数据源」。
  不提示就是静默丢数据（要到「打开后执行没数据」才发现）。

### 6. 测试帮手踩坑：antd `Button` 会在**两个汉字**之间插空格

`保存` 渲染成 `保 存`、`取数` 渲染成 `取 数` → 严格相等匹配永远找不到它们。
（`分组汇总` / `自由模板` 是 4 个字，不受影响，所以这个坑只在 2 字按钮上暴露。）
→ 按文字找元素时**先去空白再比**。一开始只比 `trim()`，四个用 Button 的用例全报「找不到元素」。
