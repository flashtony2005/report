## exportFormula：valueExpr → Excel 公式（NopReport 清单最后一块大的）

- 模型：`CellModel.export_formula: Option<bool>`（18 字段）、`GridCell.formula: Option<String>`。
  TS 镜像已同步，`mirror-check.py` 全绿。
- 翻译在**布局之后**：层次坐标此时能落成具体格，`C2[A2:+0].sum()` 在 1 月占两行 → `SUM(C2:C3)`。
  `Engine::excel_formula` → `excel_of`(AST→串) + `excel_refs`(实例组→引用；
  同列且行连续折叠成区间，否则逗号列出)。
- **刻意不翻**（回落写值 + 告警）：PROPORTION/ACCSUM/RANK/NVL（Excel 无同名函数）、
  `{}` 条件（格集过滤无对应物）、`$` 与 `value`（依赖求值上下文）、自引用。
  原则：半对不对的公式比静态值危险——它看起来能算，结果是错的。
- **分页 + 公式冲突（自己测出来的）**：公式坐标按整表生成，逐页复制后行号对不上，
  第 2 页的 `SUM(C2:C5)` 只算本页几行，跟同一格显示的静态值（整表合计）不一致。
  → 多页时统一回落写值并告警；未分页的 `sheets` 视图保留公式。

  按缩进批量替换只命中展开格那一支 → 非展开格 `export_formula` 恒 false 且**无任何报错**。
  是测试先发现「公式全为 None」才定位到。**加字段必须两个分支都拷 + 测试兜。**
- 前端可达：`openprint` 新增 `withExportFormula(tpl, on)` 后处理（不动三个构造器签名），

## CUPS 打印机枚举（macOS / Linux）—— 补齐「能打却列不出来」的半套

`print-server/src/printers.rs` 原先非 Windows 上 `list_printers()` 直接返回空列表，
打印链路（`print_job.rs`）已经走 CUPS `lp`，却列不出队列。现已补上：

- 两路实现共用 `PrinterInfo`，靠 `cfg` 切换：
  队列 `EnumPrintersW` L2 / `lpstat -a`；默认 `GetDefaultPrinterW` / `lpstat -d`；
  状态 `PRINTER_INFO_2W.Status` / `lpstat -l -p`；描述 `pDriverName` / `Description:` 续行（无则回落 `"cups"`）；
  能力 DevMode+`DC_BINNAMES` / `lpoptions -p NAME -l`。
- `classify_kind()` 解除 cfg 门控，两路共用。
- 解析函数全是 `&str -> T` 纯函数（`parse_lpstat_a` / `_d` / `_l_p` / `parse_lpoptions_l`），
  命令执行只在 `run_cups()` 一处。本机没配队列 → 7 个单测喂合成输出。

踩到的坑（写下来是因为都会重复遇到）：
1. **`run_cups` 不能看退出码**：没配队列时 `lpstat -a` 退出 1 且提示打到 **stderr**，
   那是「没有打印机」不是失败。看退出码会误判。
2. **`LC_ALL=C` 压不住本地化**：这台机器上 `LC_ALL=C lpstat -a` 仍输出中文「未添加目的位置。」。
   解析必须走白名单（只认 `accepting` / `rejecting` 关键字），不能依赖英文文案。
3. **「支持双面/彩色」看选项里有没有该值，不看默认选了哪个**：`lpoptions -l` 列出的就是全部合法值，
   `Duplex: *None DuplexNoTumble DuplexTumble` 即使默认 `None` 也算支持；只有 `*None` 才算不支持。
   `*` 前缀只用来定 `defaultDpi`。
4. 纸盒名保留原始大小写给用户看；用于比较的 `bare()` 才转小写（第一版复用 `bare()` 全小写化了）。

端到端验证手法（本机无真实队列，值得复用）：往 `PATH` 前面塞假的 `lpstat` / `lpoptions`
（吐一台彩色双面带 4 纸盒的默认机 + 一台暂停的单色机），起服务打 `/printers` 看字段对不对。

测试数 76 → 83。

## ⚠️ macOS BSD grep 在 BRE 下不支持 `\|`（同一个坑踩了两次）

`grep -v '\.spec\.\|__tests__'` 在 macOS 上 `\|` 被当字面量 → **过滤静默失效**。
后果：`scripts/ts-check.sh` 一直把 spec 文件也送进 tsc，固定报 4 条 TS2347 噪声，
看久了没人看，等于检查形同虚设。

- 修法：用多个 `-e`（POSIX 写法），并把源码 / 测试分开跑（测试多过滤一条 TS2347），
  有残留错误 `exit 1`，可挂 CI。
- 顺便：**用 Bash 跑 grep 时一律 `grep -E` 或直接用 Grep 工具**。我自己写完修复后
  紧接着又用 `grep "a\|b"` 去查代码、得到「不存在」的错误结论，差点误判字段没实现。
