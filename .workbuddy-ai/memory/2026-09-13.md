## CUPS 打印机枚举（macOS / Linux）—— 补齐「能打却列不出来」的半套

`print-server/src/printers.rs` 原先非 Windows 上 `list_printers()` 直接返回空列表，
打印链路（`print_job.rs`）已经走 CUPS `lp`，却列不出队列。现已补上：

- 两路实现共用 `PrinterInfo`，靠 `cfg` 切换：
  队列 `EnumPrintersW` L2 / `lpstat -a`；默认 `GetDefaultPrinterW` / `lpstat -d`；
  状态 `PRINTER_INFO_2W.Status` / `lpstat -l -p`；描述 `pDriverName` / `Description:` 续行（无则回落 `"cups"`）；
  能力 DevMode+`DC_BINNAMES` / `lpoptions -p NAME -l`。
- `classify_kind()` 解除 cfg 门控，两路共用。
- 解析函数全是 `&str -> T` 纯函数（`parse_lpstat_a` / `_d` / `_l_p` / `parse_lpoptions_l`），
  命令执行只在 `run_cups()` 一处。本机没配队列 → 7 个单测喂合成输出。

踩到的坑（写下来是因为都会重复遇到）：
1. **`run_cups` 不能看退出码**：没配队列时 `lpstat -a` 退出 1 且提示打到 **stderr**，
   那是「没有打印机」不是失败。看退出码会误判。
2. **`LC_ALL=C` 压不住本地化**：这台机器上 `LC_ALL=C lpstat -a` 仍输出中文「未添加目的位置。」。
   解析必须走白名单（只认 `accepting` / `rejecting` 关键字），不能依赖英文文案。
3. **「支持双面/彩色」看选项里有没有该值，不看默认选了哪个**：`lpoptions -l` 列出的就是全部合法值，
   `Duplex: *None DuplexNoTumble DuplexTumble` 即使默认 `None` 也算支持；只有 `*None` 才算不支持。
   `*` 前缀只用来定 `defaultDpi`。
4. 纸盒名保留原始大小写给用户看；用于比较的 `bare()` 才转小写（第一版复用 `bare()` 全小写化了）。

端到端验证手法（本机无真实队列，值得复用）：往 `PATH` 前面塞假的 `lpstat` / `lpoptions`
（吐一台彩色双面带 4 纸盒的默认机 + 一台暂停的单色机），起服务打 `/printers` 看字段对不对。

## 设计器暴露展开控制（min / max / keepEmpty）—— 按层级分别作用

引擎早有这三个字段、也有 `expand_count_limits` 单测，纯 UI 缺口。补的时候发现
**语义必须定死**：分组模板里每个分组格都带 `expand_type:'r'` 且 `row_parent` 链式嵌套，
一律打在所有行展开格上会逐级相乘（2 级 + 最少 5 行 = 至少 25 行）。用户确认的规则：

| 属性 | 打在哪 | 理由 |
|---|---|---|
| `expandMinCount` | 最内层行展开格 | 「每组至少 N 行」是明细级；打外层变「至少 N 个分组」 |
| `expandMaxCount` | 最外层行展开格 | 「TOP N」是分组数；打内层变「每组只显示 N 行」 |
| `keepExpandEmpty` | 所有行展开格 | 逐级保留，空报表才有空行撑着表头 |

只作用于行展开格（`expand_type === 'r'`），列展开格不管。

关键点：`cell()` **不写 `pos`**（服务端按行列下标推断），但构造器写 `row_parent` 时用的是
`cellPos()`。所以 `withExpandControl()` 得用同一个 `cellPos()` 把位置补算回来，
再比对「谁被别的行展开格认作父格」→ 最外层 = `row_parent` 不在行展开格集合里；
最内层 = 自己的 pos 没被别的行展开格认作父格。

## 缺省父格：补上「跟随左邻父格」+「最左格/第一行兜底」，并修正 A0（测试 83 → 92）

上游源码在 `nop-report/nop-report-core/src/main/java/io/nop/report/core/build/XptModelInitializer.java`
（注意是 `build/` 不是 `model/`）。对照它逐行实现，两个光看文档会做错的点：

1. **「跟随」跟的是解析后的父格，不只是显式声明的**——上游 `initParentChildren` 会把
   推断结果**回写**进 model（`if (xptModel.getRowParent() == null) setRowParent(...)`）。
   所以得按 (r,c) 缓存已解析结果（新增 `Resolved = BTreeMap<(usize,usize), ParentDecl>`），
   扫描时读它。
2. **`A0` 之前是错的**：`filter(|p| !is_root_ref(p)).or_else(default_...)` 把 A0 当「没写」
   → 落进缺省推断，与注释和上游（`if (rowParent == NONE) return null`）都不符。
   改成 `ParentDecl` 三态 `{Ref, ExplicitNone, Unset}`。

「最左格兜底」照抄了但**在我们的行序下基本不可达**：扫描一定会检查到 col 0，
若它有父格第 1 条就已跟随；兜底读同一个格子。只有上游合并格 `getRealCell()` 的差异才会走到。

### addDefaultRowParents（规则 3）：能实现，暂不做

需要 `rowExpandOffset`/`rowExpandSpan`，而它是**沿 row 子格树自底向上算出来的**
（`collectRowChild` L439-471），不是模板字段；且要在 `initParentChildren` 之后的第二遍跑。
即必须把父格解析从「边建实例边算」抽成模板 pre-pass（Pass0 解析 / Pass1 建树算 span /
Pass2 addDefaultRowParents / Pass3 建实例）。

不做的理由：三个构造器给小计合计格都**显式**写了 `row_parent`，而规则 3 门槛是
`cm.getRowParent() == null`（声明为空）→ 不触发；且顶层扩展格 span=1、范围够不着小计行；
再者它会覆盖已推断的父格，有回归风险。真受益的是手写模板，目前没有手写入口。

## 自由模板（类 Excel 逐格设计）—— 补上「没有手写入口」这个洞（commit `2bcfad9`）

之前 `row_parent` / `col_parent` / `expand_type` / `value_expr` 在 designer-react 里
**一次都没出现过**：只有 4 个向导（样例/分组/交叉/画布）机器拼模板，18 个 CellModel
字段只能靠手写 JSON 触达。这也是之前判断 `addDefaultRowParents`「暂不做」的理由之一
（真受益的是手写模板，但没有入口）。

### Univer 结论：可以用，但它只是画布

`preset-sheets-core` 已含：单元格编辑、选区、复制粘贴、撤销重做、合并单元格、
单元格样式、公式、查找替换。**不含**：排序/筛选/条件格式/打印/xlsx 导入导出（都不需要）。
主格树/递归扩展/层次坐标它一个都没有 —— 那正是 Rust 引擎的活。
（与 `类Excel报表开源方案调研.html` 的结论一致：Univer 是网格 UI 组件，不是报表引擎。）

三个必须绕开的点：
1. **`=` 会撞公式引擎**：core preset 自带公式引擎，任何 `=` 开头被当 Excel 公式，
   我们的 `D3[A3:+0].sum()` 会显示 `#NAME?` → 绑定改用 `{{ds1.city}}`。
2. **元数据不能塞进格子文本**：`row_parent` 等 18 个字段必须按 pos 存 sidecar。
3. **两个 Univer 实例会抢全局** → 自由模板与预览**共用一个容器**，按 mode 互斥切换。

### 插删行列必须重映射位置引用（最容易漏的一类 bug）

`row_parent:"A3"`、`value_expr:"D3[B3:+0].sum()"` 都是**文本**。插一行表头不改它们
→ 整个模板静默错位。覆盖 7 个字段：row_parent / col_parent / col_after /
value_expr / expand_expr / row_test_expr / col_test_expr。
删除时**正好指向被删行的引用要清空**：留悬空引用会静默指向别处，比没有更危险。

正则 `(?<![A-Za-z0-9_.])([A-Z]{1,3})([1-9]\d{0,6})(?![A-Za-z0-9_.])` 的断言
**不能加 `[`** —— `D3[B3:+0]` 的 `B3` 前面就是 `[`，加了会漏掉括号里的引用。
这个 bug 是被用例抓出来的（`D3→D2` 了但 `B3` 没动）。
断言保住了：`ds1.city`、`items[0].amount`、`qty1` 都不匹配；`:+0` 偏移不动。

19 条新用例全绿（`node --experimental-strip-types`）。

## 报表定义文件：保存 JSON / 定义格式 / 打开即执行

把「做个报表」和「跑个报表」合成一个文件。三块一起做的：

### 格式（ReportDef，Rust store.rs + TS 镜像，mirror-check 已注册）

```json
{ "format":"openprint.report", "version":1, "id":"sales-by-region", "name":"...",
  "template":{...}, "sources":[{ "name":"ds1","engine":"sqlite","database":"...","table":"sales",
  "where":"region = ?","params":["华东"] }], "options":{...} }
```

两个关键取舍：
- **只存数据源「声明」，不存数据快照**：存快照会过期，且几万行塞进文件没法看。
- **options 存开关，不存算好的模板**：存开关才能在打开时改；存算好的模板就回不去了。
  代价是服务端要有 TS `withExportFormula`/`withExpandControl` 的等价实现
  （`store::apply_options`），两边语义必须一致，否则设计器里和服务端跑出来不一样。

### 服务端

路由：`GET /api/reports`、`PUT /api/reports/save`、`GET|DELETE /api/reports/:id`、
`POST /api/reports/:id/run`、`POST /api/reports/:id/xlsx`。
目录 = 配置文件同级 `reports/`。

- **id 白名单是安全边界**：id 直接拼文件名，只允许 `[A-Za-z0-9_-]{1,80}`，
  挡住 `../../etc/passwd`。已实测返回 404。
- 列表里坏文件显示为「（文件损坏）」但**不让整个列表挂掉**。
- `run` 支持 `{"params":{"ds1":["华南"]}}` 按数据集名覆盖参数 ——
  同一份文件换参数就是另一份结果。
- **传了参数却没写 WHERE** 底层报 `Got 1, needed 0`，看不懂；
  改成「请在筛选条件里写占位符（如 region = ?）再传参」。

### 设计器

顶部加了「报表文件」：名称 / id / 保存 / 打开 / 执行。
**打开一律进「自由模板」模式** —— 自由模板能表达任何模板（向导生成的也一样），
进去还能逐格改；反过来向导填不出手写的模板。
`buildRequest` 多返回 `rawTemplate` + `options`，保存时用这一对而不是后处理过的模板。

## 推送到 GitHub：SSH 必须走 443（这台机器的代理会劫持 22 端口）

**症状**：`ssh -T git@github.com` → `Connection closed by 198.18.0.84 port 22`。

**原因**：本机有透明代理（`HTTP_PROXY=http://127.0.0.1:62228`），
`github.com` 被解析到 `198.18.0.84`（198.18.0.0/15 是 fake-IP 段，不是 GitHub），
22 端口的 SSH 根本到不了。

**解法**：GitHub 在 `ssh.github.com:443` 上提供 SSH，`~/.ssh/config` 里改写：
```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  AddKeysToAgent yes
  UseKeychain yes
  IdentityFile ~/.ssh/id_ed25519
```
这样 `git@github.com:...` 形式的 remote 照常写，底层走 443。

全过程（下次照抄）：
```bash
ssh-keygen -t ed25519 -C "..." -N "" -f ~/.ssh/id_ed25519   # 无 passphrase
ssh-add --apple-use-keychain ~/.ssh/id_ed25519              # 存钥匙串
cat ~/.ssh/id_ed25519.pub                                    # 贴到 github.com/settings/ssh/new
ssh -T git@github.com                                        # 应回 Hi <user>!
git remote set-url origin git@github.com:flashtony2005/report.git
git push origin main
```
注意：`ssh-add -l` 报「no identities」时先 `eval "$(ssh-agent -s)"` 再
`ssh-add --apple-use-keychain`（`--apple-load-keychain` 在这机器上没生效）。

已完成：17 条提交（含 135MB PDF 资产）全部推送成功，35 秒。
origin 从 HTTPS 改为 SSH。

## 报表命令行上线：`--list-reports` / `--run-report`（commit 06ea2c8）

**动机**：报表定义是纯 JSON，本该能被 cron / 脚本直接跑。此前只有
「打开设计器点执行」一条路 —— 等于把报表锁死在 UI 里。

**形态**（命中任一子命令就不启 HTTP 服务，跑完即退）：

```bash
print-server --list-reports
print-server --run-report <id> [--param ds1=华东] [--params '{"ds1":["华东"]}'] [--out x.xlsx]
print-server --help
```

**分层是刻意的**：`main.rs` 的 `CliCommand::parse` 只切分 argv，
JSON 解析与校验交给 `report::parse_cli_params` / `merge_cli_param`。
好处是「什么算合法参数」只有一份实现，**命令行与 HTTP 接口不会走偏**。
`--params` 宽松收两种写法：`{"ds1":["华东"]}` 和 `{"ds1":"华东"}`。

**几个刻意的取舍（都不是随手写的）**：

- `--run-report --out a.xlsx`（少写 id）会把 `--out` 当 id 吞掉，最后报
  「找不到报表 --out」莫名其妙 → 提前拦（`id.starts_with('-')`）。
- `--param` / `--params` / `--out` **单独出现直接报错，不静默忽略**。
  静默忽略会让用户以为参数生效了，报表却按默认参数跑出来 ——
  这种「看起来成功」的错误最难查。
- 一个参数都没给 → `None`（不动定义里的默认参数），而不是 `Some(空)`。
  **「不改」和「清空」是两回事。**
- 退出码：`0` 成功 / `1` 执行失败 / `2` 用法错误（并打印 usage）。

**验证**（对 `reports/sales-by-region.json`，数据源指向 `/tmp/report-demo.db`）：
默认参数 → 华东 37,900；`--param ds1=华南` → 40,200；`--params 华北` → 38,300
（三个数与上一轮 HTTP 端点的结果完全一致）。
`--out` → 6110 字节，`file(1)` 认作 `Microsoft Excel 2007+`。
错误路径 6 例（报表不存在 / 少写 id / 参数没处挂 / 非法 JSON / 缺等号 / 子命令互斥）均给人话。
Rust 测试 **97 → 108**。

## 缺省父格规则 3 补完：addDefaultRowParents / addDefaultColParents（commit d055b85）

> 这一节**推翻**了本文前面「addDefaultRowParents（规则 3）：能实现，暂不做」的结论。
> 当时的理由是「真受益的是手写模板，目前没有手写入口」——自由模板上线后这个前提没了。

**先证明它有用，再动手。** 构造了一个能复现的错模板：

```
r1  地区        销售员                  小计
r2  {{region}}  {{salesman, merge_down=1}}  {{city}}
r3                                      {{amount, sum}}
```

B2 向下合并一格，把 A2 的展开范围从「自己那一行」撑到第 3 行。第 3 行的 C3
扫不到任何父格（本行 col0/col1 全空）→ 挂根 → 只渲染一次：

```
修复前：华东 | 张三 | 上海         修复后：华东 | 张三 | 上海
        华南 | 孙七 | 广州                 |  | 21,900   ← 华东 12,000+9,900
         |  | 37,200  ← 凭空冒出的总计     华南 | 孙七 | 广州
                                           |  | 15,300
```

**关键结论：规则 3 的触发条件是「展开范围被撑出自己那一行之外」**，
而范围是沿子格树自底向上算的，子格行跨度（`merge_down+1`）才会把它撑开。
叶子展开格（无子格）的范围 = 自己那几行，而规则 3 明确排除与本格跨度重叠的格子
→ **此时它是彻底的 no-op**。所以常见模板不受影响，只有「子格跨行合并」才触发。

### 做法：父格解析抽成模板期 pre-pass

规则 3 要 `rowExpandOffset`/`rowExpandSpan`，那是**沿子格树自底向上算**出来的、
不是模板字段，且必须在建实例前定下来。原先边建实例边推断，拿不到全局视图。
拆成：**Pass0 解析父格 → Pass0' 算展开范围 + 认领 → Pass1 建实例**。

抽取本身**语义等价**（先单独验证过：109 测试全绿、零告警、行为不变），因为解析只读
模板与**行优先序更早**的格子（向左扫同行前列 / 向上扫同列前行 / 兜底读本行最左、第一行同列）。

### 三个踩到的点（都会再犯，记牢）

1. **门槛是 `rowParent == null`，不是「没有 Ref」**。上游 `A0` 是 `CellPosition.NONE`
   ——**非 null 的哨兵值**，所以显式 `A0` **不受**规则 3 影响。
   用 `matches!(.., Some(ParentDecl::Unset))` 精确表达。
   **并且验证了测试不是白写的**：临时把 `ExplicitNone` 也放进门槛 → 测试立刻失败。
2. **`col_after` 的格子必须放过（列轴）**。`col_after` 是我们对上游
   `colExtendForSibling` 的等价物。收编后该格变成列展开格的子格、被放进它的列区间
   **里面**，与「排在区间之后」直接打架 → 症状是「金额合计」表头跟着月份重复一遍。
   这个回归是 `cross_tab_two_metrics_with_totals` 抓到的（表头 5 列退化成 4 列）。
3. **`ranges` 只需算一次**，不必像上游那样边认领边惰性算：认领只作用在**顶层**格上，
   而顶层格不会成为别人的子格，所以后面的格子不可能看到前面的认领结果。

另加防栈保护：显式父格可指向任意格子（甚至成环），上游抛异常，
我们只求别把栈打穿，到 `MAX_LAYOUT_DEPTH` 退回叶子形态。

## 环境坑（第三次踩，务必记住）

1. **BSD grep 的 BRE 不支持 `\|`**。我用
   `grep -n "merge_down\|merge_across\|merge_to_end"` 查合并字段，**返回空**，
   一度以为字段不存在——实际在 `grid-report.ts:123-128`。
   和 `ts-check.sh` 注释里记的是同一个坑，第三次了。
2. **zsh 不对未加引号的 `$VAR` 做词分割**。`FILES=$(find ...); tsc $FILES`
   会把整串当成**一个**参数，tsc 直接打印 help。用 `xargs -0` 或改成数组。
   （`ts-check.sh` 是 `#!/bin/sh`，所以它里面没事。）
3. **`--noResolve` 下给自定义组件加 `key={...}` 是误报**：
   解析不到 React 类型，`key` 不会被特殊对待 → `TS2322 Property 'key' does not
   exist on type ...`。改用 `useEffect(..., [pos])` 达到同样的「换格重置」效果。

## 设计器画布重建：一个真实的既存问题

原先 Univer 的 effect 依赖整个 `grid`，于是：画布上改一格 → `SheetValueChanged`
→ `setGrid` → `dispose()` 掉整个 Univer 再重建。**内容本来就在画布上**，这一趟
纯属白拆，还丢掉选区与滚动位置。

改成 `canvasKey` 令牌：结构变更（增删行列 / 合并 / 载入模板）**和属性面板改动**
才 bump；画布自身的改动不 bump。

**属性面板必须 bump 这点最容易漏**：我一开始按「结构 vs 内容」切，差点做错。
实际去读 `gridToWorkbookData`（`grid-report.ts:1260`）才发现，画布显示的文字来自
`formatCellText(cell)`，所以改字段 / 聚合 / 值表达式**同样**改变显示内容——
面板改动不重建就是脏的。**结论：判据不是「结构 vs 内容」，而是「改动是不是
画布自己产生的」。** 这个边界写进代码注释了。

UI 部分**只做了类型检查与代码走查**：本环境跑不起 vite（无 node_modules），
没能在浏览器里真点一遍。这点在提交信息里也写明了。

# 表达式缓存：实测后决定**不做**（backlog 该项关闭）

提交 `96e1e9b`。backlog 里挂着「表达式缓存 / 增量重算（纯性能）」。
性能优化不该凭手感做，所以先写基准量一遍再决定。**结论：不做。**

## 基准位置与跑法

`print-server/src/report/engine.rs` 末尾 `mod scale`（4 个 `#[ignore]`）：

```bash
cargo test --release -- --ignored --nocapture --test-threads=1 bench_
```

**必须 `--release` 且 `--test-threads=1`**：debug 的常数因子会掩盖真实曲线，
而并行跑会让几个基准互相抢 CPU，数字直接失真（第一次就是这么被坑的，
每实例耗时虚高）。

## 关键实验：把表达式成本单独摘出来

只测「总耗时随规模怎么涨」答不了这个问题——得知道总耗时里**表达式占多少**。
办法：同一批数据、**完全相同的实例数**，只把计算列从 `value_expr` 换成普通
字段列，两者之差就是表达式求值的真实成本。

| 行数 | 无表达式 | 有表达式 | 表达式成本 | 占总量 |
|---|---|---|---|---|
| 1000 | 2.5ms | 3.1ms | 0.6ms | 19.3% |
| 4000 | 17.3ms | 19.3ms | 1.9ms | 10.1% |
| 16000 | 164.8ms | 174.2ms | **9.4ms** | **5.4%** |

## 结论

- 表达式求值只占 **5.4%**，而且**占比随规模下降**。缓存能省的上限就是这 5.4%。
- `expr::parse` 是每次求值的**常量**开销，不是超线性的来源——缓存换不来任何
  算法级改善。
- **不做。** 该项关闭，别再凭「感觉这里会慢」把它捡回来。

## 顺带查明的：真正的大头在哪

「展开 + 布局」这条**不含表达式**的路径，在 16000 行里占 164.8ms（约 n^1.6）。
本次不解决，但基准留在库里了：将来真有人报大报表慢，**从这里接着查，
别再去翻表达式**。

另外记一笔（**不在本次结论里**，只是读代码时看到的）：`resolve_raw` 每次调用都
`.cloned()` 一份 `Vec<usize>`（`engine.rs` 约 1651 行起），`resolve` 之后又
`filter` 出一个新 Vec —— 每次解析两次分配。哪天真要动布局路径的性能，这是个候选点。

## 顺带补的正确性测试

`cross_tab_totals_are_consistent_at_scale`（40×20 = 800 个数值格）。
其余测试的数据集都很小（2×2 那种），**行/列下标串了之类的问题在小数据上经常
刚好抵消掉**，压到 800 格才藏不住。同时守住「所有行合计之和 == 总计」。
已验证不是空跑：期望总计故意 +1 → 立刻报「总计 320401 未出现在网格里」。
