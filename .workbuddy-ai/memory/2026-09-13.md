## CUPS 打印机枚举（macOS / Linux）—— 补齐「能打却列不出来」的半套

`print-server/src/printers.rs` 原先非 Windows 上 `list_printers()` 直接返回空列表，
打印链路（`print_job.rs`）已经走 CUPS `lp`，却列不出队列。现已补上：

- 两路实现共用 `PrinterInfo`，靠 `cfg` 切换：
  队列 `EnumPrintersW` L2 / `lpstat -a`；默认 `GetDefaultPrinterW` / `lpstat -d`；
  状态 `PRINTER_INFO_2W.Status` / `lpstat -l -p`；描述 `pDriverName` / `Description:` 续行（无则回落 `"cups"`）；
  能力 DevMode+`DC_BINNAMES` / `lpoptions -p NAME -l`。
- `classify_kind()` 解除 cfg 门控，两路共用。
- 解析函数全是 `&str -> T` 纯函数（`parse_lpstat_a` / `_d` / `_l_p` / `parse_lpoptions_l`），
  命令执行只在 `run_cups()` 一处。本机没配队列 → 7 个单测喂合成输出。

踩到的坑（写下来是因为都会重复遇到）：
1. **`run_cups` 不能看退出码**：没配队列时 `lpstat -a` 退出 1 且提示打到 **stderr**，
   那是「没有打印机」不是失败。看退出码会误判。
2. **`LC_ALL=C` 压不住本地化**：这台机器上 `LC_ALL=C lpstat -a` 仍输出中文「未添加目的位置。」。
   解析必须走白名单（只认 `accepting` / `rejecting` 关键字），不能依赖英文文案。
3. **「支持双面/彩色」看选项里有没有该值，不看默认选了哪个**：`lpoptions -l` 列出的就是全部合法值，
   `Duplex: *None DuplexNoTumble DuplexTumble` 即使默认 `None` 也算支持；只有 `*None` 才算不支持。
   `*` 前缀只用来定 `defaultDpi`。
4. 纸盒名保留原始大小写给用户看；用于比较的 `bare()` 才转小写（第一版复用 `bare()` 全小写化了）。

端到端验证手法（本机无真实队列，值得复用）：往 `PATH` 前面塞假的 `lpstat` / `lpoptions`
（吐一台彩色双面带 4 纸盒的默认机 + 一台暂停的单色机），起服务打 `/printers` 看字段对不对。

## 设计器暴露展开控制（min / max / keepEmpty）—— 按层级分别作用

引擎早有这三个字段、也有 `expand_count_limits` 单测，纯 UI 缺口。补的时候发现
**语义必须定死**：分组模板里每个分组格都带 `expand_type:'r'` 且 `row_parent` 链式嵌套，
一律打在所有行展开格上会逐级相乘（2 级 + 最少 5 行 = 至少 25 行）。用户确认的规则：

| 属性 | 打在哪 | 理由 |
|---|---|---|
| `expandMinCount` | 最内层行展开格 | 「每组至少 N 行」是明细级；打外层变「至少 N 个分组」 |
| `expandMaxCount` | 最外层行展开格 | 「TOP N」是分组数；打内层变「每组只显示 N 行」 |
| `keepExpandEmpty` | 所有行展开格 | 逐级保留，空报表才有空行撑着表头 |

只作用于行展开格（`expand_type === 'r'`），列展开格不管。

关键点：`cell()` **不写 `pos`**（服务端按行列下标推断），但构造器写 `row_parent` 时用的是
`cellPos()`。所以 `withExpandControl()` 得用同一个 `cellPos()` 把位置补算回来，
再比对「谁被别的行展开格认作父格」→ 最外层 = `row_parent` 不在行展开格集合里；
最内层 = 自己的 pos 没被别的行展开格认作父格。

## 缺省父格：补上「跟随左邻父格」+「最左格/第一行兜底」，并修正 A0（测试 83 → 92）

上游源码在 `nop-report/nop-report-core/src/main/java/io/nop/report/core/build/XptModelInitializer.java`
（注意是 `build/` 不是 `model/`）。对照它逐行实现，两个光看文档会做错的点：

1. **「跟随」跟的是解析后的父格，不只是显式声明的**——上游 `initParentChildren` 会把
   推断结果**回写**进 model（`if (xptModel.getRowParent() == null) setRowParent(...)`）。
   所以得按 (r,c) 缓存已解析结果（新增 `Resolved = BTreeMap<(usize,usize), ParentDecl>`），
   扫描时读它。
2. **`A0` 之前是错的**：`filter(|p| !is_root_ref(p)).or_else(default_...)` 把 A0 当「没写」
   → 落进缺省推断，与注释和上游（`if (rowParent == NONE) return null`）都不符。
   改成 `ParentDecl` 三态 `{Ref, ExplicitNone, Unset}`。

「最左格兜底」照抄了但**在我们的行序下基本不可达**：扫描一定会检查到 col 0，
若它有父格第 1 条就已跟随；兜底读同一个格子。只有上游合并格 `getRealCell()` 的差异才会走到。

### addDefaultRowParents（规则 3）：能实现，暂不做

需要 `rowExpandOffset`/`rowExpandSpan`，而它是**沿 row 子格树自底向上算出来的**
（`collectRowChild` L439-471），不是模板字段；且要在 `initParentChildren` 之后的第二遍跑。
即必须把父格解析从「边建实例边算」抽成模板 pre-pass（Pass0 解析 / Pass1 建树算 span /
Pass2 addDefaultRowParents / Pass3 建实例）。

不做的理由：三个构造器给小计合计格都**显式**写了 `row_parent`，而规则 3 门槛是
`cm.getRowParent() == null`（声明为空）→ 不触发；且顶层扩展格 span=1、范围够不着小计行；
再者它会覆盖已推断的父格，有回归风险。真受益的是手写模板，目前没有手写入口。

## 自由模板（类 Excel 逐格设计）—— 补上「没有手写入口」这个洞（commit `2bcfad9`）

之前 `row_parent` / `col_parent` / `expand_type` / `value_expr` 在 designer-react 里
**一次都没出现过**：只有 4 个向导（样例/分组/交叉/画布）机器拼模板，18 个 CellModel
字段只能靠手写 JSON 触达。这也是之前判断 `addDefaultRowParents`「暂不做」的理由之一
（真受益的是手写模板，但没有入口）。

### Univer 结论：可以用，但它只是画布

`preset-sheets-core` 已含：单元格编辑、选区、复制粘贴、撤销重做、合并单元格、
单元格样式、公式、查找替换。**不含**：排序/筛选/条件格式/打印/xlsx 导入导出（都不需要）。
主格树/递归扩展/层次坐标它一个都没有 —— 那正是 Rust 引擎的活。
（与 `类Excel报表开源方案调研.html` 的结论一致：Univer 是网格 UI 组件，不是报表引擎。）

三个必须绕开的点：
1. **`=` 会撞公式引擎**：core preset 自带公式引擎，任何 `=` 开头被当 Excel 公式，
   我们的 `D3[A3:+0].sum()` 会显示 `#NAME?` → 绑定改用 `{{ds1.city}}`。
2. **元数据不能塞进格子文本**：`row_parent` 等 18 个字段必须按 pos 存 sidecar。
3. **两个 Univer 实例会抢全局** → 自由模板与预览**共用一个容器**，按 mode 互斥切换。

### 插删行列必须重映射位置引用（最容易漏的一类 bug）

`row_parent:"A3"`、`value_expr:"D3[B3:+0].sum()"` 都是**文本**。插一行表头不改它们
→ 整个模板静默错位。覆盖 7 个字段：row_parent / col_parent / col_after /
value_expr / expand_expr / row_test_expr / col_test_expr。
删除时**正好指向被删行的引用要清空**：留悬空引用会静默指向别处，比没有更危险。

正则 `(?<![A-Za-z0-9_.])([A-Z]{1,3})([1-9]\d{0,6})(?![A-Za-z0-9_.])` 的断言
**不能加 `[`** —— `D3[B3:+0]` 的 `B3` 前面就是 `[`，加了会漏掉括号里的引用。
这个 bug 是被用例抓出来的（`D3→D2` 了但 `B3` 没动）。
断言保住了：`ds1.city`、`items[0].amount`、`qty1` 都不匹配；`:+0` 偏移不动。

### 验证

19 条新用例全绿（`node --experimental-strip-types`）。
**端到端**：用新 API 从零搭出「缺省父格·跟随」模板（A1 region 展开 / B2 认 A1 /
C2 不写主格靠跟随）→ 渲染得 37,900 / 40,200 / 38,300 且**无** 116,400，
与之前手写 JSON 完全等价。ts-check / mirror-check / report-smoke 均通过。

### 从 npm tarball 解 .d.ts 核对 Univer API（commit `c121a00`，可复用手法）

没有 node_modules 时**照样能核对第三方 API**：
```bash

https://registry.npmjs.org/<pkg>  → versions[<ver>].dist.tarball
# 2. 解开只要 .d.ts
tarfile 里筛 n.endswith('.d.ts')
```
比读文档可靠（文档可能跨版本），比 GitHub 可靠（**presets 系列不在
dream-num/univer 的 v0.25.1 tag 里**，只在 npm 上；那个 tag 下 packages/ 是老的
61 个包布局，没有 preset-*）。

核对结果（0.25.1，下次直接用）：
- `createUniver(opts) => { univer, univerAPI }`（presets/lib/types/umd.d.ts）
- `univerAPI.addEvent(univerAPI.Event.SelectionChanged, p => p.selections: IRange[])` — sheets-ui facade
- `univerAPI.addEvent(univerAPI.Event.SheetValueChanged, p => p.effectedRanges: FRange[])` — sheets facade
- `FRange.getRow() / getColumn() / getValue()`
- `IRange = { startRow, endRow, startColumn, endColumn }`（@univerjs/protocol）
- **`FEventName` 是 class，靠 `static extend(mixin)` 运行时合并**，不是 TS 声明合并；

## 报表定义文件：保存 JSON / 定义格式 / 打开即执行

把「做个报表」和「跑个报表」合成一个文件。三块一起做的：

### 格式（ReportDef，Rust store.rs + TS 镜像，mirror-check 已注册）

```json
{ "format":"openprint.report", "version":1, "id":"sales-by-region", "name":"...",
  "template":{...}, "sources":[{ "name":"ds1","engine":"sqlite","database":"...","table":"sales",
  "where":"region = ?","params":["华东"] }], "options":{...} }
```

两个关键取舍：
- **只存数据源「声明」，不存数据快照**：存快照会过期，且几万行塞进文件没法看。
- **options 存开关，不存算好的模板**：存开关才能在打开时改；存算好的模板就回不去了。
  代价是服务端要有 TS `withExportFormula`/`withExpandControl` 的等价实现
  （`store::apply_options`），两边语义必须一致，否则设计器里和服务端跑出来不一样。

### 服务端

路由：`GET /api/reports`、`PUT /api/reports/save`、`GET|DELETE /api/reports/:id`、
`POST /api/reports/:id/run`、`POST /api/reports/:id/xlsx`。
目录 = 配置文件同级 `reports/`。

- **id 白名单是安全边界**：id 直接拼文件名，只允许 `[A-Za-z0-9_-]{1,80}`，
  挡住 `../../etc/passwd`。已实测返回 404。
- 列表里坏文件显示为「（文件损坏）」但**不让整个列表挂掉**。
- `run` 支持 `{"params":{"ds1":["华南"]}}` 按数据集名覆盖参数 ——
  同一份文件换参数就是另一份结果。
- **传了参数却没写 WHERE** 底层报 `Got 1, needed 0`，看不懂；
  改成「请在筛选条件里写占位符（如 region = ?）再传参」。

### 设计器

顶部加了「报表文件」：名称 / id / 保存 / 打开 / 执行。
**打开一律进「自由模板」模式** —— 自由模板能表达任何模板（向导生成的也一样），
进去还能逐格改；反过来向导填不出手写的模板。
`buildRequest` 多返回 `rawTemplate` + `options`，保存时用这一对而不是后处理过的模板。

### 验证（scripts/report-store-test.html）

造了 /tmp/report-demo.db（10 行 sales）跑通全链路：
保存 → 清空表单 → 执行 → 得 11 行华东（4ms，用文件里存的默认参数）；
再传 `{"ds1":["华南"]}` → 9 行华南；打开 → 表单完整回填；导出 xlsx 6136B；
路径穿越 404；删除后列表归零。Rust 92 → 97 测试全绿。

### 踩到的坑

1. **测试临时目录撞名**：`now_rfc3339()` 只到秒，cargo test 并行 → 多个用例拿到
   同一目录互相看见对方的文件（列表数出 4 个而不是 2 个）。
   修：目录名加 `process::id()` + 原子计数。
2. `save()` 会把 version 归一化成当前版本（有意为之：只按自己认识的版本写），
   所以「版本过高」的用例必须**直接写文件**，不能走 save。
3. `store.rs` 里重复实现了 `pos_of` —— model.rs 早就有 `cell_pos`，删掉改用。

### 已 gitignore

`print-server/reports/` —— 用户数据，含本地库路径、可能含连接信息，
而 origin 是公开仓库 `flashtony2005/report`。

**没碰 / 还差**：

- 前端 `npm install` 后才能跑的 `npm run type-check` / `npm run test`（沙箱装不出来）。
- 预览区域还是不分页的全表展示（设计上展示布局前结果，有意为之）。
- `expandInplaceCount` / 表达式缓存增量重算。

### 这次会话摸出的另一个沙箱怪癖：端口被旧的二进制占着

`cargo test` 不会刷 `target/debug/print-server`。上一轮验证 CUPS 后没 `cargo build`
直接重启 → 18888 还在吐旧的 `/printers` 输出。重启前的健康检查**看着没问题**
（200 + 正确 JSON），但功能是旧的。`cargo build` 后重启立刻对。
