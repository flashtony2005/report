## 3. 分页不切断合并格（组内不跨页）（已完成）

**关键洞察：主格展开出来就是合并格** —— 一个地区跨几行，它的格 rowspan 就是几。
所以「不许在合并格中间切页」== 「组内不跨页」，不用引入润乾 9 类带区模型，
前后端模型都不用动。纯函数 `merge_blocked_boundaries()`。

落点被合并格跨过时**往两边找最近的安全边界**（先退后进）；剩下的够放一页时不再切。
样例实测：华东 8 / 华南 6 / 华北 6，切页按组对齐 8/6/7（旧行为是 10/10/1）。

**被自己的用例抓到一个真 bug**：往后找安全边界时 `blocked[head_n + j]` 会越界 ——
表尾为 0 时最后一行数据就是全表末行，它后面没有边界。已修并留用例。

## 票据指令 esc / tsc / zpl（commit 4eca6d2）

**输入契约**：前端 `openprint/src/core/print-client/raw-sanitize.ts` 净化过的
画布 JSON —— 颜色 / 字体样式 / 设计器元数据已裁掉，翻译层不能假设 `fill` 一定在。
形状 `{ version, document: { page, sections: [{ components }] }, data? }`，
几何单位跟 `page.unit`，原点 = 所属 Section 左上角，多节纵向堆叠。

**三种格式各自的硬约束**（都是踩出来的，不是查文档抄的）：
- ESC/POS **没有 y 坐标**，只有行：`ESC 3 24` 钉行距 + `ESC d n` 推进 +
  `ESC $ nL nH` 设绝对 x。行距必须显式钉，否则推进多少点由机型默认值定。
- ESC/POS 中文必须 **GBK**（票据机内置中文字库），编不出来的字符要报警告。
- TSPL / ZPL 有真 x/y，但**都没有对齐参数** —— 居中 / 右对齐只能按估宽自己挪 x，
  不挪就静默变靠左。
- ZPL 的 `^` / `~` 是控制字符，内容里出现必须走 `^FH` 十六进制转义；反过来
  没有这两个字符时不该无脑加 `^FH`（会把内容里的 `_` 卷进十六进制解析）。
- 旋转只认 90 的倍数，别的角度报警告并 snap。
- **203dpi 是 7.9921 点/mm，不是整 8**：80mm 是 639 点不是 640。当成 8 会每
  127mm 差 1 点。

**探针抓到的真 bug（值得记）**：`cur_row` 第一版写成 `cur_row += 1`，表格第一行
两格（品名 / 数量）让 cur_row 变成 `row + 2`，整个方框上移一行，且每多一个同行
图元就多错一行。修成 `max(cur_row, row + 1)`。

→ **教训：原来的单测只数 `ESC d` 的「次数」，抓不住「累计位置偏了」。**
位置类断言要断**整条序列**（这次断 `[1,2,1,2,4,8,3,7]`），只数次数等于没测。
这和「只断言 last()」是同一类错误。

**另一个教训（补上了老坑）**：`binding` 是**数据路径**（`customer.name`），
`value` 是**字面量**，`contentType` 缺省时的回退顺序是 **expression > binding > value**。
我第一版写成 value 优先，结果是「把 customer.name 这几个字原样印在小票上」——
看着"有内容"，不报错。前端 `resolveTextValue` 是真理源。

**翻不了的必须留痕**：image / chart / math / signature / richtext / zone /
labelgrid 一律不翻但进 `Ticket::warnings`（指名控件 id + 坐标），`/print` 回给
调用方并置 `ok=false`。数据行驱动的表格也只留痕（`data` 运行期无形状约束）。

**已知没做**：Windows 的 RAW 直发（要 winspool StartDocPrinter(RAW)，本机
macOS 编译验证不了，不写没验过的 unsafe）。非 Windows 走 `lp -o raw` ——
不能过 CUPS 过滤器，会被当文本重排。

**本服务 `service_error` 是 HTTP 200 + `{ok:false, message}`，不是 5xx** ——
探针判据要落在 ok / message 上，别只看状态码。（xlsx 那条路是 500，别混。）

### 几何全在服务端算（不依赖模板写死尺寸）

按图 DPI 折显示尺寸 → 缩到不超格宽且**不放大** → 撑开所在列宽 / 行高。

- **DPI 必须折**：203dpi 的 120×80 图，Excel 按物理尺寸只显示约 57×38px。
  不折就是 2.1 倍大，而**设计器里看着是好的**（设计器用像素）。
- 列宽上限 60 字符、行高上限 **409.5 磅**（Excel 的硬上限，超了**直接拒开文件**）。
- 合并格按**整段**算可用空间。

**Excel 单位换算（都在 xlsx.rs 顶部，别凭记忆写）**：
`px = round(chars×7) + 5`；反解是 `chars = ceil((px − 5.5) / 7)`（**ceil 不是 round**）；
`px = round(pts×4/3)`；XML 里 `width = floor(px×256/7)/256`，所以**反解是
`px = round(width_xml × 7)`，不带 +5**（`+5` 那个 0.7109375 的小数就是这么来的，
第一版探针算错了）。

### 探针抓到的两个真 bug（单测都没抓住）

## ODBC 引擎（缺口 4，最后一项；八项全清）

用户拍板：**装依赖 + feature-gated + 真机验证**（先问的，没自己往用户机器上装东西）。

### 做成可选 feature，不是硬依赖

`odbc-api = { version = "29.0.0", default-features = false, features = ["odbc_version_3_80"], optional = true }`
+ `[features] odbc = ["dep:odbc-api"]`。

- `default-features = false` 是因为默认带的 **`prompt`** 会拖进 `winit`（GUI 依赖），
  headless 服务不要。
- **不需要额外链接器环境变量**：odbc-sys 构建脚本自己问 `brew --prefix` 找 libodbc。
- 本机装了 `brew install unixodbc sqliteodbc`（unixodbc 2.3.14 / sqliteodbc 0.99991）。

### 「没编进这个构建」≠「暂未实现」（这条最容易被写歪）

默认构建下用到 odbc 必须报「**没有编进这个构建**」+ 重编命令。报成「暂未实现」
听起来像永远没有，用户会去换驱动 / 提需求，其实只要重编一次。
→ `odbc_not_built_in()`（`db.rs`，`#[cfg(not(feature = "odbc"))]`）。

**连带发现**：`admin.html` 原来把「暂未实现」**写死**在配置块和连接列表标签里。
feature 一开，那两处就变成**页面在说谎**。改成读 `/health.odbc`（= `cfg!(feature="odbc")`）
**三态**显示：已编入 / 未编入 / 读不到服务状态。第三态是刻意的 ——
**读不到 ≠ 没编入**，混为一谈就是换了个方向的谎。

### 只读保证弱一档（照实写了，别当成同级）

| 引擎 | 手段 | 级别 |
| --- | --- | --- |
| sqlite | `SQLITE_OPEN_READ_ONLY` | 文件级 |
| postgres | `SET SESSION ... READ ONLY` | 会话级 |
| **odbc** | 只拼 `SELECT`/`COUNT` + `where` 设防 | **语句级** |

做不到会话级是因为**够不到裸连接 handle**：`odbc-api 29` 没暴露 `SQL_ATTR_ACCESS_MODE`，
而 `Connection::into_handle(self)` 是**消费 self** 的、`Environment::allocate_connection`
是**私有**的 —— 想设连接属性就得放弃查询 API。
同一个原因让 `SQLGetInfo(SQL_IDENTIFIER_QUOTE_CHAR)` 也拿不到 → 引号符**写死 ANSI 双引号**。
写死可接受：引号猜错得到**明确的 SQL 语法错**，不是静默算错数据。
残余风险（驱动允许表达式里调有副作用函数）写进了模块头 + README，并强调**配只读账号**。

### odbc-api 29 的编译器事实（省下次的时间）

- **两个 `Connection`**：高层 `connection::Connection<'c>`（不透明）vs 裸句柄
  `handles::connection::Connection<'c>`。`as_sys` / `set_autocommit` 只在**裸句柄**上。
- `PrimaryKeysRow` 字段是 **`column`**，不是 `column_name`。
- **`bool` 没实现 `Pod`** → `Nullable<bool>` 编不过；用 `Nullable::<u8>` 判 `!= 0`。
- `col_data_type` 是 **`ResultSetMetadata` trait 的方法**，trait 要在作用域里。
- 没有 `VarArrayLen` → 是 `VarCharArray<const LENGTH: usize>`，泛型写 `fn text_of<const L: usize>`。
- 同步 API → 全包 `spawn_blocking`。

### 目录函数的名字参数是「搜索模式」（会静默多匹配）

`SQLTables`/`SQLColumns` 的表名 / schema 参数：`_` 匹配任意单字符、`%` 任意串、`\` 转义。
不转义的话 `user_name` **连 `userXname` 一起匹配出来，而且不报错** ——
表名带下划线的到处都是，几乎必然踩到。探针里专门放 `userXname` 诱饵表守着。

### 探针自己踩的坑（都不是产品 bug）

- **沙箱删除配额是「按轮累计」的**（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，>50 后每次删除要人工确认）。
  故障注入要连跑十几次探针 → 用 `shutil.rmtree` 清理会在第 N 次挂掉，**报错长得像探针自己坏了**
  （差点误判成「未注入时探针就是红的」）。→ 探针改成**一个文件都不删**：
  测试库 `DROP TABLE IF EXISTS` 再建，ini / 配置覆盖写。
- **注入明细行要挑**：探针汇总行「✗ N 条断言失败：」在**最后**，取 `bad[0]` 会拿到无关内容。
- **jsdom 里 `body.textContent` 把 `<script>` 源码也算进去** → 源码注释里的「暂未实现」
  被当成页面上的字，三条断言全是**假红**。判据：查「页面上有没有某个词」要
  `cloneNode` 后先 `querySelectorAll('script, style').remove()`。
- **ESM 裸包解析按脚本自己的位置**找 node_modules，跟 cwd 无关 → 脚本在 `scripts/` 而
  jsdom 在 `designer-react/node_modules`，必须 `createRequire(join(ROOT,'designer-react/package.json'))`。
- **两个 `Edit` 打同一个文件会竞态**（今天又踩一次，`db.rs` 的 `resolve_target` 那处被静默丢掉）。
  靠「`usable_as_default` 报 unused」才发现。→ 同一个文件的多个改动**一条一条发**。
- 故障注入脚本早期版本在 `print-server/src/` 留过 `.inject-backup`（后来改成内存还原没删干净）。
  已加进 `.gitignore` 兜底。
