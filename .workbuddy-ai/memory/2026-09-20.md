## 1. MySQL 不再静默降级成 sqlite（已完成）

`norm_engine` 对未知引擎一律回落 sqlite，`ServerConfig::load()` **又不调 `validate()`**
（只有保存/试连才调），所以手改配置写 `engine: "mysql"` 是真能踩到的：
报「sqlite 文件不存在」，看着像路径错了，其实是引擎不支持。

新增 `unsupported_engine_name()`（mysql/mariadb/mssql/sqlserver/oracle），
在 `conn_to_target` / `finish_engine` / 试连三处拦截。
故障注入后用例正好红在 `Sqlite("definitely-not-here.db")` —— 就是那个静默降级。

## 3. 分页不切断合并格（组内不跨页）（已完成）

**关键洞察：主格展开出来就是合并格** —— 一个地区跨几行，它的格 rowspan 就是几。
所以「不许在合并格中间切页」== 「组内不跨页」，不用引入润乾 9 类带区模型，
前后端模型都不用动。纯函数 `merge_blocked_boundaries()`。

落点被合并格跨过时**往两边找最近的安全边界**（先退后进）；剩下的够放一页时不再切。
样例实测：华东 8 / 华南 6 / 华北 6，切页按组对齐 8/6/7（旧行为是 10/10/1）。

**被自己的用例抓到一个真 bug**：往后找安全边界时 `blocked[head_n + j]` 会越界 ——
表尾为 0 时最后一行数据就是全表末行，它后面没有边界。已修并留用例。

## 5. 报表参数 / 查询表单（已完成）

原来只有 `RunRequest.params`（数据集名 → 位置参数数组）那条例底层通道，
前端没法据此画表单。新增 `ReportDef.params: Vec<ReportParam>`
（name/label/kind/default/required/options）+ 运行请求 `values`。

两个纯函数 `resolve_params()` / `bind_params()`。绑定规则：数据源 params 里
**整体等于** `"$name"` 的字符串才换（不认「包含 $」—— 会把真想写进 SQL 的 $ 换掉）。

**探针踩出一个真问题**：未知参数检查原本放在必填检查之后，于是 typo 被报成
「region 必填」，把人往错的方向带。改成先查未知参数，现在报
「未知参数「regoin」：本报表声明的参数是 [region]」。
教训：**报错顺序也是正确性的一部分** —— 先报离用户真实错误最近的那条。

真机探针（sqlite + /api/reports/:id/run）：传值只出该地区、默认值生效、
必填缺失与 typo 各自报对人话。Rust 221 passed。

## 票据指令 esc / tsc / zpl（commit 4eca6d2）

补 `print_job.rs` 那句「画布 JSON → 票据指令翻译（待实现）」。新增
`print-server/src/ticket/{mod,esc,tspl,zpl}.rs` + 真机探针
`scripts/verify-ticket-print.py`。Rust 单测 221 → 280。

**输入契约**：前端 `openprint/src/core/print-client/raw-sanitize.ts` 净化过的
画布 JSON —— 颜色 / 字体样式 / 设计器元数据已裁掉，翻译层不能假设 `fill` 一定在。
形状 `{ version, document: { page, sections: [{ components }] }, data? }`，
几何单位跟 `page.unit`，原点 = 所属 Section 左上角，多节纵向堆叠。

**三种格式各自的硬约束**（都是踩出来的，不是查文档抄的）：
- ESC/POS **没有 y 坐标**，只有行：`ESC 3 24` 钉行距 + `ESC d n` 推进 +
  `ESC $ nL nH` 设绝对 x。行距必须显式钉，否则推进多少点由机型默认值定。
- ESC/POS 中文必须 **GBK**（票据机内置中文字库），编不出来的字符要报警告。
- TSPL / ZPL 有真 x/y，但**都没有对齐参数** —— 居中 / 右对齐只能按估宽自己挪 x，
  不挪就静默变靠左。
- ZPL 的 `^` / `~` 是控制字符，内容里出现必须走 `^FH` 十六进制转义；反过来
  没有这两个字符时不该无脑加 `^FH`（会把内容里的 `_` 卷进十六进制解析）。
- 旋转只认 90 的倍数，别的角度报警告并 snap。
- **203dpi 是 7.9921 点/mm，不是整 8**：80mm 是 639 点不是 640。当成 8 会每
  127mm 差 1 点。

**探针抓到的真 bug（值得记）**：`cur_row` 第一版写成 `cur_row += 1`，表格第一行
两格（品名 / 数量）让 cur_row 变成 `row + 2`，整个方框上移一行，且每多一个同行
图元就多错一行。修成 `max(cur_row, row + 1)`。

→ **教训：原来的单测只数 `ESC d` 的「次数」，抓不住「累计位置偏了」。**
位置类断言要断**整条序列**（这次断 `[1,2,1,2,4,8,3,7]`），只数次数等于没测。
这和「只断言 last()」是同一类错误。

**另一个教训（补上了老坑）**：`binding` 是**数据路径**（`customer.name`），
`value` 是**字面量**，`contentType` 缺省时的回退顺序是 **expression > binding > value**。
我第一版写成 value 优先，结果是「把 customer.name 这几个字原样印在小票上」——
看着"有内容"，不报错。前端 `resolveTextValue` 是真理源。

**翻不了的必须留痕**：image / chart / math / signature / richtext / zone /
labelgrid 一律不翻但进 `Ticket::warnings`（指名控件 id + 坐标），`/print` 回给
调用方并置 `ok=false`。数据行驱动的表格也只留痕（`data` 运行期无形状约束）。

**已知没做**：Windows 的 RAW 直发（要 winspool StartDocPrinter(RAW)，本机
macOS 编译验证不了，不写没验过的 unsafe）。非 Windows 走 `lp -o raw` ——
不能过 CUPS 过滤器，会被当文本重排。

**本服务 `service_error` 是 HTTP 200 + `{ok:false, message}`，不是 5xx** ——
探针判据要落在 ok / message 上，别只看状态码。（xlsx 那条路是 500，别混。）
