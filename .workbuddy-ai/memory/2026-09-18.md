## 超长文本：按需换行 + 按需行高（行高这个缺口的收尾）

背景：昨天把列宽上限抬到 60，超过 60 的文本仍然被裁。而光开 `set_text_wrap`
不够 —— Excel 只在「行高没被写死」时才自动撑高，各查看器行为还不一致。

实现（`print-server/src/report/xlsx.rs`）：
- `lines_needed(text, avail)`：每个 `\n` 段独立算 `ceil(宽 / 可用宽)` 再 **求和**。
  硬换行是作者要断开的地方，不能跟自动换行混在一起取 max。
- `avail` 把**合并跨过的列宽算进来**，否则横跨多列的长标题会被误判成要换行。
- 行高 = 行数 × **15pt**（`LINE_HEIGHT`，Excel 自己的默认行高）。
- **只有真的要多于一行的行才写行高**；只有自己装不下的格子才套 wrap 格式。
  → 普通报表一行 `customHeight` 都不写、文件里没有 wrapText 样式，零变化。

验证：
- 5 条单测；3 次故障注入全抓到（`div_ceil`→整除 / 段间 sum→max / 行高 15→14）
- 集成层 2 次注入：关行高写入 → 探针看到 0 行高度；关 wrap → 探针看到无 wrapText
  （且行高仍在 → 证明是两条独立的线）
- 真机 18900：23 字备注 → 行高 30 + wrap；含 `\n` → 行高 30 且换行符原样保留；
  横跨 3 列的标题合并后够宽 → **不**换行不写行高；内置样例 23 行 → 0 行高度、无 wrap。

顺带把这两项纳入 `scripts/verify-xlsx-export.py`
（`--expect-height-rows N` / `--expect-wrap yes|no`），并反向验证过三条断言都会红。

Rust 187 passed，镜像一致。commit `3a028a8`。
