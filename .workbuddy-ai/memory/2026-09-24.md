### 核心结论

**本项目已经是「AI 可验证」的，但不是「AI 可编写」的。**
- 可验证：探针 / 故障注入 / 可判定不变量 —— 正是 AI-first 需要的地基。
- 不可编写：AI 只挂在**自由画布**那一层；差异化内核（`ReportDef` / `CellTpl` / 主格 / 表达式）对 AI 完全不可见。
- 且：画布协议**三份声明已漂移**，漂移**已造成静默删控件 bug**（已复现）。

### 先纠正的前提（重要，别再说「本项目没有 AI」）

`openprint/src/ai/` **716 行 5 个文件** + `designer-react/src/modals/AiAssistantModal.tsx` 完整接入。
含提示词/few-shot/流式客户端/**校验→回喂结构化错误→重试 1 次**/归一化修复，三模式（新建/改当前/只改选中）。

**这是靠 grep 发现的，不是靠依赖清单** —— 又一次印证「判断某能力有没有，先 grep 源码」。

### 复现的 bug（本次最硬的一条）

三份「控件类型」声明：schema 13 个 / `normalize.ts` 白名单 9 个 / 提示词散文 8 个。
`normalizeControl` 对白名单外的 type 返回 `null` → 被 filter 丢掉 → `diffSelectedControls` 算进 `removedIds` → `removeControl` **删掉控件** → 还弹**绿色成功**。

即：**选中画布上的图表控件让 AI 改配色 → 控件消失，界面说成功。**

复现：`text`/`zone` 过；`chart`/`math`/`signature`/`labelgrid` 返回 `[]`（4 failed / 2 passed）。
脚本见 `REFERENCE.md` §二十.2（`normalize.ts` 只有 `import type`，可单文件隔离跑）。

**通用教训**：一份协议有 N 处并行声明 = N 处会漂移，且漂移是静默的。
解法不是「记得同步」，是**写一条断言它们一致的闸，并证明这条闸能红**。

## 下午：修掉 §3.1 那个静默删控件的 bug（用户选「让丢弃出声」）

用户对「拓宽白名单 vs 让丢弃出声」的取舍表态：**倾向后者**。
理由（我也认同）：拓宽白名单会让模型有机会产出它并不理解载荷的图表控件，而「出声」在任何情况下都对。
所以 `VALID_TYPES` **仍是 9 项**，没动。

### 改动分 5 层（每层都可能「看着修好了、其实没接上」）

| 层 | 文件 | 关键点 |
| --- | --- | --- |
| 1 | `openprint/src/ai/normalize.ts` | `DroppedItem` / `NormalizeResult`；`normalizeControl(raw, dropped)` 的 `dropped` **必填**；`normalizeTemplate` → `{value, dropped}`；**整节类型拼错也上报**（原来也静默） |
| 2 | `openprint/src/ai/generate.ts` | `GenerateResult.dropped` **必填**；选区路径透出；**整模板路径把丢弃并进 `lastIssues`** → 复用已有的回喂重试；重试后仍不完整 → `ok:false` |
| 3 | `openprint/src/design/ai/shared/ai-assistant-logic.ts` | `diffSelectedControls` 第 3 参 `droppedIds` **必填**；`removedIds` 排除丢弃的 id；新增 `preservedIds` + `droppedIds()` / `droppedNotice()` |
| 4 | `designer-react/src/modals/AiAssistantModal.tsx` | 卡片显示「AI 处理不了」；`applySelected` 保留原样 + **warning**（非 success） |
| 5 | `openprint/src/design/ai/AiAssistantPanel.vue` | 同上 |

**⚠️ 意外发现：Vue 侧 `AiAssistantPanel.vue` 是同一个 bug 的第二个现场**（它也调 `diffSelectedControls`）。
如果只修 React，Vue 那套 UI 会继续删用户的控件。**改共享逻辑时一定要 grep 全部调用方。**

### 设计要点（可复用）

**把「丢弃」做成必填参数/字段，而不是可选回调或日志。** 这样「忘记处理」在**类型层面**就写不出来
（`GenerateResult` 少 `dropped` 直接 TS 报错；`normalizeControl` 少传收集器也是）。
这是「让静默失败变响」的通用手法：**先让忽略变得写不出来，再谈文档提醒。**

测试写法：白名单内/外两条用例都由 `VALID_TYPES` **推导**（不硬编码），将来有意放宽时自动适配；
另加一条显式清单用例把这个**刻意取舍**钉成文档。

### 🔴 我必须记下的错误：我把「测试有没有被跑到」判错了

上午那份分析里我写了「`openprint/src/ai/ai.spec.ts` **不在任何闸里 / 没有任何脚本会跑**」。
**这是错的。** 实测：

因为 `designer-react/vite.config.ts` 的 `test.include` 里有 `../openprint/src/**/*.spec.ts`。

**我犯的错**：只 grep 了 `scripts/` 目录就下了结论。判定「某测试有没有被跑到」要读**跑器的 include**。

**这个错误还让我把病因说错了**：bug 长期存活的真正原因**不是**「测试没跑」，而是
**「没有一条断言守那个不变量」**——8 条用例全绿，却没有任何一条问过「白名单外的类型有没有被上报」。
**测试跑了 ≠ 测到了。** 这个形态比「闸是红的」更难发现，因为它是**绿的**。

已在三处更正：`AI优先-差距分析与改进方案.md` §3.7（含「本节初版写错了」的显式标注）、
`REFERENCE.md` §二十.3、`MEMORY.md` 的 AI 层 bullet。
顺带把原方案里 0.2 那条**错的**一致性闸也改了 —— 原文写「断言 `schema.enum ≡ ControlType ≡ VALID_TYPES`」，
那会是一条**永远红**的闸（`VALID_TYPES` 本就该更窄）；正确的不变量是单向的。

### 提交后又自己找出一个洞（已补，第二次提交）

`droppedIds(dropped)` 只取**带 id** 的丢弃项。如果模型返回的未知类型控件**没带 id**，
就认不出它是选区里的哪一个 → 原控件的 id 仍会落进 `removedIds` → **照样被删**。
即：我的第一版修复只堵了「带 id 的丢弃」，**没堵「认不出是哪个的丢弃」**。

补法：`diffSelectedControls` 的第 3 参从 `string[]` 改成整个 `DroppedLike[]`，
内部算出 `unattributedDrops`；**只要 > 0，本次一律不删**。
判据是**代价不对称**：少删一个控件是**看得见**的（控件还在，想删再删一次），
多删一个是**看不见**的（静默丢数据）→ **保守优先于「猜对」**。
两个 UI 都多了一条 warning 分支说明「本次未执行任何删除」。

闸从 5 条加到 **6 条**（新增 4b：把 `unattributedDrops > 0` 改成 `false` → 必须红），**6/6 抓到**。
复验：AI spec 33 passed · 模态 spec 5 passed · ts-check 0 错 · 两个 project 闸 0 错 · `ts-test.sh` 239 passed。

**教训**：修「静默丢数据」时，要问一句「**有没有哪条路径是我认不出来的**」——
认不出来的那条最容易被漏掉，因为它连 id 都没有，而 id 正是我用来判断的依据。

→ 新形态，值得记进 `silent-failure-hunt`：
**「没有跑器的闸」比「红的闸」更坏** —— 红闸至少会喊；没有跑器的闸是**绿的**，
谁看一眼都会得到「契约一致」的信心，而那份信心是空头。
（这跟本项目已踩过的「长期红的闸 = 没有闸」是同一族的第三种形态。）
