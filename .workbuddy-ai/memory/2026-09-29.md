### ⚠️ 这一轮最值钱的结论：**写进注释 ≠ 处理了**

`check-all.sh` 里当时**明明白白写着**：

```
⚠️ 这是**已知的覆盖缺口**：…另外那 32 个 spec 文件…仍然不在本脚本里 ——
不是「没必要」，是那 346s 太贵。
```

这段话**读起来是负责任的**（承认了、给了理由、还强调「不是没必要」），
**但它同时让这件事变得不用处理了** —— 看起来「已经被知道、被权衡过」。

| | 错注释（09-28 那例） | **对注释（本例）** |
| --- | --- | --- |
| 复核的人去查 | 发现不对 → 有机会被修 | 发现**全对** → 于是走了 |
| 抗复核性 | 低 | **高** |

⇒ **判据：缺口写进文档时，必须同时写下「什么条件下必须回来处理它」。**
只写「现在不做，因为贵」= 把它变成**永久状态** ——「贵」不会自己变便宜。
**可执行写法**：把「因为贵」换成**可判定的触发条件**。
本例的条件真的出现了：「CI 比本机快 2~5 倍」被量出来 →「346s 太贵」当场失效 → 就该回来做。

### 顺手退休一条「已知未验风险」

`ci.yml` 原写「runner 只有 2 核，没在 2 核环境验证过，首次超时不算回归」。
**这条对串行的闸不成立**：闸 7 固定 `--no-file-parallelism`（**正确性**要求，
并行下本机实测 16 条超时假红）→ 一次只有一个文件跑、**独占 CPU**
⇒「互相抢 CPU 导致超时」**在结构上不存在**，与核数无关。

**顺带把核数变成可读的**：`::notice::` 现在带 `（runner N 核）`。
原来那句「只有 2 核」**没有任何依据**（job log 要 admin）。这延续了 09-28 那条
「把信息写到我读得到的地方去」。

## 追加：结掉 §11.6 的「未定论」——「CI 比本机快」是**假的**

### 结论

WorkBuddy 会话往 `NODE_OPTIONS` 注了一个 `--require` shim
（`node-language-shim.cjs`，959 B → 再 require `node-safe-delete-shim.cjs` +
`node-brokered-fs-shim.cjs`，**给每个 node 进程打 fs 补丁**）。
vitest 每个测试文件起一个进程 ⇒ 成本 × 文件数。

| | 带 shim | 清掉 shim |
| --- | --- | --- |
| 闸 7（44 文件 / 390 用例） | 343s | **99s** |
| 闸 8（70 文件） | 130s | **5s**（26×） |
| **总计** | **511s** | **118s**（4.3×） |

`NODE_OPTIONS="" bash scripts/check-all.sh` → **118s，通过 8 · 失败 0 · 没跑成 0**，用例数不变。
**闸 8 的 `environment` 累计 851.57s → 16.04s** —— 正是当年「剩下最可疑的」那一栏。
**CI 没这个 shim** ⇒ 本机 118s < CI 234s，**本机更快**（正常方向）。

### ⚠️ 过程中的两次自我纠错（比结论值钱）

| # | 一度以为 | 真相 |
| --- | --- | --- |
| ① | `--maxWorkers=1` 是个 3.4× 优化 | **旗子无关** —— 我直连 vitest 时手写 `NODE_OPTIONS=` 把 shim 顶掉了 |
| ② | 沙箱拖慢 fs | 关掉沙箱跑：30s vs 29s。shim 是**会话**注入的，不是沙箱的 |

**判据**：① 改跑器参数前先确认两次测量的环境变量一致；② 「本机 vs 别处」先问「我这边多加载了什么」。

**顺带排除的**：`--no-file-parallelism` 与 `--maxWorkers=1` **等价**（同一 `NODE_OPTIONS` 下都是 ~5s）；
`--no-isolate` **不能用**（全量 44 文件跑出 **24 条失败** —— 共享 `document` + 共享模块注册表，
`vi.mock` / 模块级单例跨文件泄漏。隔离是**承重**的）。
