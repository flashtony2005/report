`designer-react/src` 共 **44 个 spec**，闸 7 只跑 `grid-report-*` = **12 个** → **32 个没闸**。
清单里有 `canvas/`(5) `panels/`(4) `toolbar/`(2) `stores/`(4) `modals/`(5，非 grid-report)

（守 `openprint/src/contracts/golden/designer-v1.json` 的等价性）。
**我上一轮（09-28）刚改过它的失败提示语**（死路 → 两条恢复路径），
**却从没意识到它不在任何闸里**。

### 改法（一句话）

闸 7：`ts-test-designer.sh grid-report-` → `ts-test-designer.sh`。

| | 改前 | 改后 |
| --- | --- | --- |
| 闸 7 | 12 文件 / 151 用例 / ~185s | **44 文件 / 390 用例 / 343s** |
| 全量跑闸（本机） | 363s | **511s（8m31s）** |
| 结果 | — | **通过 8 · 失败 0 · 没跑成 0** |

**32 个从未跑过的 spec 一条都没坏**（390 全过）—— 和 §11.3 那 676 条一样，
缺的只是跑器，不是修不好的东西。

### ⚠️ 这一轮最值钱的结论：**写进注释 ≠ 处理了**

`check-all.sh` 里当时**明明白白写着**：

```
⚠️ 这是**已知的覆盖缺口**：…另外那 32 个 spec 文件…仍然不在本脚本里 ——
不是「没必要」，是那 346s 太贵。
```

这段话**读起来是负责任的**（承认了、给了理由、还强调「不是没必要」），
**但它同时让这件事变得不用处理了** —— 看起来「已经被知道、被权衡过」。

| | 错注释（09-28 那例） | **对注释（本例）** |
| --- | --- | --- |
| 复核的人去查 | 发现不对 → 有机会被修 | 发现**全对** → 于是走了 |
| 抗复核性 | 低 | **高** |

⇒ **判据：缺口写进文档时，必须同时写下「什么条件下必须回来处理它」。**
只写「现在不做，因为贵」= 把它变成**永久状态** ——「贵」不会自己变便宜。
**可执行写法**：把「因为贵」换成**可判定的触发条件**。
本例的条件真的出现了：「CI 比本机快 2~5 倍」被量出来 →「346s 太贵」当场失效 → 就该回来做。

### 顺手退休一条「已知未验风险」

`ci.yml` 原写「runner 只有 2 核，没在 2 核环境验证过，首次超时不算回归」。
**这条对串行的闸不成立**：闸 7 固定 `--no-file-parallelism`（**正确性**要求，
并行下本机实测 16 条超时假红）→ 一次只有一个文件跑、**独占 CPU**
⇒「互相抢 CPU 导致超时」**在结构上不存在**，与核数无关。

**顺带把核数变成可读的**：`::notice::` 现在带 `（runner N 核）`。
原来那句「只有 2 核」**没有任何依据**（job log 要 admin）。这延续了 09-28 那条
「把信息写到我读得到的地方去」。
