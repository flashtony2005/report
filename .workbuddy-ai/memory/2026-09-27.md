## mirror-check.py 加「语义层」（第 2 档）—— 规则类事实的跨语言闸

**动机**：`mirror-check.py` 以前只对**字段名形状**（24 组）。于是「TS 侧单独改一个字节上限
/ 别名 / 白名单」**没有任何闸会红** —— Rust 侧改了有内容钉子，TS 侧改了无人拦。
属本项目最怕的「同一份事实声明两遍后漂移」。

### 改了什么

`scripts/mirror-check.py` 从单层变**两层**：

```
A. 形状层   24 组 (Rust 文件, Rust 类型, TS 类型) —— 只比字段名（行为不变）
B. 语义层    8 条规则类事实 —— 比内容，每条自带方向
```

新增 `dataclass Fact{label, rust, rust_path, ts, mode, note}`，`mode` 三种：

| mode | 含义 | 用在 |
| --- | --- | --- |
| `equal` | **顺序 + 内容**都要一致 | 会被 TS 拿去拼提示文案的清单（`PAPER_NAMES.join(' / ')`）—— 顺序变了用户看到的话就变了 |
| `set_equal` | 集合相等，**顺序不算** | 只做「认不认识」判断的清单（`IssueCode`） |
| `ts_subset` | **TS 不允许比 Rust 宽**，允许更窄 | 别名表（TS 少认一个别名是合法收窄） |

### 关键设计：**抽取失败必须红，不能静默跳过**

抽取函数返回 `Optional[list[str]]` —— **`None` 不是「空」，是「抽取失败」，计为红**。
理由（写进文件里了）：静默跳过会让这条检查退化成「永远绿、但根本没在检查」——
**比红闸更坏，因为它产出的是空头的信心**。

配套 `_one(pattern, text)` 要求锚点**恰好匹配 1 处**：
匹配 **0 处**（常量被改名）和 **≥2 处**（正则写松了）**都算失败**。

**「≥2 处」不是假想的**：`engine.rs` 在 4 个测试函数内各自定义了局部 `const KINDS`
（`:4559 :4803 :4852 :4921`）。抽取器若图省事做**全仓搜索**，「取第一个」会
**静默取到测试里的那张表**。`_one()` 把这种情况变成红。

### 另一个自己踩出来的坑：字符串里的 `{`

取函数体靠数花括号（`_fn_body`），而 `normalise_symbology` 里有 `format!("…{raw}…")`
和 `"{}"` —— **字符串字面量里的 `{` 会让计数错位**，切出错误的函数体、可能给出**假 OK**。
修法：先 `_blank_strings()` 把字符串**内容**抹成**等长空格**（长度不变所以索引不漂）再数括号。
三种引号都要处理（Rust/TS 双引号、TS 单引号、TS 模板串）。

## 第 4 档第 1 条：保存不再毁用户的报表

**用户说「按推荐的选择处理」→ 我推荐的是这条。** 原本只是「原子写报表」（~5 行），
读代码时发现**另一半更严重**，一起做了。

### 两个缺口

| # | 缺口 | 性质 |
| --- | --- | --- |
| **A** | 手打一个**已存在**的 id 点保存 → 那份报表被**无声无息换掉** | **静默** |
| **B** | 写到一半崩 / 磁盘满 → 文件变截断 JSON，旧内容无备份、不可恢复 | 可见的数据丢失 |

**A 不在体检报告里**，是顺着 B 的代码读出来的：`store::save` 的 doc 注释写着
「静默覆盖同名文件会丢东西，**所以调用方（UI）要先经列表确认**」，
而 `GridReportModal` 的 `saveReport` **一次确认都没有**，UI 手上明明有 `savedReports`。

> **教训：读到「所以调用方要 X」的注释，去调用方看一眼 X 做了没有。**
> 这种注释比没有注释更坏 —— 它让后来的人**以为已经处理过了**。

### 改了什么

**服务端** `print-server/src/report/store.rs`：
新增 `write_atomic(path, text)` = `.bak` 备份 → 写 `.tmp` → `rename`。
与 `config.rs::ServerConfig::save` 同一套。`rename` 保「不出半成品」，
`.bak` 保「覆盖可逆」——**两件事，缺一不可**。
顺带钉住新风险：`.bak` / `.tmp` 不能进 `list()`（判据 `extension()=="json"` 天然跳过；
改成 `contains(".json")` 就会漏）。

**客户端** `designer-react/src/modals/GridReportModal.tsx`：
- 新增 `lastSavedId` / `reportsListKnown` / `pendingOverwrite` 三个 state
- `saveReport` 拆成「判据 + `doSave`」两段（确认后要能回到落盘那步，不能重建请求）
- 判据 `id !== lastSavedId && (!reportsListKnown || 列表里有这个 id)`
- 确认框写明**要换掉的是哪一份** + 上一版留在哪个 `.bak`

## 第 4 档第 1 条·补做：确认从「客户端自觉」升级成「服务端强制」

上一条记的边界（列表快照过期 → 客户端判不出同名 → 静默覆盖）当天补掉了。

### 两道闸查的**不是同一个事实**（所以是互补，不是重复）

| | 判据来源 | 挡得住 | 挡不住 |
| --- | --- | --- | --- |
| UI 预判 `saveReport` | 打开弹窗那一刻的**列表快照** | 手打一个列表里已有的 id | 之后别处新建的同名 |
| 服务端 `store::save_new` | **文件系统**（权威） | 任何调用方，含 curl | —— |

### 改动

- **`store.rs`**：`SaveError{Invalid, Conflict}` —— **必须能区分**，否则 UI 只能靠
  匹配文案分辨「弹错误」还是「弹覆盖确认框」，文案一改就静默失效。
  `save` 改返回它；抽出 `normalise_id` **只此一处**；新增 `save_new`（已存在 → `Conflict`）。
- **`mod.rs`**：`SaveQuery{force}` + `forced()`；handler 按 `forced()` 选 `save` / `save_new`；
  `Conflict` → **409**、`Invalid` → 400。`force` 走**查询串**不走请求体 ——
  请求体是 `ReportDef` 本体、要原样落盘，塞 `force` 得靠 `#[serde(skip)]` + TS 同步忽略，
  那是往「用户资产的文件格式」上开一个只为本次请求服务的口子。
- **UI**：`doSave` 加 `force` 实参（→ `?force=1`）；**409 分支排在通用 `!res.ok` 之前**；
  `id === lastSavedId` 时带 force（不带的话「存自己刚存过的那份」会被 409 顶回来，
  用户看到「存自己的也要确认」= 把闸做成了绊脚石）。

### 三个关键判据

1. **`forced()` 只认 `1`/`true`/`yes`**，`0`/`flase`/空值**一律当没带**。
   语义是「**证明**你知道要覆盖」，不是「提过这事」。判错方向的代价是静默覆盖 →
   一律往「多问一次」倒。
2. **409 分支必须在通用错误分支之前**。落进通用分支的症状：用户看到「报表 x 已存在」
   然后**没有任何办法继续保存**，明明点一下「覆盖」就能存。
3. **`normalise_id` 只此一处**。`save` 会 trim → `" t8 "` 落盘成 `t8.json`；
   `save_new` 若拿没 trim 的串查存在性 → 判「不存在」→ 放行 → 覆盖掉 `t8.json`。
   **不报错、不警告，安静地毁数据。** 有专门用例 + 注入 S2 钉住。

### 证据

  **文件逐字节不变**、有 force 能穿透、typo 不当授权、非法 id 是 400 不是 409。
- 新注入 `scripts/fault-inject-save-conflict.py` **6 条 / 7 道门禁，7/7**。

而 UI 正是靠状态码决定弹错误还是弹确认框。单测代替不了。

## 第 4 档第 1 条·补做 2：`updatedAt` 乐观锁（同日）

接上一节「仍未做」：**做了** `PUT /api/reports/save?base=<updatedAt>`，不符 → **412**。
（详情 `架构体检-不足与改进方案.md` §9.7；引擎契约 `报表引擎详解` §13.6.1；
长期参考 `.workbuddy-ai/memory/REFERENCE.md` §二十一.12。）

### 为什么必须做

`force` 是**授权声明**（「我有权写这个 id」），**不是版本比对**。
前两道闸查的都是「**有没有**」，**没有一道查「是不是我看到的那个」**：

> 我打开 A（V1）→ 别人改了 A（V2）→ 我保存 → 请求带 `force`（我确实在编辑它）
> → 服务端**没有任何依据**说「你手上的不是最新的」→ 静默覆盖掉别人的 V2。

### 改了什么

- **`store.rs`**：`save` / `save_new` 合成**唯一入口** `save(dir, def, expect)`，
  `expect: Expect{Absent, Base(String), Anything}`（**三态**）。`SaveError` 加
  `Stale{expected, actual}`，`message()` 改返回 `String`（**别拿它做分支判据**）。
  新增 `now_millis` / `days_from_civil` / `format_rfc3339_millis` /
  `parse_rfc3339_millis` / `next_updated_at`。
- **`mod.rs`**：`SaveQuery{force, base}` + `expect()`；`Stale` → **412 + `Json(CasConflictBody{expected, actual})`**。
- **UI `GridReportModal.tsx`**：`baseUpdatedAt` 状态；`doSave(def, id, {force, base})`
  两个开关都发；**412 分支**弹第二个框（三个按钮：取消 / 重新打开 / 用我的版本覆盖）；
  保存响应回填 `baseUpdatedAt`；打开报表时播种 `def.updatedAt`。

### 五条判据（都不是顺手写的）

1. **409 / 412 的分界不是状态码，是「失败里有没有客户端能用的值」。**
   409 原样重发（补 `force`）就能过 → 不需要 payload；412 原样重发**永远不会**成功
   （必须先改状态）→ **必须**带 `expected`/`actual`，否则用户没有出路。
2. **`base` 压过 `force`** —— 代价不对称：`force` 赢 → 带 `base` 的请求**静默退化成盲覆盖**，
   保护丢了且**不留痕迹**；反方向只是多点一次「覆盖」。→ **冲突时选错得更响的那边。**
3. **三态而不是 `Option`** —— `Option` 只有两态，把「无条件覆盖」塞进 `None` 会让
   `force=1` 打在**全新 id** 上被判成「不存在」→ 412 = **凭空造出不存在的冲突**。
   白拿：`match` 穷尽性由**编译器**保证。
4. **`Base` 打在「文件不存在」上必须 `Stale`**（当前版本≠base），不能当新建放行。
5. **「用我的版本覆盖」发 `force` 且\*\*不带 `base`\*\*** —— 带上会因 base 赢而**再 412**，
   用户卡在点了没反应的按钮上。

### `updatedAt`：两件事必须分开（我原先混了）

`next_updated_at = max(now, 旧值 + 1ms)`，定宽 `YYYY-MM-DDTHH:MM:SS.mmmZ`（UTC）。

- **严格递增由 `+1ms` 保证，与时钟精度无关**（秒级时钟也严格递增）。
  我一开始写注释说「毫秒精度让它唯一」——**错的**。
- **毫秒精度解决的是另一件事**：`+1ms` 以「上一次的值」为基准 → 时间戳**越跑越超前于
  真实时间**；而它**是给用户看的**（「更新于 …」）→ 超前就是显示错误。毫秒让它实际
  不可达（每次保存都写盘）。顺带对齐 `local-repo.ts` 的 `new Date().toISOString()`。
- **结构上不能互相代替 → 各有一条测试**（精度一条、单调一条）。
- **定宽 ⇒ 字典序 == 时间序**。`updatedAt` 在**所有消费点**都是**不透明字符串**
  （Rust 只打印 `main.rs:121`；TS 用 `localeCompare` 排序、原样显示，**无一处解析**）
  → 这正是界面「按字符串排序」**正确**的原因；形状不定宽则**静默排错**。
- 解析器**只认两种定宽形状**：24（当前）/ 20（**旧版秒级**，磁盘上已有）——
  不认后者第一次保存就丢单调性。

  最有价值** —— 唯一能抓到「副作用已经发生」的那条。

### 坑（都是「闸自己有毛病」）

1. **注入报「没抓到」时先怀疑闸在误报。** 探针原先早期步骤失败就 `return 2`（= 没跑成）
   → 第 2 步一挂，注入 L9 从「抓到」变成「**没验过**」= **一个真回归被报成「结论不明」**。
   修法：区分「契约破了」（1）与「环境没起来」（2）。**退出码语义是承重的。**
2. **`.bak` 不能当「这次碰没碰盘」的证据，除非先清掉上一次的。** 断言「被拒的保存没留
   `.bak`」时，**前一次**合法覆盖的 `.bak` 还在 → 断言测的是**上一次保存**。
3. **子串锚点不是行锚定的。** 缩进 10 空格的锚点**同时**匹配缩进 14 空格那行的偏移 4
   （`count() == 2`）→ 注入报「锚点不唯一」。改用**逐字多行块**。
4. **一条「绿得不是因为它该绿」的用例。** UI「回填新版本」断言原先比较的两个值**恰好

5. **注入必须连参数一起删。** Rust `format!` 多传实参是**编译错误** → 「丢掉毫秒」那条
   注入得把 `millis` 实参一并删，否则报的是「没编译过」。
6. **`cmd | tail -N` 之后的 `$?` 是 `tail` 的，不是 `cmd` 的。** 收尾跑探针
   `python3 … | tail -40` 紧跟 `echo "EXIT=$?"` 打出 `EXIT=0` —— 那是 **`tail` 的退出码**，
