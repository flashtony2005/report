## 把非线性语义画进网格（已完成并推送）

设计态模板格子看不见三件决定报表形状的事：哪一格会往下长、哪一格的数是算出来的、
谁挂在谁下面。做法是编码成**样式**（不能加文本标记 —— 文本是回写载体，
`formatCellText` → `{{...}}` → `parseCellText`，塞标记会在用户编辑时静默冲掉 model）。

- 底色 = 扩展方向（纵向 `#FFF1B8` / 横向 `#D7F0E3`）
- 字色 = 内容来源（字段 `#1668DC` / 表达式紫斜 `#6B4FBB`）
- 底边框橙 `#D85A30` = 挂了 `row/col_test_expr`
- 主格是「关系」：选中一格点亮它的 `row/col_parent`（`PARENT_HIGHLIGHT`），
  移开还原；用 `setBackgroundColor` 直改不重建工作簿（重建丢选区）。

产物：`openprint/src/report/grid-report.ts`（`SEMANTIC_LEGEND` / `semanticStyleOf` /
`semanticBgOf` / `parentPosOf` / `PARENT_HIGHLIGHT`）、`GridReportModal.tsx`（图例 +
SelectionChanged 点亮主格）、`scripts/verify-semantic-colors.py`。

### 顺带修掉的三个真 bug

1. **空扩展格画不出底色**：`gridToWorkbookData` 里 `if (!text && !anchor) return`
   把没文字的扩展格整格跳过 —— 最该被看见的语义恰好在空格上失效。
2. **边框 `s: 2` 是 HAIR 不是 MEDIUM**：Univer `BorderStyleTypes` 里
   `1=THIN 2=HAIR 8=MEDIUM 13=THICK`。想画醒目的一条却画成最细发丝线。
   已换成具名常量 `BORDER_THIN/BORDER_MEDIUM`。**别对第三方枚举写魔法数字。**
3. 重复实现 `parseCellPos`（已有 `parsePos`），主格高亮色在两处硬编码 —— 都收敛成一份。

### 验证手法（可复用）

- 11 条新单测 + 5 个故障注入（改底色 / 去橙边框 / 主格高亮失效 / 空扩展格又不输出 /
  只改图例不改配色）逐个确认能变红。
- **canvas 上的东西只能数像素**：Univer 画在 canvas 上，DOM 读不到，
  页面也没暴露 `univerAPI`。截图 → PIL 数 `#rrggbb`。
- **必须裁到网格区域**：图例本身就是这几个颜色的色块，不裁的话图例自己
  就能让检查通过（第一版被骗过去了，报「4 种颜色都在」其实是图例贡献的）。
- 坐标从已上色格子的 bbox 反推：先让 A1 变黄，从黄色 bbox 得到格子位置和行高，
  再算出 B1 的坐标去点。

## 主格关系常显（已完成并推送）

主格是「关系」，而 Univer 只有底色 + 字色两个通道且都已占满 ——
**格子里静态画不出关系**。关系本质是树，所以做成网格旁**常显一棵主格树**
（`parentTreeOf` / `parentChainOf`），而不是硬塞进格子。

- 树只收带 model 的格（字面量标题是噪音）；成环 → 拎出来当根标 `cycle`；
  主格指向无 model 的格 → 当根标 `orphan`。两种异常都不让节点消失。
- 选中时点亮**整条**主格链（原来只有直接主格）+ 直接列主格。
- 9 条新单测 + 4 个故障注入。教训：第一条 orphan 测试**没抓到**注入，
  因为节点被成环兜底救了、结果碰巧一样 —— 加了 `cycle` 为假的断言才补上。
- 实测：树 `A1 └ B1 └ C1`；点 C1 → A1+B1 同时亮橙（2761px，bbox 横跨两列）；
  点 A1 → 橙归零、黄恢复到 1168px。

## 第 1 项：expandInplaceCount 的等价性实验 + per-cell 入口

差距表里那行 ⬜ 原本要前后端加模型字段。先做实验回答「值不值得做」：

| 实验                              | 观测                                                            | 结论                       |
| ------------------------------- | ------------------------------------------------------------- | ------------------------ |
| 补出来的行显示什么                       | 模板兜底 `"—"` 出现在补足行上：`"— \| "` ≠ `" \| "`                    | 补足行是**模板行的副本**，不是空行    |
| 数据多于 N 时                        | 5 条 + 下限 3 → 6 行                                            | 下限不是上限，只补不截             |
| 模板里手写预留行                        | 2 / 5 条数据 + 2 行预留 → 5 / 8 行，预留行**不随数据伸缩**                 | 静态行是根格，「手写预留」≠「至少 N 行」 |

前两条 = NopReport `expandInplaceCount` 的输出形状：不足复用、超出正常新增。
**`expand_min_count` 在引擎层已经是等价实现**，差距表那行 ⬜ → ✅（论证见
`引擎差距分析-对照PDF资料.md` 的 `expand_min_count` 节）。

剩余差异（窄）：NopReport 允许预留行各自不同（插入后手改某一行）。我们补足行
必然是同一模板行的副本。这个场景在我们的网格模型里用户可直接写多行模板行表达，
语义是「固定行」而非「下限」，不影响「默认 N 个空行」这个需求。

### 但是够不着：UI 补 per-cell 入口

引擎等价 ≠ 用户能用。原来 `expand_min_count` 只在分组 / 交叉表模式下由报表级
开关套用（`withExpandControl`），那个开关按「猜最内 / 最外层」定位格子——
自由模板的层级是用户一格一格定的，让它再猜一遍会覆盖用户意图，所以自由模式
**刻意不套**。结果：本引擎主场里用户根本够不着。

解法：自由模板格子属性面板里，**选中展开格时**出现「最少行数 / 最少列数」
输入（`free-cell-expand-min-count`，`expand_type='c'` 时 label 自动变列），
打在哪一格由点选决定，不猜。

### 守住的测试

- **Rust**（`mod.rs::tests::bill_template` + 3 个 `it` + 4 次故障注入 J1–J4）：
  拿掉补行 → 两条变红；改成 `truncate` → 「只补不截」单独变红；补足行硬 Null →
  「模板副本」单独变红；给预留行挂主格 → 第三个变红且暴露出「每个数据行各跟 N 行」。
- **TS**（`grid-report.spec.ts` 的「自由模板：最少行数按格直设」）：
  提交链路 `gridToSheet` → `withExportFormula` 重建 model 时值仍在；
  故障注入 K1（去掉 `{...m}` 展开）让 `expand_min_count === 4` 红（`undefined`）。
- **浏览器**（手动）：纵向 ↓ → 「最少行数」输入出现、testid 进 DOM、
  模板体检警告里识别到「扩展格」（模型注册成功）。

### 「等价」与「复述」的区别

第一次三个测试全绿时差点以为它们在互相复述。J3 把补足行兜底改成 Null 后，
`pads_with_template_row_not_blank_row` 红而 `is_a_floor_not_a_cap` 仍然绿
—— 两条断言测的是**不同的主张**，不互相复述。记号留给以后：用同一个变量改两次
看不出问题的测试组，拿掉其中一条命题单独跑，必有一条死。

## per-cell UI 入口补齐（format_expr / dict / format / keep / max）

第 1 项收官后顺手把自由模板面板里**没暴露的** CellModel 字段补齐。原则：

- 引擎真支持 + 用户能受益 → 加
- 引擎没实现（`expand_expr` 只在测试夹具出现）→ 不加，加了是死控件
- 与全局开关互相覆盖（`export_formula` per-cell vs 报表级）→ 不加，留全局

新加的 6 个 testid：

| testid | 字段 | 说明 |
| --- | --- | --- |
| `free-cell-format-expr` | `format_expr` | 展示期表达式，`value` 指代本格值 |
| `free-cell-dict` | `dict` | JSON 对象，半截输入留草稿不提交（避免静默毁数据） |
| `free-cell-format-kind` | `format.kind` | text/int/decimal/currency/percent |
| `free-cell-format-digits` | `format.digits` | 选了 kind 才出现 |
| `free-cell-expand-max-count` | `expand_max_count` | 跟 min 并列在展开格行 |
| `free-cell-keep-empty` | `keep_expand_empty` | 空集保留开关 |

新增 1 条 TS 测试，把上面 5 个字段（除 digits 触发条件）一次性塞进一个带 `value_expr`
的 cell，逼 `withExportFormula` 走「重建 model」分支再断言全活着。故障注入
（让 `withExportFormula` 只丢 `dict`）让字典断言单独变红，其余 91 个测试不变 ——

证明这一组测试不是互相复述，每条断言守着自己的字段。
