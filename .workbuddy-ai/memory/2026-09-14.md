## 把非线性语义画进网格（已完成并推送）

设计态模板格子看不见三件决定报表形状的事：哪一格会往下长、哪一格的数是算出来的、
谁挂在谁下面。做法是编码成**样式**（不能加文本标记 —— 文本是回写载体，
`formatCellText` → `{{...}}` → `parseCellText`，塞标记会在用户编辑时静默冲掉 model）。

- 底色 = 扩展方向（纵向 `#FFF1B8` / 横向 `#D7F0E3`）
- 字色 = 内容来源（字段 `#1668DC` / 表达式紫斜 `#6B4FBB`）
- 底边框橙 `#D85A30` = 挂了 `row/col_test_expr`
- 主格是「关系」：选中一格点亮它的 `row/col_parent`（`PARENT_HIGHLIGHT`），
  移开还原；用 `setBackgroundColor` 直改不重建工作簿（重建丢选区）。

产物：`openprint/src/report/grid-report.ts`（`SEMANTIC_LEGEND` / `semanticStyleOf` /
`semanticBgOf` / `parentPosOf` / `PARENT_HIGHLIGHT`）、`GridReportModal.tsx`（图例 +
SelectionChanged 点亮主格）、`scripts/verify-semantic-colors.py`。

### 顺带修掉的三个真 bug

1. **空扩展格画不出底色**：`gridToWorkbookData` 里 `if (!text && !anchor) return`
   把没文字的扩展格整格跳过 —— 最该被看见的语义恰好在空格上失效。
2. **边框 `s: 2` 是 HAIR 不是 MEDIUM**：Univer `BorderStyleTypes` 里
   `1=THIN 2=HAIR 8=MEDIUM 13=THICK`。想画醒目的一条却画成最细发丝线。
   已换成具名常量 `BORDER_THIN/BORDER_MEDIUM`。**别对第三方枚举写魔法数字。**
3. 重复实现 `parseCellPos`（已有 `parsePos`），主格高亮色在两处硬编码 —— 都收敛成一份。

注入 bd 回归能变红。

## 主格关系常显（已完成并推送）

主格是「关系」，而 Univer 只有底色 + 字色两个通道且都已占满 ——
**格子里静态画不出关系**。关系本质是树，所以做成网格旁**常显一棵主格树**
（`parentTreeOf` / `parentChainOf`），而不是硬塞进格子。

- 树只收带 model 的格（字面量标题是噪音）；成环 → 拎出来当根标 `cycle`；
  主格指向无 model 的格 → 当根标 `orphan`。两种异常都不让节点消失。
- 选中时点亮**整条**主格链（原来只有直接主格）+ 直接列主格。
- 9 条新单测 + 4 个故障注入。教训：第一条 orphan 测试**没抓到**注入，
  因为节点被成环兜底救了、结果碰巧一样 —— 加了 `cycle` 为假的断言才补上。
- 实测：树 `A1 └ B1 └ C1`；点 C1 → A1+B1 同时亮橙（2761px，bbox 横跨两列）；
  点 A1 → 橙归零、黄恢复到 1168px。

## 语义色 × 合并单元格（真实形态验证，已推送）

之前所有语义色验证都搭在**没有合并**的小网格上 —— 而真实模板第一件事就是
标题横铺合并。补了一次真实形态验证：A1 标题合并 1×3 + A2→B2→C2 三级链。

- A2/B2 双黄 2620px；点主格树 C2 → A2+B2 同时亮橙 2795px、黄让位到 0。
  合并块不影响语义色，也不影响主格链点亮。
- 字面量标题**即便被合并也不进主格树**（树只收带 model 的格）。
- 新单测「合并锚点保留语义底色」，注入「合并格不套样式」能变红。
