## 把非线性语义画进网格（已完成并推送）

设计态模板格子看不见三件决定报表形状的事：哪一格会往下长、哪一格的数是算出来的、
谁挂在谁下面。做法是编码成**样式**（不能加文本标记 —— 文本是回写载体，

- 主格是「关系」：选中一格点亮它的 `row/col_parent`（`PARENT_HIGHLIGHT`），
  移开还原；用 `setBackgroundColor` 直改不重建工作簿（重建丢选区）。

产物：`openprint/src/report/grid-report.ts`（`SEMANTIC_LEGEND` / `semanticStyleOf` /

## 主格关系常显（已完成并推送）

主格是「关系」，而 Univer 只有底色 + 字色两个通道且都已占满 ——
**格子里静态画不出关系**。关系本质是树，所以做成网格旁**常显一棵主格树**
（`parentTreeOf` / `parentChainOf`），而不是硬塞进格子。

- 树只收带 model 的格（字面量标题是噪音）；成环 → 拎出来当根标 `cycle`；
  主格指向无 model 的格 → 当根标 `orphan`。两种异常都不让节点消失。
- 选中时点亮**整条**主格链（原来只有直接主格）+ 直接列主格。
- 9 条新单测 + 4 个故障注入。教训：第一条 orphan 测试**没抓到**注入，
  因为节点被成环兜底救了、结果碰巧一样 —— 加了 `cycle` 为假的断言才补上。
- 实测：树 `A1 └ B1 └ C1`；点 C1 → A1+B1 同时亮橙（2761px，bbox 横跨两列）；
  点 A1 → 橙归零、黄恢复到 1168px。

## 第 1 项：expandInplaceCount 的等价性实验 + per-cell 入口

差距表里那行 ⬜ 原本要前后端加模型字段。先做实验回答「值不值得做」：

| 实验                              | 观测                                                            | 结论                       |
| ------------------------------- | ------------------------------------------------------------- | ------------------------ |
| 补出来的行显示什么                       | 模板兜底 `"—"` 出现在补足行上：`"— \| "` ≠ `" \| "`                    | 补足行是**模板行的副本**，不是空行    |
| 数据多于 N 时                        | 5 条 + 下限 3 → 6 行                                            | 下限不是上限，只补不截             |
| 模板里手写预留行                        | 2 / 5 条数据 + 2 行预留 → 5 / 8 行，预留行**不随数据伸缩**                 | 静态行是根格，「手写预留」≠「至少 N 行」 |

前两条 = NopReport `expandInplaceCount` 的输出形状：不足复用、超出正常新增。
**`expand_min_count` 在引擎层已经是等价实现**，差距表那行 ⬜ → ✅（论证见
`引擎差距分析-对照PDF资料.md` 的 `expand_min_count` 节）。

剩余差异（窄）：NopReport 允许预留行各自不同（插入后手改某一行）。我们补足行
必然是同一模板行的副本。这个场景在我们的网格模型里用户可直接写多行模板行表达，
语义是「固定行」而非「下限」，不影响「默认 N 个空行」这个需求。

### 但是够不着：UI 补 per-cell 入口

引擎等价 ≠ 用户能用。原来 `expand_min_count` 只在分组 / 交叉表模式下由报表级
开关套用（`withExpandControl`），那个开关按「猜最内 / 最外层」定位格子——
自由模板的层级是用户一格一格定的，让它再猜一遍会覆盖用户意图，所以自由模式
**刻意不套**。结果：本引擎主场里用户根本够不着。

解法：自由模板格子属性面板里，**选中展开格时**出现「最少行数 / 最少列数」
输入（`free-cell-expand-min-count`，`expand_type='c'` 时 label 自动变列），
打在哪一格由点选决定，不猜。

## expand_expr：死字段 → 固定列表展开（748c0bf）

不是无害的死字段：`grid-report.ts` 的 `validateTemplate` 在**主动替它担保**
（"没数据集？写 expand_expr 就行"），而 Rust 引擎一处都不读 → 用户照做拿静默错报表。
空头支票比没这个字段更糟，所以必须处理。

**先量后改救了一次**：`model.rs` 原注释写 P1 范围是「数据集名 / 数组字面量」。
量下来「数据集名」根本不可能实现 —— `Engine::new(ds: DataSet)` 引擎只有一个 DataSet，
全仓无 `datasets` 复数。只实现了数组字面量，删掉注释里那一半。

实现要点：
- `Expr::Array`。`[` 在 **primary 位置**上只可能是数组字面量，层次坐标的 `[`
  紧跟格名由 `parse_ident` 消费，不冲突。
- 加枚举变体后编译器报了 2 处我漏掉的穷尽 match（`excel_of`、`expr_is_cur_independent`）。
  **加 AST 变体后先 build 一遍，让编译器点出所有 match。**
- `group_by_list` 与 `group_by_field` 的差异就是全部价值：顺序按字面量 +
  数据里没有的项照样展开（月份补全）。

**既有坑（非本次引入，记录在差距文档）**：展开格实例数为 0 → 子格 `by_pos` 查不到
父格 → `vec![None]` 退回挂根 → 拿全量数据算合计（`engine.rs:638-643`）。
用无关的 `expand_max_count: 0` 复现得到一模一样的 `" | 700"`，确认正交。

脚下坑：Python heredoc 往 Rust 里写 `r#"[\"a\"]"#` 会把反斜杠写进 raw string
（`\\"` → `\"`），解析直接失败。Rust raw string 里不该有转义。

## 修「主格展开成 0 条 → 子格退回挂根算全量合计」（bb72496）

根因：父格展开成 0 条时 `by_pos` 里**根本没有它的键**（原先 `created.is_empty()`
直接 `continue`，连键都不登记）。于是「主格展开成 0 条」和「主格压根不存在（模板
写错）」在子格眼里完全一样，都走「退回挂根」→ 子格挂到根上拿全量数据 → 算出一张
「什么都没筛」的假合计（实测 700）。看着像真的，比报错难查。

修法：pos **早于父格循环**登记进 `by_pos`（可以是空表），然后三分开：
有实例 → 正常；空表 → 子格一条不出；键不存在 → 挂根 + 告警（原行为）。

**自引用必须单独放过**：`p == pos` 不能走「空表」那条，否则整张表悄悄变空
（探针实测 left=[""]）。现成模板里真有这种写法 —— 两个测试的 helper 把
`row_parent` 硬编码成 "A1"/"A2"，而那个格自己就是展开格。已把模板改干净，
引擎里的豁免用专门的测试守住。

## 报表目录「静默换个地方」（已披露，未改行为）

服务起来后 `/api/reports` 返回 `[]`，但 `print-server/reports/sales-by-region.json`
明明在。根因：`store::reports_dir(config_path)` = **配置文件同级**的 `reports/`，
而 main.rs 里默认配置路径是**相对**的 `print-server.json`（`OPENPRINT_PRINT_SERVER_CONFIG`
可覆盖）。于是「从哪个目录启动」决定看见哪个 `reports/`：

| 启动 cwd | 解析出的报表目录 | /api/reports |
|---|---|---|
| `print-server/` | `print-server/reports/` | 1 条 |
| 仓库根 | `report/reports/`（不存在） | `[]`，**无任何报错** |

**目录跟着配置文件走是刻意设计**（便于整体备份/迁移），所以没改行为，只做披露：

- 启动横幅加 `报表目录: <绝对路径>`（canonicalize，和「打印落盘目录」同款）
- `/health` 加 `reportsDir`
- `/api/reports` 加 `x-reports-dir` 响应头（不塞 body：`ReportSummary[]` 形状已有人用）
- 设计器空列表时把那行目录显示出来（`report-file-empty-hint`）

### 关键实现点

- **跨域下自定义响应头默认读不到**，要服务端 expose。本项目用
  `CorsLayer::permissive()`，它包含 `.expose_headers(Any)` → 回
  `access-control-expose-headers: *`，现代浏览器能读。**curl 证明不了这一点**，
  得在页面里 `fetch(...).then(r => r.headers.get('x-reports-dir'))` 才算验过。
- `HeaderValue` 只收可见 ASCII，**中文目录名会被拒**。直接 `.ok()` 丢掉就又是静默
  失败（而回这个头的全部意义就是排空列表），所以写了 `store::header_safe`：按 UTF-8
  字节 percent 编码非可见 ASCII，`%` 自己也编码，客户端 `decodeURIComponent`。
- 设计器侧先写的是 Tooltip，**hover 触发不了也验不了**（antd Tooltip 用 overlay
  不用原生 title，`agent-browser hover` + 合成 MouseEvent 都没弹出）。改成**行内
  文字**：更好验，也更该被看见 —— hover 才出现的诊断信息本身就是坏设计。

### 探针

把 `p.join("reports")` 改成 `p.join("report")` → 两个新测试立刻红，且给出具体
路径差异（`/srv/openprint/report` vs `/srv/openprint/reports`）。改 `header_safe`
则第三个红。**三个测试都不是摆设。**

`univerFormulaFree.ts` 注册 `beforeCommandExecuted` 钩子，

1. **docs + docs-ui 插件不能省**。sheets-ui 的单元格编辑器依赖
