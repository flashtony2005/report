### 1.1 提出问题（p5-p6）：8 条旧系统痛点 → 引擎解法

| 痛点 | 解法 |
|---|---|
| 颜色警告要写代码 | 单元格颜色属性写表达式 |
| 查询条件控制列显隐 | 交互报表：列 `Visible` 写与参数相关表达式 |
| 动态列 | 横向/纵向扩展 |
| 小计合计 | 动态格间计算 |
| 主细表要写代码 | 交互报表或树型样式变通 |
| 展现后数据无法过滤组合 | 显示控件对**本地缓存数据**再过滤 |
| 数字大小写 | 显示值表达式做串/数字转换 |
| 公司级报表逐个定制 | 统一上报功能 |

**七大收益**：分离业务数据与展现形式（小计/合并/大小写不写进 SQL）；多源分片+动态格间计算缩短
周期；业务人员可做简易报表；上报统一；报表代码从单据模块剥离；推拉订阅；保存查询条件。
**建议**：《单位领料明细汇总查询》原三四天的单据改用引擎后**熟悉产品者半天完成**；润乾为 Java
产品、条件面板支持不够，**建议自主研发**；安排专人分步开发。
**风险**：只覆盖数据概念；查询条件构造 SQL、交互控制扩展、表达式解析、上报均未深入分析。

### 1.2 主要技术（p8-p11）

四项：报表引擎、表达式解释、控件开发、脚本语言扩展。两个核心概念：

- **多源分片**：一表数据来自多个业务实体（可能七八个乃至十几个），**设计时保持多个数据体不合并**。
  传统单源不分片要 JOIN（横向）+UNION（纵向也有分片），既难写又慢。
- **分片 ≠ 子报表**（原文）："子报表是某一种分片方法，但子报表与主报表并非一个整体，**不能互相
  运算**。这里说的分片，各片处于一个统一报表当中，可以互相运算。"
- **动态格间计算**：传统工具根本缺陷是"**没有很好的运算后报表数据命名机制**"（只能以列名命名
  设计期数据单元），故跨行跨组运算、随意独立格运算、引用报表外数据都做不了。

## 2. 概念体系与术语

| 术语 | 定义要点 |
|---|---|
| 合并单元格 | 以**左上角格编号**作为合并格编号；边框不能分段设置 |
| 属性值 / 属性表达式 | **互斥**。属性值设计期写死、运行期不运算；表达式运行期运算。属性表达式中用 `@value` 引用数据值 |
| 单元格数据类型 | 普通文字、统计图、图片字段、图片文件、**子报表**、空白单元格、HTML 文本 |
| 数据集 | SQL 二维表，或由业务对象获取 |
| 参数 | 作用于 SQL where/参数；有数据类型、缺省值、输入格式、最大宽度；可在数据集与表达式中引用 |
| 宏 | **无类型的字符串**，运行期文本替换，可出现在单元格值/表达式/数据集定义/属性表达式，写法 `${宏名}`（p51 处作 `%year`，两处记法不一致） |
| 可扩展单元格 | 数据值表达式**含集合函数**则默认可扩展，可改扩展方向；不含则默认不可扩展 |
| 横伸主格 / 纵展主格 | A 横向（纵向）扩展时 B 被同步复制，A 是 B 的横伸（纵展）主格，B 是 A 的附属格。**前篇 p16-17 称"上主格/左主格"，扩展模型章改称"横伸/纵展主格"，同一概念两次命名** |
| 00 格 | 找不到主格时的缺省根格；所有格最终都有主格。根坐标 `Cellx{00}` |

**设计器属性面板字段清单**（p1 截图 OCR，可直接作 designer-react 面板字段来源）：数据值 / 显示值 /
显示格式串 / 数据类型 / 扩展方向(默认·横向·纵向) / 纵展主格 / 横伸主格 / 格子可见 / 行后分页 /
列后分页 / 行可见 / 列可见 / **最少扩展**（不足 N 个补空行）/ **内容合并** / 允许排序 / 边界线宽。

**填报表**（p24，仅两条；作者明说 Delphi 版尚未实现）：
1. 填报表的**报表样式、扩展规则和普通报表完全一样**；
2. 额外增加：更新属性、自动计算、合法性检查、是否可写、编辑风格等属性。

→ 这是刻意的架构取向：**填报不是另一套模型，而是普通报表上的属性增量**（见 §9.6）。

## 3. 架构设计

### 3.1 总体组件图（p26）
`数据源 → 数据模型 → 报表管理/上报`；`报表设计器(Cell 方式)`；`报表调度 → 报表数据 → 报表显示`；
下挂 `扩展模型 / 表达式 / 交互模型 / 子报表 / 统计图`；输出侧 `控件 → Excel/Pdf/XPS` 与
`界面建模 → 报表打印 → 打印模型`。调度器、管理、上报、界面、分析标为"待扩充"。

### 3.2 产品三件套
- **报表设计器**：Excel 网格式编辑、横纵向合并、批量选中修改、剪贴板（复制自动调整公式）、
  多次 UNDO/REDO、动态更新引用单元格与表达式值；**自带运算引擎，可预览打印**。
- **报表服务器**（开放 API）：数据源——一表多源、多表共源、可适配多数据源；扩展模型——横纵向对称
  扩展、**常数序列扩展（如按 1-12 月）**、数据表直接扩展、分组扩展、**多级层次扩展（行列方向均可
  叠加）**、混合分片（固定与变动部分任意组合）；数据模型——**智能表达式（根据所处位置决定运算范围）**、
  表达式均可设条件、跨行跨组运算行列对称；单元格属性——显示格式、代码值↔显示值映射、属性表达式、
  斜线、固定图片与图像字段。
- **显示控件**：Web HTML、导出 PDF/EXCEL（含统计图）、带格式文本、预览打印、**支持显示不分页数据**。

### 3.3 架构目标与约束（p29）
可维护性/可扩展性：**扩展运算与分页独立实现**；扩充表达式即可提高运算能力；可构建多维分析应用。
可用性：**上万条记录**数据量、适用于 Web。易用性：技术人员用类 Excel 设计器，多维分析用专用设计器。
实现约束：与既有产品共用表达式引擎与语法、共用显示组件（原文脱敏为 Xxx）。

### 3.4 三种模型
- **用例模型**：5 用例——设计报表 / 浏览报表 / 预览打印报表 / 填报 / 多维分析；参与者——报表设计
  人员、用户、数据分析人员。另有"基础结构用例"（给每步加可用性/可靠性/性能/容错）与"扩展用例"。
- **分析模型**（三层）：应用层=设计器、打印预览；实体描述层=报表元数据、表达式引擎、数据源；
  基础结构层=**扩展运算引擎、分页引擎**。基本要求：注意扩展和运算效率；**外部定义数据源程序集、
  实现特定接口**；可扩充表达式；**报表文件以 XML 存储**；使用 ViewGrid 控件；轻量级预览控件。
- **设计模型**：`GRRDesigner`、`IGRPDataSource`、`IGRPPages`、`IGRPMetaData`、`【IGRP】Pager`、

## 4. 扩展模型（核心）

### 4.1 四条规则（p35/p41）
1. **扩展规则**：扩展时**主单元格或同级别单元格被拉大成合并单元格，附属单元格被复制**（横伸主格
   扩展→附属格横向同步复制；纵展主格→纵向同步复制）。
2. **引用规则**：附属格动态引用主格值，随主格扩展复制到不同位置，引用随之变化。
   例 `ds1.select(col1, col2=A2)`（A2 为扩展主格）。
3. **统计规则**：附属格用缺省聚集表达式时，**缺省统计所属主格区域内所有目标格**。例 `Sum(C3{})`。
4. 复制出的新格**所有属性都引用被复制格的属性**（属性共享，非深拷贝）。

**"拉大 vs 复制"判定**（文档两个反例）：① B2 横向扩展，B1 在其上方但 B1 非扩展格→B1 不是 B2 的
横伸主格；**B1 与 B2 的横伸主格都是 00 格 → 同级 → B1 被拉大**而非复制。② B2、B4 同为 B1 的
附属格 → 二者至少平级 → B2 扩展时 **B4 延展（拉大）而非复制**。

### 4.2 默认扩展方向判定顺序（p38，可直接编码）
单值表达式→不可扩展（**不可扩展格不能缺省做主格**）；集合表达式→可扩展；横伸主格横向扩展→本格
默认横向；纵展主格纵向扩展→本格默认纵向；主格为行首格→默认横向、列首格→默认纵向；**以上都不
满足→默认纵向扩展**。

### 4.3 主格认定五步递归（p41-p42）
**横伸主格**（向上依次查找，当前格 B3、上方格 B2）：
1. 当前格显式设了横伸主格属性 → 取设定值；
2. 未设 → 检查上方格 B2 是否**横向扩展格且列范围内包含当前格** → 是则 B2 即横伸主格；
3. B2 非横向扩展格 → 检查 B2 的横伸主格，**当前格跟随 B2**（共主格）；
4. B2 的横伸主格认定回到步骤 1 递归；
5. 到首行仍无 → **缺省 00 格**。
**纵展主格**完全对称，改为**向左依次查找**，查"是否纵向扩展格且行范围内包含当前格"，到最左仍无
则为 00 格。
→ "显式优先 → 相邻可扩展格 → 跟随相邻格 → 递归 → 落到 00 格"是本档最可直接移植的实现级内容。

### 4.4 绝对层次坐标
```
Cellx[Lk:Ik, Lk-1:Ik-1, ..., L1:I1 ; Lk':Ik', ..., L1':I1'] {条件}
       └──── 纵展主格链（分号前）────┘  └── 横伸主格链（分号后）──┘
```
- `Lk` 为 `Cellx` 的纵展主格，`Ik` 为其扩展后次序（从 1 起）；不指定或 `Ik=0` = 当前格所属当前主格。
- 目标格 `Cellx` 必须是 `Lk..L1` 的附属格。
- **只有横伸主格时分号不能省略**（`Cellx[; Lk':Ik', ...]`）；**只有纵展主格时分号可省略**。
- ⚠️ 内部矛盾：p19 说"`Lk` 次序从近到远（离当前格最近的主格开始）"，p43 说"从远到近"。**必须选定一种写死**。
- ⚠️ `{}`/`[]` 在 OCR 中大量混用（`C2(A2:0,B2:0){}` 与 `C2[A2:0,B2:0][]` 并存）。按文末规则
  "**表达式最后面跟花括号表示集合**"，应统一为 `[]` 包坐标、`{}` 表集合。
- 例（A2 纵向扩展出 a2/a7，B2 附属扩展出 b2/b4/b7/b10）：`C2[A2:0,B2:0]` 写在 d4 → 所属 A2 分组=a2、
  B2 分组=b4 → 表示 **c4-c6**；`C2[A2:2,B2:1]` → a7 区内第一个 B2 = b7 → 表示 **c7,c8,c9**。

### 4.5 相对层次坐标（位移坐标）
`Cellx[Lk:±lk, ..., L1:±l1 ; Lk':±lk', ...]`，`lk` 为偏移量（当前主格上/下、左/右第 N 格），不指定
即当前主格。用于同期比、比上期、环比。等价式：`B2[A2,B2] = B2[A2:±0,B2:±0] = B2[A2:0,B2:0] = B2`。
`C2[-1]` = 离当前格最近分组格之前偏移一位的分组格覆盖区中的 C2。

### 4.6 条件表达式与三个运算符
- 条件表达式 `Cellx{坐标}[EXP]`，**条件一律用中括号**，返回 true/false；空括号 = 该坐标下全部目标格
  集合。例 `avg(B1[B1<60])` 求不及格平均分。
- **`&`**：`&Cellx` 返回**当前格位于该主格中的第几个位置**。例 d4 格 `&A2=1, &B2=2, &C2=1`；
  d12 格 `&A2=2, &B2=2, &C2=3`。→ 做"序号列"的标准写法。
- **`?`**：解决"目标格主格与当前格主格扩展前同名"的歧义。`?Cellx` 指**写表达式的当前格**的某主格；
  不加 `?` 指目标格的主格。例 `=B1{?A1=A1-3}`：当前格所属 A1 主格值 = 目标 B1 所属 A1 格值减 3。
- **根坐标**：`Cellx{00}` 返回 00 格下所有目标格集合。典型占比 `=C2/sum(C2{00}[])`。
- 命名：列 A/B/C…、行 1/2/3…，格 = 列名+行名；一格最多两条斜线，此时数据值用逗号分隔。

### 4.7 数据级函数（p23-p24）
```
datasetName.select    (selectExp {, descExp {, filterExp {, sortExp}}})
datasetName.group     (selectExp {, descExp {, filterExp {, sortExp}}})
datasetName.select_one(selectExp {, filterExp})
datasetName.sum       (selectExp {, filterExp})
```
`descExp` true 逆序 / false 正序；`filterExp` 过滤；`sortExp` 排序依据。其余为集合/日期/字符串/数学函数。

## 5. 数据模型：操作符与系统变量（p50-p52）

| 记号 | 含义 | 示例 |
|---|---|---|
| `:` | 矩形区域（两对角点），可作 sum/max 参数 | `A1:D5` |
| `in` / `to` | 属于集合 / 生成数组 | `A1 in (1,2,3)`；`1 to 5` ≡ `[1,2,3,4,5]` |
| `.` | 字段 | `IRKD.RKDID` |
| `[]` | 过滤 / 取位置 | `CKD.CLID[DJ>10]`；`CKD.CLID[2]` |
| `[]`+排序 | **仅数据集支持排序，单元格不支持** | `CKD.CLID[CLMC ASC; CLJG DESC]` |
| `{}` | 层次坐标；加 `[]` 取该坐标下全部目标格集合 | `C5{A5:1}` / `C5{A5:1}[]` |
| `@value @row @col` | 当前格值、当前行列号 | |
| `@DRow @DCol` | **设计期**行列（扩展前） | |
| `@pageIndex @pageCount` | 当前页码 / 总页数（分页阶段求值） | |
| `@2000-1-1'` | 日期字面量（`@` 为首字符） | |

**表达式计算分两阶段**（p51，重要）：分为**扩展期间计算**与**分页期间计算**；与页眉相关的表达式
（页码、页数）在分页阶段算，**系统自动判断阶段**。
**约束**：页统计表达式只统计单元格集合表达式，**不能影响扩展过程**。

典型用例（p52）：`&A1`（序号）、`ds1.id[type=B1]`（数据集条件引用扩展格）、`avg(B1[B1<60])`、
`C2/sum(C2{00}[])`（占比）、`Count(B2{00}[B2>$B2])+1`（排名）、`C2+D2[-1]`（累计 / 比去年同期）。

## 6. 算法说明（p53，文档中唯一的实现级伪代码）

### 6.1 单元格变量（求单个目标格）
1. 未设左主格和上主格时，先**查找目标格与当前格的共同左主格 `l` 和上主格 `t`**；
2. 若左主格的**源格**即目标格 → 返回左主格 `l`；上主格源格即目标格 → 返回上主格 `t`；
3. 若左主格源格 `L` 是目标格的**直接**左主格 → 在 `l` 的附属格中查找匹配的格 `c`；若 `c` 的上主格
   属于 `t` → 返回 `c`；上主格侧按对称方法查找；
4. 若 `L` 是**间接**左主格 → 在 `l` 的附属格中查找"是目标格递归左主格"的格 `c`，**把左主格设为 `c`
   再次调用步骤 4**，直至满足条件 3 转而调用 3 取值。

### 6.2 单元格列表（求目标格集合）
与 6.1 同构，步骤 3 增加扩展处理：
> 在 `l` 的附属格中查找匹配的格 `c`：**若 `c` 不是扩展格**且上主格属于 `t` → 返回 `c`；
> **若 `c` 是扩展格 → 在 `c.ExtCells` 中查找上主格属于 `t` 的单元格列表**；
> 若无符合的格，则按步骤 3 从上主格重新查找并返回。

**实现暗示**：单元格对象需具备 **源格（设计期格）/ 左主格 / 上主格 / 附属格集合 / `ExtCells`（扩展
实例列表）**。`ExtCells` 是文档点名的字段，说明实现采用"**设计期格 + 运行期实例列表**"的双层结构，
而非直接摊平成二维表——与"新格属性引用被复制格属性"的共享语义一致。求值核心动作是：
**求两格共同主格 → 沿主格链递归下降 → 在 `ExtCells` 中按另一主格过滤**。

## 7. 图形模型（p54-p56）
统计类型：折线图、纵向/横向柱形图、面积图、散点图、饼图、快速折线图、横向折线图、横向面积图。
统计图以**单元格数据类型**形式挂在格上，X/Y/Z 轴由单元格 Notation 表示，**不加 `[]`（不表集合）**。
图片三类：页面背景图（每页相同）、单元格背景图（扩展出的格背景图都一样）、单元格图片内容（DB 图片
字段如 `employee.photo`）。图形样式：**None / 拉伸 / 平铺**。实现：Delphi + **TeeChart**。

## 8. 打印模型（p57-p61）

### 8.1 九类带区语义

| 带区 | 扩展 | 分页行为 |
|---|---|---|
| 页眉区 | — | 每页都有（第 X 页/共 X 页、工程名、公司名） |
| 标题区 | **可引用数据区格，但不参与扩展和复制** | — |
| 表眉区 | — | 标题与表体之间，分页每页重复 |
| 表头区 | **参与扩展** | 分页每页重复、分栏每栏重复 |
| 数据区 | 可自由扩展复制 | — |
| 表脚注 | 可引用数据区格，**不参与扩展复制** | 最后一页数据最后一行显示 |
| 页统计 | — | 统计**每页**数据，每页都有，可引用数据区格 |
| 表统计 | — | 最后一页最后一行显示 |
| 页脚区 | — | 每页都有（页码、作者、日期） |

自动折行：标题、页统计、表统计**不折行**；表头、表脚等可折行。

### 8.2 打印/分页参数（含默认值，可直接作配置项）
剩余页面用空行填充(否)｜单元格大小自动适应(是)｜允许横向拆页(横表才允许，默认不可用)｜
允许纵向拆页(纵表才允许，默认不可用)｜数字自动折行 / 数值 0 输出为空 / 空字段输出为"-"(均否)｜
打印时启用套打(否)｜边框线宽 1 / 颜色黑｜多栏打印(否) / 栏距[10,1000] 初始 0｜
**页末空隙处理：不处理 / 合并到末尾 / 平均分配 / 按比例分配（默认按比例分配）**｜
**分页方式：按纸张尺寸 或 按数据行数**｜每页显示数据行数｜**打印布局行数/列数/顺序**（一张纸打多页
报表，顺序=先横向或先纵向）｜页眉页脚每页都显示 or 一张纸只显示一次｜行高列宽单位（像素/毫米/英寸）。
另有两个面向合并格跨页的专门开关：**分页断开时值重复显示**、**合并格可分两页显示**。

## 9. 交叉表示例与工程细节

**交叉表（p62）**：数据集 `orders`（`FloorName / EntType / Diameter / Weight`），按"楼层 × 构件类型"
统计钢筋总重。`A3=Group(Floor.FloorName[])`（纵展主格）→ `B3=Group(Floor.EntType[])`（附属）→
`C3=sum(...)`；小计行 `C4=Sum(C3[])`（缺省统计所属主格区）；末行 `B5=Group(Floor.EntType[])` 作
"全部层汇总"，**主格设为 00 格**脱离楼层分组。变体：`Group(Floor.Diameter[])` +
`sum(Floor.Weight[Diameter<>10])`。要点：**同一 Group 表达式，改主格属性即从"分组内小计"变"全表汇总"**。

**工程细节**：报表定义以 **XML** 存储；部署 Client（设计器/预览）→ 报表服务器（扩展运算+分页+
表达式+数据源）→ DB；导出 HTML/PDF/Excel（含统计图）/带格式文本/XPS。
**表达式引擎选型**（附录二）：推荐 **Flee**（.NET，LGPL）——**把表达式直接编译成 IL**
（`DynamicMethod` + 轻量 codegen）→ 极快；不产生常驻动态程序集、IL 可被 GC 回收；支持自定义变量、
短路逻辑、集合索引；`CalculationEngine` 支持表达式间引用与按自然顺序重算。首要选型标准是"报表计算
要算很多次，效率是重要考虑因素"。另一线索：作者早期用 **ANTLR** 写过表达式语法文件。
**性能目标**仅"上万条记录"与"轻量级预览控件"。附录三（分析能力 8 级：标准报表→即席查询→多维分析
→警报→统计分析→预报→预测型建模→优化）用于界定报表引擎只覆盖 1-3 级。附录一总结：实现报表引擎只需
**表达式引擎 + 扩展模型**两个核心技术。

## 10. 差异化与可借鉴点

1. **主格认定五步递归算法**（§4.3）。润乾/蒋步星资料多只讲主格概念与效果，本文给出可逐条编码的
   判定顺序，含"跟随相邻格""落到 00 格"两个兜底。这是"用户不配主格也能跑对"的关键，建议
   print-server 直接照搬。
2. **`ExtCells` 与源格/实例分离**（§6.2）。配合"新格属性引用被复制格属性"，可实现属性共享，避免
   万行级报表的属性复制开销。
3. **两阶段表达式求值 + 扩展与分页引擎分离**（§3.3/§5）。架构级决策，直接导出"页统计不能影响扩展
   过程"的约束；不先定这条，分页很容易反噬扩展结果。
4. **缺省聚集 = 所属主格区域**（§4.1 统计规则）与 **"拉大 vs 复制"由主格链是否同级判定**（§4.1
   反例）。前者让"小计格"零配置正确，后者比按几何位置猜健壮得多。
5. **填报表 = 普通报表 + 属性增量**（§2）。明确拒绝为填报单建模型，差异收敛为单元格属性 + 回写
   规则。对我们设计填报能力的取舍有直接参考价值。
6. **明确定性"子报表不能互相运算"**（§1.2），选"统一报表内多源分片"为主路径；但单元格数据类型里
   仍保留子报表——并未彻底否定，只是不作为组合复杂报表的主路径。
7. **打印带区矩阵与分页参数表**（§8）可直接抄进配置 schema，尤其"页末空隙处理 4 策略、按行数分页
   + 打印布局行列/顺序、合并格跨页两条开关"。
8. **设计器属性字段清单**（§2）可作 designer-react 属性面板来源，"最少扩展""内容合并"易被忽略但实用。

**需自研时拍板的坑**：层次坐标 `Lk` 书写次序（p19"从近到远" vs p43"从远到近"，自相矛盾）；
`{}`/`[]` 分工；宏 `${}` 与参数 `%year` 两种记法；术语"左/上主格"与"横伸/纵展主格"二选一。

**文档缺失**：无性能方案（只有"上万条"目标值）、无缓存/增量重算设计，填报与上报仅停留在属性罗列。
