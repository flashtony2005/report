非线性报表计算引擎架构设计（v2 · 工程深化修订版）

v2 · 针对 7 类高风险评审问题的可落地架构蓝图

修正 v1 中 4 个不成立假设（全量物化、坐标 O(1)、表达式哈希缓存、静态 DAG），并把有限 / 交替扩展、并行、分页、填报提升为可执行的约束与算法。

v1 是理论提炼 + A1–A16 工程骨架；v2 针对架构评审发现的 7 类高风险问题做深入分析与方案修订，修正 v1 中 4 个不成立假设（全量物化、坐标 O(1)、表达式哈希缓存、静态 DAG），并把有限 / 交替扩展、并行、分页、填报从"伪代码"提升为可执行的约束 + 算法。理论推导仍以《非线性报表设计详解》为准。

一、概述与定位

非线性报表引擎核心命题：给定一张以单元格为单位的模板 + 若干数据集，自动生成任意布局（清单 / 分组 / 交叉 / 自由 / 主子 / 填报）的实例报表。与传统"线性报表引擎"的根本差异：单元格是第一公民，每个单元格都可独立成为"主格"向外扩展，引用通过"层次坐标"而非固定节区变量完成。

  • 第一公民：Cell（而非数据行 / Section）；
  • 两大原语：扩展 Expand（主格按数据复制成矩形带）、引用 Reference（层次坐标取其它格值）；
  • 三大保证（理论层）：停机、封闭、可计算；
  • 默认安全子集：实报表 / (满)正实报表 / 整报表（理论已证明扩展可交换、结果与顺序无关）；非实报表需要显式指定扩展顺序；
  • 五模型（润乾官方）：展现 / 数据 / 运算 / 子报表 / 填报表，全部已在"详解"版并入。

二、总体分层架构（v2 修订）

自下而上六层（v2 在 v1 五层基础上新增"实例化控制"职责）：

  1. 模型层 Model：展现 / 数据 / 运算 / 子报表 / 填报表五模型；模板对象（TemplateCell）与实例对象（InstanceNode）分离；
  2. 解析层 Parse：Template Parser · Master Analyzer（主格树）· Dataset Loader · Template Validator（新增：主格循环、跨带合并格、符号循环静态校验）；
  3. 引擎层 Engine（核心）：Expand Engine（虚拟扩展 + 实例索引）· Expression Engine（层次坐标求值）· Dependency Resolver（静态 + 动态）· Fill Engine；
  4. 实例层 Instance：InstanceIndex（实例身份）· OffsetIndex（物理偏移）· 三档物化策略（Virtual / Meta / Full）；
  5. 调度层 Schedule：Cache Engine（上下文敏感三级缓存）· Parallel Scheduler（三阶段并行）· Cycle Detector（静态 / 动态）；
  6. 渲染层 Render：Stream Band Iterator（流式带迭代）· Page Engine · 导出 HTML / Excel / PDF。

v2 关键变化："实例表"不再是一张物化表格，而是"实例索引 + 按需求值 + 流式输出"；分页与渲染从引擎尾部变成引擎外的独立布局子系统。

三、核心对象模型（v2 修订）

以 Cell 为中心，但明确区分模板格（设计时）与实例格（运行时）：

struct TemplateCell {
    id: CellId,
    row: i32, col: i32, rowspan: i32, colspan: i32, // 模板坐标与合并范围
    xp: Option<CellId>, yp: Option<CellId>,         // 左主格 / 上主格
    expr: Option<Expression>,                        // 如何产生结果
    role: CellRole,                                  // 普通 / 维度 / 数值
    upd: Option<UpdateSpec>,                         // 填报回写定义
}

struct InstanceNode {
    id: InstanceId,
    template: CellId,
    master_path: Vec<(MasterId, Ord)>,   // 主格线 + 同束号（逻辑身份，稳定）
    value: Option<Value>,                // 惰性求值，可驱逐
    state: CellState,
}

struct Report {
    template: Vec<TemplateCell>,
    masters: MasterGraph,       // 主格树 / 同束
    expressions: ExprGraph,     // 静态依赖 DAG
    instances: InstanceIndex,   // 实例身份 → 物理位置 / 值缓存
    data: DataContext,          // 数据集 + 版本号
    layout: OffsetIndex,        // 行 / 列物理偏移索引
}

设计要点：

  • 身份与坐标解耦：InstanceId 一旦生成即稳定；物理坐标变化（如新增数据导致下移）不改变实例身份，因此值缓存不会因布局变动整体失效；
  • 模板不保存实例结果：TemplateCell 只有"如何产生"；InstanceNode 按需创建、按带求值、可驱逐；
  • 三大图：MasterGraph（主格树 / 同束）、ExprGraph（静态依赖）、InstanceIndex（实例身份）+ OffsetIndex（物理布局）。

四、模板解析与主格分析

解析层把模板转成对象图并构建主格树：根 @，每个有 xp / yp 的单元格挂到父格之下。BuildMasterTree：O(N) 遍历单元格按 xp/yp 挂父子，同时算深度得扩展队列顺序。

v2 新增 Template Validator（A25），解析期即拦截不可实现模板：

  • 主格循环（xp / yp 成环）→ 报模板错误；
  • 跨两条扩展带的合并格 → 一期直接报错（§10 约束）；
  • 符号循环引用 → 静态环检测并给出环路径；
  • 扩展方向冲突（横主格有左主格、纵主格有上主格等）→ 按润乾规则校验。

五、扩展引擎（v2 修订：虚拟扩展）

v2 中"扩展"的语义是：在 InstanceIndex 上登记主格实例记录，而不是物理复制单元格几何。每个主格实例记录：

struct MasterInstance {
    master: MasterId,
    ord: Ord,                 // 同束号
    row_set: RowSet,          // 数据集行集 / 维序列成员
    children: Vec<MasterInstance>,
    band: Option<BandId>,     // 所属扩展带
}

三档物化策略：

策略内容适用
Virtual只有主格实例记录；实例格值按需求值、用完即弃默认；大报表、在线预览
Meta实例记录 + 值节点缓存（L1），逐带驱逐交互式翻页、填报
Full全量物化（受预算上限约束，超限自动降级）小报表、全量导出

复杂度修正：扩展调度 O(M) 只覆盖"调度"；实例登记输出 O(I)（I = 主格实例数）；不产生 O(输出格数) 的物理格。输出格数只在渲染 / 求值时按带出现。

增量扩展（A3 修订）：新增数据 → 叶子主格追加实例记录 + OffsetIndex 区间加 + 脏标记传播；只重算受影响 DOMB 及其下游，复杂度 O(size(DOMB) + 偏移级联)。

六、坐标系统与物理定位（v2 新增）

逻辑身份：实例格 = (TemplateCellId, master_path)，其中 master_path 是主格线各级 (MasterId, Ord) 序列；层次坐标表达式先解析为主格路径，再翻译为物理坐标。

物理定位两分支：

  • 均匀扩展带（各实例高度相同）：y = band_start + (ord - 1) × height + local_row，可 O(1)；
  • 非均匀扩展带（嵌套 / 交替，子带高度因数据而异）：
height(inst) = base_height(inst) + Σ height(child_inst)
物理偏移(inst) = 本带起点 + 前面所有兄弟实例高度累计 + 内部子实例偏移

Offset Index（A18）：用 Fenwick / 平衡树维护稀疏行、列槽位：

  • 点查：O(log N)；区间加（整带增高）：O(log N)；
  • 增量级联（A19）：新增 / 删除叶子实例 → 祖先路径逐层区间加，O(k × depth × log N)；
  • Layout Version：布局版本只使依赖平面函数 / 物理位置的节点失效；纯值依赖不受坐标移动影响（身份不变）。

修正结论：v1 的 A11 O(1) 仅对均匀带成立；一般情形为 O(depth × log N)。

七、计算与依赖引擎（v2 修订：静态 + 动态）

v1 假设"单元格只能引用其它格值 → 天然 DAG → Kahn 一次拓扑"。该假设对 eval()、平面函数、嵌入式子报表不成立。v2 采用双图 + 脏标记：

  1. 静态依赖图（模板级）：解析期按表达式静态扫描构建，Kahn 求主计算顺序并做静态环检测（报模板错误，含环路径）；
  2. 动态依赖注册（A22）：eval()、平面函数、动态表达式在求值时把实际引用注册为实例级依赖边；新边产生后重算下游（脏标记传播 A21）；
  3. 平面函数屏障：row() / cols() / range() 引用"所有未扩展格"，标记为全量依赖；求值策略是"先完成普通节点，再对该区域快照串行求值"，不做虚假并行；
  4. 两类循环引用：
  • 静态环：模板校验期报错（A1 → B1 → C1 → A1）；
  • 动态环：运行期检测，报实例级路径（A1[P:3] → B2[Q:1] → A1[P:3]），并标记该实例不可计算；
  1. 结果版本：每个实例节点版本 = max(自身数据版本, 上游版本)；脏传播按版本比较跳过无效重算。

八、缓存体系（v2 修订：上下文敏感键）

层级v1 键v2 键说明
L1 CellCachecell_id → valueInstanceId → value身份稳定，坐标变化不失效
L2 ExprCachehash(expr)H(expr 指纹, 基格 master_path, pdr 行集指纹, data_version)同一表达式不同上下文分桶
L3 BandCachemaster_version → 实例片段(master_id, data_version, filter 指纹, child_layout_version)子布局变化才重建带

失效模型：全局版本向量 (data_ver, expr_ver, layout_ver)；任一变化沿依赖边传播。layout_ver 变化默认不触发值重算（仅平面函数依赖者例外），这是身份 / 坐标解耦的收益。

复杂度修正：命中 O(1)；L2 键构造 O(depth)。v1 的 "L2 = hash(expr)" 是错误实现，必须废弃。

九、并行策略（v2 修订：三阶段并行）

v1 的 O(N/P) 只在"纯计算 DAG、无共享写入"的理想场景成立。v2 分三阶段，明确并行边界：

阶段工作并行模型正确性约束
P1 扩展主格实例登记 + OffsetIndex 更新串行主路径（先横后纵）；仅互不相交主格子树可并行实例索引写锁分段，避免全局坐标竞争
P2 计算表达式按 DAG 求值每波取入度 0 节点批量并行平面函数 / 动态 eval 节点形成屏障
P3 渲染带流式输出 / 分页与 P2 流水线重叠（算一批、渲一批）分页按带顺序消费，不随机访问

复杂度修正：每波 O(ready/P)；总耗时 = Σ 波次，受关键路径约束；实际并行度收益取决于表达式占比，不与模板规模成正比。

十、有限扩展与交替扩展（v2 修订：形式化）

v1 的 A10 / A12 只给出均匀堆叠公式，无法表达"客户（纵）→ 订单（横）→ 商品（纵）"这类实例高度逐客户不同的交替布局。v2 定义：

struct ExpandNode {
    master: MasterId,
    direction: ExpandDirection,   // Vertical / Horizontal
    band: BandRect,               // 本节点模板带
    children: Vec<ExpandNode>,
}
  • 实例树：递归展开 ExpandNode 得到 MasterInstance 树；实例身份与物理布局分离；
  • 递归带高：height(node_instance) = base_height + Σ height(child_instance)，宽度对称；
  • 交替坐标：沿实例树递归累计行 / 列偏移——方向为 Vertical 时累加行，Horizontal 时累加列，最终二维坐标 = 两条路径的叠加；
  • 跨带合并格约束（A25）：合并格不得横跨两条不同扩展带；一期模板校验直接拒绝，避免"撑一个填一个"尺寸错乱（对应原书定理 2.4 的注意事项）；
  • 相邻格撑大：只作用于整带（整带增高），由 OffsetIndex 统一区间加，不逐格处理；
  • 与开放问题的关系：原书把"有限扩展 / 交替扩展 / 分页"列为未解决开放问题；v2 以"实例树 + OffsetIndex + 约束校验"给出工程决策，而非声称已证明。

十一、分页与渲染（v2 修订：独立布局子系统）

v1 的分页三件套假设已有全量实例表。v2 改为流式分页：

  1. Stream Band Iterator（A24）：按主格扩展序产出带序列，一次只持有一个带；
  2. Page Layout Engine（A14）：used + band.height ≤ page.height 则装入，否则开新页；
  3. Band Split（A15）：跨页时记录 continuation 游标 (band_id, 行偏移, 合并格拆分策略)；策略 A 整块移下页（保真、留白），策略 B 按行边界切分 + 合并格续块（紧凑、复杂）；
  4. Repeat Header（A16）：新页克隆页头带；横向分页独立处理列，页头 / 分页伸缩由布局引擎负责。

导出：HTML 流式；Excel 稀疏行写入（如需公式，输出平面计算串）；PDF 复用同一布局树。分页与导出是独立子系统，不并入核心计算引擎。

十二、填报表（v2 修订：范围与工程化）

  • 一期范围：显式字段名 / 对象名（不做自动分片启发式）；方向判定沿用 v1 规则（左 / 上有扩展格则延用，否则右 / 下有无数值格，默认纵向）；
  • 动态增删：仅限叶子主格的完整扩展带（原书规则 4.6），由扩展引擎增量接口处理；
  • 回写：DataPort 抽象（不绑定 SPL）；事务 + 乐观锁 + 行级校验；失败回滚到实例快照；
  • 采集：基于 InstanceIndex 而非物化格，"先扩展后采集"；
  • 二期：自动分片 / 序表识别，需要 golden 测试集校准启发式规则。

引擎复杂度低高

结论：非线性引擎在表达能力上严格覆盖线性引擎（任何线性报表都能用"单行主格纵向扩展"退化实现）；但引入主格图与层次坐标后，解析、调度与物化控制复杂度更高，v2 的全部修订都是为了在保证正确性的前提下把这种高表达力工程化。
