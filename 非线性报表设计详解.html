非线性报表模型与设计详解

基于《非线性报表模型原理》（蒋步星，2007，润乾报表理论基础）逐章重构 · 算法 + 形式化定义 + 图示

单元格为中心 · 扩展 + 引用 · 可证明停机 / 封闭 / 可计算

一、为什么需要非线性报表模型（设计动机）

传统报表工具采用线性报表模型：源自数据库理论——先对数据集做分组/聚合，再把结果"填入"布局简单的表格。其重心在"数据集运算"，而"单元格 / 表格布局"被严重弱化，难以描述合并单元格、不规则分片、交叉表、套表等复杂样式，也无法灵活表达相对引用 / 层次引用，填写（回写）几乎空白。

核心思想：把"单元格"提升为理论体系的第一公民，数据集退化为"提供数据来源的从属属性"，几乎所有变换与计算都以表格（单元格网格）为主体。由此用一套统一的"扩展 + 引用"机制描述绝大多数复杂报表，并可在理论上证明停机性、封闭性、可计算性。

二、数学基础（原书第 1 章）

模型建立在严格的集合论与函数论之上。下列概念是后续一切算法的前提。

2.1 集合、数组、矩阵

  • 集合 {…}：|X| 元素个数；A⊆B、A∪B、A∩B、A\B 为并/交/差。
  • 数组 (a₁,a₂,…,aₙ)：有限集按序排列的序列；相等要求长度与成员次序完全相同。
  • 叉积 X₁×X₂×…×Xₙ；矩阵：由多个 n 元组构成的数组（行数=成员数，列数=成员长度）。

2.2 四种基本变换符号（算法的基本动作）

符号含义
S += a把 a 加入集合/数组 S（数组缺省加到末尾）
S -= a从 S 中删除 a
a → b上下文中所有含 a 的集合把 a 替换 为 b（保持数组次序）
a → x上下文所有含 a 的集合先 S -= a；若 S 是 n 元组则递归 S → x
注意：a → x 是"删掉以 a 为元素的集合"，不是替换 a 本身；有限上下文必在有限步停止。

2.3–2.5 函数、表达式与属性

  • 聚合函数：参数本身是集合的函数，如 sum(X)、min、max、avg。
  • 集合函数：返回值都是数组的函数，如 list(v₁,…,vₙ)、to[q](n,m)。
  • 计算串：内容为表达式的字符串；eval(x) 把计算串当表达式计算（结果仍可能是计算串，可再 eval）。
  • 属性即函数：属性 p 定义为 X×Y 的子集且无两元素同左元；x.p（或 p(x)）即 x 的属性值；属性表达式的计算结果才是属性值。
关键区分：聚合函数 ≠ 集合函数。集合函数是"报表自动化"（一个单元格可展开成一组）的基础；聚合函数处理统计运算。二者对建模都至关重要。

三、表格与报表的形式化定义（原书第 2 章）

3.1 网格、表格、单元格

网格 T：以 N×N 为定义域的可逆函数 e，T = { e(r,c) | 1≤r≤n, 1≤c≤m }，即 n 行 m 列网格，元素称元素格，|T|=n·m。

表格：为网格 T 设一个由 T 上矩形构成的有限集 UG[T]（矩形 = 任意两格之间的元素格都包含在内），且单元格两两相离。元素称单元格。

元素格 坐标锚点 合并格 (|U|>1) 辖区
图 2　网格由元素格构成；多个矩形（两两相离）即为单元格；合并格 |U|>1。矩形引理：单元格必可写成 M(a,b,c,d)。

3.2 原序、最前格、跟随格、单元格数组

对单元格 A,B：若 row(A)<row(B) 或（行号相同且列号更小），记 A<B，称原序。

定理 2.2：原序具有可序性（任意两格必有 A<B 或 B<A）与传递性 → 所有单元格可排成一个数组，即单元格数组 UG[T]。最前格通常 U(1,1)，跟随格即紧邻其后者。"按原序遍历每个单元格"即从最前格沿跟随格递推。

3.3 基本变换算法

算法 2.1 / 2.2　表格行列增删

  • 增加行（第 k 行后加 1 行）：E(i,j) → E(i+1,j)（k<i≤n）平移下方元素格；补入新行；若某单元格同时跨 R(k) 与 R(k+2)，把它向新行"撑大"。
  • 删除行（删第 k 行）：先删仅在该行的单元格；E(k,j) → x；E(i,j) → E(i−1,j)（k<i≤n）整体上移。
定理 2.3：对任一表格执行增/删行列后仍是表格（UG 仍由两两相离的矩形构成）。

算法 2.3　子表引入

允许单元格 X.val 是另一张表格 S（子表）。过程：① 撑大——若子表行列数更大，先在宿主对应位置加行列，把跨越的子表格撑到同尺寸；② 填入——按偏移 E[T](a+i−1,b+j−1) 逐个加入宿主 UG 并复制 val。

关键约束：必须先把所有子表格都撑大、再统一填入；若撑一个填一个，会把已填入的子表单元格再次撑大，导致尺寸错乱。该算法处理"有限扩展""交替扩展"等纯靠扩展算法搞不定的复杂表。

  • 包含带：扩展格 P 的连续行(列)集 B，使 DOMB[P] 中所有单元格都落在 B 内。
  • 扩展带 B[P]：P 的所有包含带的交集。纵主格的扩展带是连续行集，横主格是连续列集。
定理 2.6：扩展带是非空连续行/列集；子格的扩展带是 P 扩展带的子集；不在任何扩展带内的单元格，其左/上主格为 @。空心带：扩展带内某行与 DOMB[P] 无单元格相交，则该行是空心行，必在带中部。

3.7 自动主格设置（算法 2.4）

逐格设主格繁琐，书中给出自动主格设置算法：对每个未设主格的单元格，在它左（上）边、同行（列）里找第一个"更大（不小于）"的单元格设为它的左（上）主格。

算法过程：先按原序处理所有纵主格（设左主格），再按原序处理所有非主格；每个单元格在左侧交行集中、在"扩展格集合 X 或非主格已设主格集合 Y"中取列号最大者 W：若 W∈X 则 U.xp=W，否则 U.xp=W.xp；空集则 U.xp=@。上主格对称。定理 2.10：对临时报表执行后必成报表。

"扩展"是把源表（模板）生成为实例表（结果）的过程，由三个层层递进的算法构成：

4.1 算法 3.1　扩展带复制（基础原子操作）

输入：报表 T 上纵主格 P，其扩展带 B[P]=R(p,q)，k=|B[P]|=q−p+1。

  1. 对与 B 交叉且与 R(q) 相交的单元格 U，截断为 V={E∈U | p≤row(E)≤q}（去掉超出扩展带的部分）；
  2. 在第 q 行后加入 k 行（执行 k 次算法 2.1）；
  3. 对与 B 相交的单元格 U：若 U∈DOMB[P]，U 与新复制部分 U' 合并；否则把复制部分 U' 作为复制格加入 UG，并 U'.val=U.val；
  4. 对 P 的每个属格/子格的复制格，递归设置其 (左/上) 主格 = 原主格的复制格。
定理 3.1：复制后仍是报表。定理 3.2（单元格变迁）：复制后继承格及其复制格的列号、列数与原格相同；行号/行数相同的单元格其继承格与复制格对应相同。横扩展带复制对称。

4.2 算法 3.2　主格扩展（把一次复制推广到 n 份）

规则 3.1：未扩展格的格值必为非空数组（单值视为 1 元组，空值视为含 NULL 的 1 元组）。

过程（对未扩展格 P）：① 计算 P.val 得数组 (v₁,…,vₙ)，n≥1；② 置扩展状态为真；③ 连续对 P 执行 n−1 次扩展带复制，产生 P₂,…,Pₙ；④ 令 Pᵢ.val=vᵢ。→ DOMB[P] 中每个单元格 U 产生 n 个导出格。

定理 3.5：主格扩展后单元格变迁（把定理 3.2 的 +k 推广为 +k·(n−1)）。推论 2（整报表重要）：整报表扩展后任何单元格的行数、列数都不变 → 可设计更高存储效率的实现。定理 3.6/3.7：纵主格与横主格的交辖区在扩展中一一对应——这是"层次坐标"合理性的根基。

4.3 算法 3.3 / 2.3　报表扩展（调度全部主格）

规则 2.2：主格扩展只能对"其主格已是已扩展格"的未扩展格执行。

算法：① 找一个可执行的未扩展格（其主格已扩展），找不到则结束；② 扩展它（算法 3.2）；③ 回到 ①。

扩展停机定理（定理 3.9）：对任意报表，报表扩展必在有限步结束，结束时无未扩展格。
扩展交换定理（定理 3.8，实报表核心）：对实报表，扩展两个主格已扩展的未扩展格 P、Q 可交换 → 结果不依赖主格选择顺序。因列数远少于行数，实践一般先扩展横主格、再扩展纵主格效率更高。
扩展封闭定理（定理 3.10）：报表扩展对实报表/(满)正实报表/整报表封闭且反封闭。非实报表不具交换性，结果依赖顺序（取原序靠前者）。

4.4 源格、同源、同束（实例表单元格的身份系统）

扩展把一张源表变成多张中间表，最终实例表单元格极多。书中建立三套"坐标"唯一定位它们：

  • 源格 src(u)：中间表单元格 u 在源表 T₀ 上的根（递归取原格的源格），@ 的源格是 @。
  • 同源 / 同源号 seq(p)=#p：同源格 = 源格相同的单元格；同主格的同源格按行(列)号排序后的序号。
  • 同束 / 同束号 ord(p)=&p：同束格 = 同一未扩展格的导出格（或其继承格），同源且同束。
定理 3.11/3.12：同源扩展格列(行)号相同、行(列)号互异；同束格同源号连续；同源扩展格同束 ⇔ 主格相同。这些是"层次坐标唯一性"的保证。

五、语法与引用机制（原书第 4 章）

源表在设计时写表达式，但计算时要引用"尚未存在"的实例表单元格。因此需要三种坐标系统。

5.1 层次坐标（最常用、最安全）

基格：表达式总是"相对某个单元格 c"计算，c 称基格。

对中间表单元格 c，C=src(c)：取左主格线 (P₀…Pₙ)、上主格线 (Q₀…Qₘ)，记 Pᵢ=src(pᵢ)、xᵢ=ord(pᵢ)，写成

C[P₁:x₁, …, Pₙ:xₙ ; Q₁:y₁, …, Qₘ:yₘ]（P₀=Q₀=@ 省略）。xᵢ/yⱼ 即 c 在主格 Pᵢ/Qⱼ 上的层次坐标（同束号，非 0）。

定理 4.1：层次坐标唯一标志单元格。定理 4.2：零层次坐标 ⇔ 只能引用到"基格导格的先辖区"内的单元格。位移坐标：相对基格 a，写成 +x / −x / 0，全 0 退化为零层次坐标。
图 10　层次坐标 = 源格名 + 沿主格线的同束号；唯一标志、且支持相对/位移引用。

5.2 线性坐标

用同源号 seq 代替同束号 ord 的坐标：C[x;y]（非主格）、C[x]（扩展格）。

定理 4.3：线性坐标唯一。定理 4.4：单层主格的层次坐标与其等价线性坐标一致（C[P:±x;Q:±y] = C[±x;±y]）。

5.3 平面函数（绝对方位引用）

不依赖主子关系的方位函数：rows()/cols()（总行列数）、row(c)/col(c)（行列号）、cel(c,y,x)=U(row(c)+y,col(c)+x)（特别 cel(@,y,x)=U(y,x)）、range(a,b)（记作 a:b，矩形区单元格集合，可 sum(a:b)）。

平面函数返回值会随进一步扩展而变化，计算时需特别处理（见 §6.2 隐含引用规则 5.2）。

5.4 数据源：数据集与缺省行集

数据集：由"数据数组"构成的矩阵，同列同类型；行=记录，列=字段（可起列名）。划分函数：select(x)、group(x)，派生 rselect/rgroup/select(x,fx,sx) 等。

缺省行集 pdr(p,ds)（规则 4.1）：递归——p=@ 用全表；已扩展且 p.dsr 有 ds 则用其行集；否则沿 p.pu 上溯。非主格 c 引用数据集时，缺省行集 = pdr(c.xp,ds) ∩ pdr(c.yp,ds)。

六、计算算法（原书第 5 章）

6.1 计算状态与可计算格（算法 5.1）

规则 5.1：单元格属性表达式只能引用其他单元格的格值（避免任意引用造成循环）。
  • 计算状态：已计算 / 未计算（@ 视为已计算）。
  • 可计算格：其主格线上扩展格均已计算、且表达式引用的单元格均已计算（或不存在）的未计算格。
  • 计算 c：扩展格则扩展之；非主格则算 c.val 并置已计算。
算法 5.1 报表计算：① 找可计算格 c，找不到则结束；② 计算 c；③ 回到 ①。计算停机定理（定理 5.1）：有限步结束（结束≠无未计算格，只保证无"可计算格"）。计算交换定理（定理 5.2）：两个可计算格计算可交换、计算同构；实报表结果与顺序无关。

平面 vs 线性：平面计算串适合"格式复杂但单元格少"；线性计算串适合"格式简单但容量巨大"（占用少、可实时计算）。纯线性计算串的整报表甚至可用于超巨报表以提升性能、减少存储。

九、关键性质与设计要点总结

  1. 一切以单元格为中心：网格→表格→单元格→扩展属性→主格树→扩展带→辖区，构成完整几何+代数结构。
  2. 三层扩展算法把"模板（源表）"确定性展开成"结果（实例表）"；对实/(满)正实/整报表封闭且可交换，结果与扩展顺序无关（实践先横后纵）。
  3. 扩展必停机（定理 3.9），计算必停机（定理 5.1），二者都可证明。
  4. 三套坐标解决"设计时写、运行时引用"的错位：层次坐标（唯一、安全、支持相对引用）、线性坐标（简洁）、平面坐标（弱环境友好）。
  5. 缺省行集 pdr 让交叉表的数据集引用"自动对位"，是表达式智能化的关键。
  6. 可计算性可静态判定：符号循环引用 ⇔ 无可计算队列 ⇔ 不可（静态）计算；运行时用"单次遍历"在 O(n) 失败试算内完成并定位循环。
  7. 填写三形态 + 两种计算串：平面（小而复杂）/线性（大而简单），覆盖自由式、行列式、交叉式及动态增删。
  8. 线性报表是交集真子集：非线性模型表达能力严格包含线性模型，但线性模型在"能用它描述的简单大报表"上时空效率更高——二者互补而非替代。

十、原文指出但尚未完全解决的开放问题

  • 布局：有限扩展（扩展带仅矩形而非整行/列）、交替扩展（纵主格有横子格）、分页处理；
  • 计算：格间关联模型与统计图、允许属性引用时的循环引用消解；
  • 填写：非叶子主格的动态填写、交叉动态填写（更新属性不只定义于主格）；
  • 实现：算法的高效工程化方案（如利用整报表"单元格大小不变"特性优化存储）。

十一、工程实现算法补充（新增 · 计算引擎架构）

以上内容（二–十）主要是理论算法：已建立"单元格第一公民""扩展 + 引用"的模型，并证明了停机、封闭、可计算等性质。但开放问题（§十）也指出，实现层仍缺"算法的高效工程化方案"。本章给出把非线性报表数学模型落地为非线性报表计算引擎所需的关键工程算法层，与前面的 2.x / 3.x / 5.x 理论算法一一对应。

11.1 报表内部对象模型算法

理论模型把报表拆成 5 个对象：Report → Grid / Cell / MasterGraph / ExpressionGraph / RuntimeContext。实际实现用扁平化的结构体承载：

struct Report {
    cells: Vec<Cell>,        // 单元格数组（原序）
    masters: MasterGraph,     // 主格树
    expressions: ExprGraph,   // 表达式依赖图
}

struct Cell {
    id: CellId,
    row: i32, col: i32,       // 原始坐标
    rowspan: i32, colspan: i32, // 合并范围

    yp: Option<CellId>,       // 上主格
    value: Value,             // 值（运行期填充）

核心思想：Cell 不保存结果，而保存"如何产生结果"（坐标、主格关系、表达式、状态）。结果在运行时由 Expand/Expression 引擎惰性填充到 value / state，从而支持增量更新与缓存。

11.2 主格树构建算法

已有理论：主格线 P₀=@, P₁.xp=@, P₂.xp=P₁, P₃.xp=P₂ 形成树。工程实现把它转成一次性建树：

输入:  Cell 集合
输出:  MasterTree

BuildMasterTree():
  1. 创建根节点 @
  2. 遍历所有 cell:
       if cell.xp != null:
           parent = cell.xp
           parent.children.add(cell)
  3. 对 yp 同理（横主格方向）
  4. 计算每个节点深度 depth
  return tree
复杂度：O(N)（N = 单元格数，单遍遍历）。构建后即可供扩展调度（§11.3）与单元格定位（§11.8）直接复用，无需每次重算主格线。

11.3 扩展计划算法（优化算法 3.3）

原算法 3.3 每轮"扫描全部格找可扩展主格"，最坏 O(N²)。优化思路：用扩展队列替代全表扫描。

struct MasterNode { id; expanded:bool; depend_count:int }

初始化:
  for master:
    if parent.expanded:        // 主格已扩展 → 可扩展
        queue.push(master)

while queue not empty:
    P = queue.pop()
    expand(P)
    for child in P.children:
        if child.ready():      // 依赖均已扩展
            queue.push(child)
复杂度：O(M)（M = 主格数量，M ≤ N）。每个主格入队/出队各一次，避免重复扫描非主格单元格。实践仍"先横后纵"（§4.3）以利用列数远小于行数的特点。
图 16　扩展调度（算法 A2）：用入队/出队的扩展队列替代每轮 O(N) 扫描，整体 O(M)。

11.4 增量扩展算法（重要）

原算法每次"重新生成整张实例表"。实际系统中用户追加一条数据（如销售明细新增"商品D"）时，不应重算整表，只应更新受影响的 DOMB[P]。

IncrementExpand(P, newData):
  1. 定位主格 P 及其扩展带 B[P]
  2. 计算新增数量 k = |newData|
  3. 复制扩展带：在 B[P] 末尾追加 k 份（算法 3.1 局部版）
  4. 更新主格索引 / 同束号 ord
  5. 触发依赖重算（仅 DOMB[P] 及下游）
复杂度：从整表重算的 O(N) 降为 O(size(DOMB))（仅受影响的后辖区单元格）。配合主格树版本号 version（新增数据 version++），可实现"只动变化部分"。
图 17　增量扩展（算法 A3）：新增数据只在扩展带末尾追加，局部更新 DOMB[P]，避免整表重算。

11.5 依赖计算图算法（DAG + 循环检测）

理论已规定"单元格只能引用其他单元格的格值"（规则 5.1），因此天然形成有向无环图 DAG。据此可拓扑排序计算，并检测符号循环引用。

ExpressionGraph:  A1 → B1 → C1   （引用方向）

拓扑排序 Kahn:
  indeg=0 的节点入队
  while 队列非空:
      计算节点; 删除其出边; 更新下游入度
  若仍有未计算节点 ⇒ 存在环

CycleDetector:
  输出环路径，如  A1 → B1 → C1 → A1
复杂度：O(N+E)（N 节点 / E 依赖边）。拓扑排序同时完成"计算顺序"与"循环检测"——对应理论的可计算队列（§6.3，定理 5.11/5.12），但工程版能精确给出环路径用于报错定位。
图 18　依赖计算图（算法 A4/A6）：拓扑排序即得计算顺序，剩余节点即循环引用。

11.6 高性能计算调度算法（三级缓存）

普通"对每个 cell 计算"会大量重复。优化为三级缓存，逐级命中避免重复计算：

L1  CellCache         cell_id  → value          // 单元格结果
L2  ExprCache         hash(expr) → result         // 同表达式结果
L3  MasterInstanceCache  master_version → 实例片段  // 整段扩展结果

流程:
  用户请求 → 检查 L3 实例缓存 → 检查 L2 表达式缓存
          → 必要时计算 → 写回 L1/L2/L3
复杂度：命中缓存为 O(1)。配合 §11.4 的主格版本号，L3 可在"数据未变"时直接复用整段实例，大报表收益显著。

11.7 并行计算算法

非线性报表的 DAG 天然可并行：入度为 0 的节点彼此无依赖，可由线程池并发执行。

while DAG 非空:
    ready = find_all(indegree == 0)   // 一批可并行节点
    parallel_execute(ready)           // 提交线程池
    update_graph()                    // 完成后删边、更新下游

线程模型:
  Expansion Thread        // 扩展
       │
  Calculation Thread Pool // 并行计算
       │
  Render Thread           // 渲染

11.11 有限扩展算法（Expansion Band Algorithm）

传统报表的明细扩展本质是"插入整行 / 复制整行"。但非线性报表的扩展单位不是 Row / Column，而是矩形扩展带（Rectangle Band）——只允许商品区、数量区、金额区这类局部矩形被复制，整表其余部分（如外层"销售单"标题、客户主格）保持不动。

11.11.1 扩展带模型

把"可扩展区域"抽象为一个带边界与方向的矩形对象：

struct ExpandBand {
    id:          BandId,
    start_row:   i32,   // 矩形上界
    end_row:     i32,   // 矩形下界
    start_col:   i32,   // 矩形左界
    end_col:     i32,   // 矩形右界
    direction:   ExpandDirection,  // 扩展方向
    master:      CellId,          // 主格
    clone_rule:  CloneRule         // 复制规则
}

例：模板中 A5:C5 这一横条即一个 Band：start_row=5, end_row=5, start_col=1, end_col=3。它只覆盖"商品|数量|金额"三列，扩展时只复制这一条，不影响同表的客户主格与销售单标题。

图 23　扩展带模型：扩展单位从"整行"下沉为"矩形 Band"，由四边界 + 主格 + 方向唯一刻画。

11.11.2 有限扩展算法

输入： ExpansionBand, data[商品A, 商品B, 商品C]
输出： 实例区域（如 A5:C7）

FiniteExpand(Band, data):
  1. 取 Band 尺寸
       height = end_row - start_row + 1
       width  = end_col - start_col + 1
  2. for item in data:
       克隆 Band  →  offset += height      // 沿方向堆叠实例槽位
  3. 建立主格关系： newCell.xp = master
  4. 更新坐标索引
  return InstanceBand

复杂度： O(data_count × band_size)

11.11.3 非整行 / 列坐标映射算法

由于扩展单位是矩形而非整行，不能用 row++ 推进。必须建立逻辑坐标 → 物理坐标的映射：

physicalRow = band.startRow + index × band.height + localRow
physicalCol = band.startCol                          + localCol

其中 index 是第几条数据，localRow/localCol 是单元格在 Band 内的相对位置。这样任意实例单元格都能被唯一定位，且与"整行 / 整列"解耦。

11.12 交替扩展算法（Alternating Expansion）

本章内容取自润乾报表（Raqsoft）官方《高级指南·非线性报表模型》的两章权威定义：展现模型（zxmx36.html）与数据模型（sjmx43.html）。作者蒋步星即润乾报表创始人，因此这两章是本文档理论部分（§2 表格结构、§6 缺省行集、§11 对象模型）所依据的工程源头。它们构成"模型基础层"——在扩展算法与计算算法之前，先定义报表长什么样（展现）与报表数据从哪来、如何组织（数据）。

12.1 展现模型（Presentation Model）

采用"类 Excel"方案：报表是由 N 行 M 列的基本矩形格子构成的平面图形，这些格子称为单元格。核心定义：

  • 单元格：平面图形的基本单元（矩形格子）。
  • 合并单元格：选中一片矩形连续区域并合并后得到的大单元格（注意：合并区域只能是矩形，这与 §2.1 矩形引理一致）。
  • 行 / 列：水平排列的一组单元格为行（从上到下 1,2,3…）；垂直排列的一组为列（从左到右 A,B,C…）。
  • 单元格命名：用"列号 + 行号"命名，如 A 列第 1 行 = A1；合并单元格以左上角单元格编号作为整格编号（如合并格 B2）。
  • 报表：由单元格、合并单元格、行、列组成的二维矩形表格；加上"表格中的数据 + 数据间的运算逻辑"即构成报表。
图 28　展现模型：类 Excel 的单元格/合并格/行列/命名体系，是 §2 表格结构的形式化源头。

12.2 数据模型（Data Model）

数据是报表的基础。润乾用以下概念组织数据：

  • 数据集：由"数据数组"构成的二维数据表，同列元素类型相同，每列有唯一名字。
  • 记录 / 字段：为区别于报表的行/列，数据集的行称记录、列称字段。记录有行号 1,2,3…（存于第 0 列）。
  • 行集：由数据集的行按某种顺序构成的数组；数据集本身也是行集。组成上是数据集的子集，但次序未必相同。
  • 分组与组集：把记录按规则划分成 N 个行集的过程称为分组，每个行集称为一个组，多个组构成组集。
  • 数据集函数：对记录取数/分组/运算的函数，书写为 dsName.f(…)。
  • 单源 / 多源报表：数据源含 1 个数据集为单源（ds1），含多个为多源（ds1, ds2…）。

关键书写规则（取行号）：

dsName.#0              // 获得当前行的行号（#0 即第 0 列）
dsName.select(#0)      // 获得数据集所有记录的行号
dsName.f(...)          // 数据集函数

多数据集模型是润乾的差异化设计：多个数据集不做 union/join 整合运算，而是直接用于报表运算，并在运算过程中按关联键（如左表头"项目名称"）动态关联。它支持异构数据源与多源分片报表，避免了整合运算对 CPU / 内存的占用，性能显著优于"先合并再计算"的传统单数据集模型。

图 29　数据模型：数据集（记录/字段）经分组得到组集；多源数据集直接关联，无需整合运算。

13.1 集合、数组与表达式基础

  • 集合：确定事物的汇集；润乾中元素可以是数据、单元格、行、列、记录、字段、组等。
  • 数组：集合按规则排序所得的有序序列，成员个数为长度；是集合的特例。
  • 集合函数 / 操作符：结果为集合的运算；如 select()、group()、list()、query()、call()、to()。
  • 集合表达式 / 单值表达式：结果分别为集合 / 单值；前者使单元格成为可扩展单元格（默认按扩展方向复制若干份），后者为不可扩展单元格。

13.2 扩展模型与主格模型

扩展方向有横、纵两种，一个扩展格同时只能有一个方向。主格 / 附属格是相对概念：扩展格主动复制，其右（下）的格被动跟随，称前者为后者的主格，后者为附属格；左主格（纵向扩展时）与上主格（横向扩展时）可分别人为设置，但须满足：左主格必为纵向扩展格、上主格必为横向扩展格、禁止循环设置、横向格无左主格、纵向格无上主格。

  • 根格（报表首格）：左上角灰格，存报表级属性，层次坐标特殊基准，书写为 `0（反引号 0，非引号）。
  • 缺省主格认定：纵向扩展时左主格缺省为左边纵向扩展格（无则 `0）；横向扩展时上主格缺省为上方横向扩展格（无则 `0）。
  • 扩展变化规则：从主到次逐级扩展；横向扩展拉同列上主格、纵向扩展拉同行左主格；主/附属格重叠区域形成交叉扩展，横纵扩展相互独立、顺序无关（呼应 §3.8 扩展交换定理）。
  • 缺省引用规则：格间运算直接写单元格名即可，前提是被引格能由当前格唯一确定——通常是当前格的主格、或与其有相同一级主格、或是固定格。
图 30　主格/附属格树：根格 `0 为根，纵向扩展产生左主格、横向扩展产生上主格，多层扩展按级别递推（对应 §2.4、§11.2）。

13.3 层次坐标、位移坐标与根坐标

扩展前无法预知某格会复制出几个、在哪儿，因此引入层次坐标唯一描述扩展后的每个单元格：

cellx[ Lk:lk, Lk-1:lk-1, … L1:l1 ; Tk:tk, Tk-1:tk-1, … T1:t1 ]
// Lk/Tk 为左/上主格，lk/tk 为其扩展后的次序（从远到近）
// 只有上主格时，分号不可省；只有左主格时，分号可省
  • 位移坐标：描述目标格相对当前格的位置（相邻 n 行/列），如同期比、环比；符号用 ±lk / ±tk。
  • 根坐标表示法：完整坐标从根开始，写成 cellx[`0, Lk:lk,… ; `0, Tk:tk,…]，`0 即根。
  • & 运算符（逆运算）：&cellx 返回当前格所属的 cellx 主格在所有扩展格中的排序（第几个）。
  • 缺省表示法：目标格某主格与当前格相同时可省略；满足缺省引用规则时直接写单元格名。
图 31　层次坐标 / 位移坐标 / 根坐标 / `&` 运算符：扩展前精确定位扩展后实例格（对应 §6、§11.8）。

13.4 格集与 $ 运算符

对一组单元格运算时引入格集：

list(Cell1, Cell2, …)            // 枚举若干格
[Cellx : Celly]                  // 以两格为对角的矩形区域（link 操作符）
sum([A1:B3])                     // 对矩形区聚合
cellx[层次/位移坐标]{}            // 坐标界定范围内的单元格集合（有{}返集合，无{}返首格）
cellx[坐标]{条件表达式}          // 集合内再按条件过滤
C2[A2:-1]{ $B2 == B2 }           // $B2 指代当前格的 B2 主格，B2 指代目标格的 B2 主格

缺省格集：cellx[\]{} 或 Cellx{} 表示当前格主格管辖范围内的全部目标格集合。

13.5 定位与拉伸（报表区域）

整表分区（横向：左表头→常规列→右表头；纵向：分页页眉→头标题→报表头→分组表头→数据区→表尾区→尾标题→分页页脚），区域顺序不可颠倒，合并格不能跨区。关键规则：

  • 空白单元格优先占用：不存属性的占位格，保证整表为矩形且不占内存；扩展复制时紧邻的空白格被优先占用。
  • 分页时伸缩：标题区无法预知数据区横向扩展大小，对中间某格设"分页时伸缩"属性，横向扩展时引擎对其拉伸；无设定则拉伸最右格。
  • 位置不变：横向扩展时，除靠右对齐与被拉大的格外，其余格保持位置不变。

13.6 子报表模型

含多片有共同主题但各自独立子主题的单元格片段的报表称主子报表 / 复合报表；片段即子报表。润乾基于单元格模型提供两种方式：

  • 引入式子报表：以当前格为扩展格向右下扩展，占用主表空白行列、接受主表行高列宽，扩展后与主表形成统一二维矩形；源格不保留，主表不能访问子表值。
  • 嵌入式子报表：缩在当前格内或仅撑大当前格，不影响周边；格中嵌表、格线不对齐，不能导出 Excel；源格保留，主表可用 eval() 访问。

参数传递与关联：子表参数统一由主表入口传递（主表参数 / 表达式结果 / 常数）；主子表共用运算环境，参数或数据集重名即共用（内容相同建议同名以省数据库访问）。嵌入式访问语法：

eval( StringExp, SubRptExp )
// 例：取嵌入式子报表 A1 中 B2 的值加 10
eval("B2+10", A1)   或   eval("B2", A1) + 10

十四、填报表采集模型（润乾官方）

本章并入润乾《高级指南·填报表模型·采集模型》（cjmx56.html，蒋步星）。它把本稿 §4 报表填写 的理论（更新属性 upd、自由式/行列式/交叉式三形态、动态增删）落到工程级"如何把一张格子表自动识别为数据库可以增删改的序表"。核心由三类单元格、自动分片、序表，以及取数/回填 SPL 构成。

14.1 三类单元格与序表

填报模型把单元格分成三类，再由采集程序自动拼成"序表"（序表 ≈ 一个二维数据表，可作增删改的单元）：

  • 普通格：一般作为字段名（表头）；
  • 维度格：字段值，标注"属于哪个对象的哪个维度"；
  • 数值格：字段值，是真正要采集/回填的数据；自动计算的数值格可由其它数值格算出（既用于展现，也用于采集回填）。

采集程序自动分片：行列上连续的一片数值格（连同对应维度格）为一片；连续两行以上"只有数值格、无维度格/非空普通格、且不合并"的视为行式分片（支持自由增删行）；其余单值（维度/数值格）被拼成一个"一行记录"的序表。序表由"维度格字段名相同的数值格"聚合而成——单值同对象名→并入同一序表，不同对象名→不同序表（单行序表的维字段作为公共维默认拼入其它多行序表）。

14.2 数据采集规则

字段名采集

数值格/维度格未显式设字段名时，规则为：扩展后表格，取上（左）同宽（高）的普通格内容作字段名。例：B1/D1 以左侧 A1/C1 为字段名；A4–D5 以顶部 A3–D3 为字段名。

同序表 / 同记录采集

维度格字段名相同的数值格视为同一序表（对象）；同分片内维度值不同的为不同记录，格内容作为相应字段值。行式填报表中"数值格区同一行 = 同一条记录"。例：数值格 B3 的维度字段为 {地区, 年度}，与 C3 同对象 → 组成 (地区, 年度, 金额, 数量) 序表；而 C2–C5 维度为 {年份, 地区}、E2–E5 为 {年份, 地区, 状态} → 裂成两个序表。指定对象名可显式分片（同名则合并，异名则分离）。

14.3 取数表达式与回填

一个完整填报表由三部分组成：取数 SPL（把要回填的序表赋值给变量，可返回多个：序表变量、维序列、下拉序表）、填报表 SHT（设计模板，在普通格用 变量名.字段名 引入，如 score.SCORE）、回填 SPL（页面填好后通过同一变量名取走填写后的序表，处理写库）。空数据展现时取数 SPL 可省；如要取回填前数据，需在"数据处理"中保存旧数据（如 score_old）。

十五、填报表扩展模型（润乾官方）

本章并入润乾《高级指南·填报表模型·扩展模型》（kzmx59.html，蒋步星），是 §14 采集模型的同级子章。它规定填报场景下"维度格如何把维序列展开成多行/多列"，与展现模型的扩展（§12.1、§3）同源，但其数据源是维序列而非数据集行集，且扩展后由 §14 的采集程序再拼成序表——即"先扩展、后采集"。

15.1 扩展触发条件

当维度格的单元格表达式是维序列时，按序列成员纵向或横向扩展表格。即：扩展以维度格为单位，数据源是写在单元格里的维序列（如 ["中国","美国"] 或嵌套的 [[...],[...]]），而不是普通数据集的行集。

15.2 扩展方向判定规则

对每个需要扩展的维度格，方向按如下优先级判定：

  • 若其左（上）有扩展格 → 延用该扩展格的方向；
  • 否则，若其右（下）有数值格 → 纵（右）/横（下）向扩展；
  • 若右、下均有 或 均无数值格 → 默认纵向扩展。
图 36　维度格扩展方向判定决策树（左/上优先 → 右/下 → 默认纵向）

15.3 撑大与终止

扩展时，同行/列上相邻的非扩展格被"撑大"（随扩展方向一起增长，保持与扩展区对齐）。多层扩展：当维序列是嵌套结构时，按层依次展开（国家→省→市…），扩展持续进行直到遇见数值格为止——数值格作为叶子终止扩展。

图 37　多层扩展嵌套树：国家→省→市→数值格（D2 终止）

15.4 示例

  • 例1：B4 纵向扩展，A3 被撑大；
  • 例2：B4 纵向扩展 + C2 横向扩展，C1、A3 被撑大（纵横混合）；
  • 例3（多层）：A2 ["中国","美国"] → B2 [["河南","河北","山东"],["阿拉斯加","加州"]] → C2 三层嵌套到市 → D2 数值格终止。
