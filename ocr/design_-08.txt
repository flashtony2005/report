多源分片
结算、支付、合同费用类型、单位等数据都存放在不同表中，传统开发
中是在服务器端通过连接或者 Union 来构造复杂的 SQL 语句。这是一种单源不分
片的方法 ，在涉及表多的时候会带来两大问题;
1.， SQL 的复杂程度: 横向分片，需要 JOIN，如果纵向也有分片，则需要 JOIN+UNION 。
如果数据来自于五六个数据源，写这个 SQL 就需要水平和时间，也不利于维护
2.， 运行效率: 涉及多张表时，就算复杂的 SQL 正确的写出来了，但由于 JOIN 和编写
SQL 的写法，实际运行时的效率比较低
